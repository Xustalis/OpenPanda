## 一、现存问题（按严重度）

### [P0] 1. 安装器自启服务指向错误配置路径（真 Bug）

**证据**
- `scripts/install.sh:184-185`：LaunchAgent plist 写死
  `--config $PREFIX/config.yaml`（`~/.local/share/openpanda/config.yaml`）；
  `install.sh:210` 的 systemd unit 同样写死。
- `cmd/panda/init.go:139`：`panda init` 实际写入 `UserConfigPath()` =
  `~/Library/Application Support/openpanda/config.yaml`（macOS），
  `internal/config/config.go:469-475`。

**后果**
- `install.sh:168` 的 `HAVE_CONFIG` 检查 `$PREFIX/config.yaml` → 用户跑完
  `panda init` 仍永远警告"尚未生成配置"。
- 自启 daemon 用不存在的 `--config` 启动 → **开机自启实际是坏的**。

**修法（10 行内）**
- plist / systemd unit 去掉 `--config`/`--card` 参数，让 daemon 走
  `ResolvePath()`（`config.go:482`）自动发现用户级配置；
- `HAVE_CONFIG` 改为探测 `UserConfigPath()`（或干脆去掉该警告）。

### [P1] 2. 安装/更新链路的体验与一致性

| 问题 | 证据 | 说明 |
|---|---|---|
| install.sh 卸载提示教用户手动删目录 | `install.sh:254` | `panda uninstall` 已存在且质量高（白名单 + 备份 + confirm），安装器只字未提 |
| 两套 PATH 行为不一致 | `install.sh:155-158` 只警告；`panda install` 主动改 rc 文件 | 用户困惑：为什么一个帮你写一个不写 |
| 下载无断点续传、GitHub API 无 token | `install.sh:57`、`install.sh:106` | `latest` 解析撞上 API 限流（匿名 60 次/小时）就安装失败；大包中断只能重来 |
| 三套安装布局并存 | install.sh → `~/.local/share/openpanda`；`panda install` → `~/.local/bin`；Homebrew → Cellar | 升级/卸载语义不统一 |

### [P2] 3. 模型调用层

| 问题 | 证据 | 说明 |

| 完全没有响应缓存 | `internal/entry/` 全目录 grep `cache` 零命中 | 相同问题重复问 = 重复花钱、重复等待 |

  —— 改协议要改 7 处。codex.py 的参数解析 bug（v0.0.4-beta 修复）就是
  重复代码漂移的直接证据。

### 审查确认做得好的（不动）

  目录 + 队列空闲才 apply + 失败清残留。

## 二、v4 新增项（按性价比排序）

### 1. [v4] 模型缓存（三项，缺口已确认）

- **意图分类缓存**：`answer / tool_call / task` 三分类对同一句话是确定性的，
  按 `(prompt hash, devices snapshot hash)` 做磁盘缓存（SQLite 一张表），
  命中率会很高。
- **Supervise 结果缓存**：`done/continue` 判定同样可缓存。
- **会话内前缀缓存**：system prompt + 设备列表不变时走 provider 的
  prompt caching（Anthropic / OpenAI 都支持），只改
  `internal/entry/model.go` 的请求头，**性价比最高**。

### 2. [v4] 轻量但更强的提示词

- 把 `internal/entry/prompt.go` 的 systemPrompt 拆成两层：
  - 常驻核心：路由三分类（约 1/3 体积）；
  - 按需注入：记忆治理规则仅在用到 memory 工具时注入；task JSON 样例仅在
    最近 N 轮出过 task 时注入。
- `summarizeDevices`（`prompt.go:133-158`）目前每轮全量重发设备列表 →
  变化时才重建 + 短 hash 缓存。

### 3. [v4] adapter 共享 harness 库

- 抽 `adapters/_harness.py`：stdin 契约、watchdog、`_kill_tree`、`_emit`、
  progress 事件。7 个 adapter 各自只剩 ~30 行"怎么调 CLI"的差异。
- `inject.go` 的凭据探测改为按注册表（`internal/agents/registry.go`）声明的
  凭据清单驱动，新增 agent 不再改 if 链。

### 4. [P0+][v4] 安装器修复（详见上文 P0/P1）

- 修自启配置路径 Bug；
- `curl -C -` 断点续传 + `GITHUB_TOKEN` 透传；
- 末尾提示改为 `panda uninstall` + `panda doctor`；
- PATH 写入与 `panda install` 对齐（统一"主动写 rc"或统一"只提示"）。

### 5. [v4] 自动更新器补强（现有实现已健全）

- 更新失败后的**回滚**：目前 `.old` 只在 Windows 有
  （`internal/install/install.go:118-127`），Unix 无回退路径；
- 更新时展示 changelog 摘要（CHANGELOG 已有结构化内容可拉）；
- daemon 模式下的更新通知（现在只有 web 里能触发）。

### 6. [done→v4 补曝光] 一键删除器

`panda uninstall` 已实现（`internal/install/install.go`），v4 只需要：

- install.sh / README / docs/install.md 把它讲出来；
- 增加 `--purge`（连用户资产 memory/projects/skills 一起删，需二次确认）
  与 `--backup-only`。

### 7. [v4] `panda init` 简化

现状 8 连问（`cmd/panda/init.go:69-83`：节点名、资源类别、类型、VM identity、
API 类型、BaseURL、模型名、API key）。改为：

- 默认路径只问 1 个问题："要现在配置模型吗？（回车 = 跳过，稍后在 web 里配）"；
- 加 `--defaults`（全自动）与 `--non-interactive`（CI 用）；
- node kind / resource class 由 `detectCard()` 自动推断，仅在多节点场景才问。

### 8. [v4] 免配置直接进 web + web 内引导（半成品，值得做完）

现状：
- `panda web` 已零配置可用（回环 + 临时 token，`cmd/panda/web.go:56-67`）；
- settings 页能改模型 API key（`webui/panel/settings.go:43-88`，含连通性校验）。

**缺的闭环**：
- 加 Onboarding 向导视图（`webui/app/src/views/` 目前没有）：首启检测
  `model.BaseURL == ""` → 顶部横幅"配置模型后才能对话" → 一步式表单
  （API 类型 / BaseURL / 模型 / Key，带"测试连接"按钮，复用 settings.go
  已有校验）；
- 引导完成后**热加载 engine**：现在 engine 是启动时判定的
  （`web.go:80-91`），改配置要重启进程 —— 需要把 engine 构造挪进可重载的
  holder。
