# Agent・Subagent のモデルと並列設定

**設定 → Agents** で親・子モデル、Agent ごとの並列上限、ワーカー並列上限、子タスクの制限を設定できます。例のモデル ID は各 CLI で利用できる値に置き換えてください。

```yaml
injection:
  model: never
routing:
  max_concurrent: 6
  agent_concurrency:
    codex: 2
    claude_code: 2
  agent_models:
    codex: [my-root-model]
    claude_code: [my-claude-model]
  subagent_models:
    codex: [my-child-model]
    claude_code: [my-child-claude-model]
delegation:
  enabled: true
  max_concurrent: 3
  fanout: 3
  max_children: 12
  max_depth: 2
```

- `routing.max_concurrent` はこのワーカーの実行中の Agent 呼び出しとキュー受付の上限です。0 は能力カードの値を継承します。
- `agent_concurrency` は Agent 別の追加上限です。キーにはカード名かアダプターファイル名を使えます。同じアダプターの別名はファイル名の上限を共有します。
- `subagent_models` は OpenPanda が作る子タスク用です。キー省略は親の選択を継承、明示的な `[]` は CLI の既定値です。画面で空にすると継承へ戻ります。
- `delegation.max_concurrent` は全親タスクの子呼び出しの共有上限、0 は追加制限なしです。`fanout` は親ごとの同時生成・待機数、`max_children` は累積子数、`max_depth` は最大世代です。
- 上限を下げても進行中の処理は中断しません。待機中の親は Agent 呼び出し枠を使いません。
- 制限は単一ワーカー内の実行中のアダプター呼び出しです。クラスター全体や CLI 内部の子 Agent・待機セッションは対象外です。独立ワーカー間の厳密な共有セマフォではありません。
- プロジェクト付きの複数子タスクで有効な `fanout` が 1 を超える場合、`paths`・`isolate`・`workdir` を省略した兄弟タスクは自動的に隔離コピーとなり、worker・Agent・委譲の上限内で並列実行できます。変更は競合を検査してマージされます。単独の範囲未指定タスクは引き続きプロジェクト全体をロックします。明示的に重複しない `paths` を指定すればコピーを避けられます。共有ツリーで重複するパスは直列です。

これはネイティブ CLI モデル選択です。注入モデルと明示的な CLI 環境変数が優先されます。例の `injection.model: never` は CLI 自身の認証を使います。Panda の認証情報が必要なノードではコピーしないでください。接続先と認証の上書きには `injection.agents` を使います。単一モデル CLI は最初の候補、OpenCode は利用可能な候補を選びます。ZCode は `provider/model`、generic コマンドは `{model}` に対応します。

保存は現在のワーカーへ即時反映され、同じ設定の他ワーカーは約 1 秒ごと・実行前に同期します。進行中のモデルは変わりません。

```sh
panda config routing set agent_models codex my-root-model
panda config routing set subagent_models codex my-child-model
panda config routing set max_concurrent 6
panda config routing set agent_concurrency codex 2
panda config delegation set max_concurrent 3
panda config delegation set fanout 3
panda config routing get --json
```

API: `GET /api/settings/execution`, `PUT /api/settings/execution` (Bearer token).

## 実行期限とコンテキスト

- 候補切り替え、一時的な障害の再試行、認証情報の救済は、ラウンドごとに同じ期限を共有します。期限はタスク指定または全体のタイムアウトに終了猶予を加えた値です。キャンセル後は新しい候補を開始しません。panic は自身の試行を終了し、実行リソースを解放します。
- OpenCode の provider/session エラーは即時終了します。回答後の終端 idle でも、パイプを開いたままの CLI を終了します。初期 idle、ツールエラー、別セッションのイベントは完了扱いにしません。管理対象の Codex タスクは再開用セッションをディスクに保存し、独立診断は既定で一時セッションを使用します。`thread.started` と旧形式のセッションイベントに対応します。
- agent プロンプトのソフト予算は複雑度に応じて 12,000 / 32,000 / 64,000 バイト、不明時は 32,000 です。ユーザー要件、受け入れ基準、作業範囲、プロトコル制約は維持します。スキル本文と縮約索引は残り予算を共有します。個人メモリ索引は関連トピック最大六件、4,000 バイト以内とし、プロジェクトとの分離を維持します。全コマンドは `panda help` で参照できます。
- コンテキスト超過時の再試行は元の予算を半減し、最大 32,000 バイトとします。実行メモは省略箇所を明示し、UTF-8 を保ったまま 12,000 バイトまで圧縮できます。再開時もコールドスタートに備え全タスク要件を保持します。`exec_agent_start` の `prompt_bytes` と `context_budget_bytes` はトークン数ではなくバイト数です。
- 検収・要約は同じモデルの独立した短文設定を使用します。出力上限 2,048 トークン、通信再試行は最大一回、拡張思考の無効化を要求しますが対応は provider に依存します。検収期限は 45 秒で、失敗時は人による確認に回します。通常の対話や agent のモデル設定は変更しません。設定済み・使用中のモデル確認は、agent タスクを作成せず読み取り専用 `model_list` ツールで処理します。

反映には新しいバイナリとアダプターの配置が必要です。設定のホットリロードでは実行中のコードは置き換わりません。

## 調査タスクと実行証拠

- spec の `task_kind` は `code_question`、`investigation`、`edit`、`operations`。省略は既存タスクと互換で、権限を付与するものではありません。調査・コード質問は読み取り専用 `plan`、編集は会話の権限に従います。深い調査は coding harness に委譲し、委譲失敗をディレクトリ概観だけで完了扱いにしません。
- 調査は実装・呼び出し元・関連テストの根拠、対象範囲と未検証事項を示します。静的調査でビルドやテストは必須ではなく、制限付き検索では全体の不存在を証明できません。編集は関連検証、運用は要求された事後状態を確認します。読み取り専用では acceptance コマンドを自動実行しません。
- worker ローカルの `execution_environment` は attempt ごとの cwd、git commit/ブランチ/dirty（未追跡も含む）、ルート `AGENTS.md`/`CLAUDE.md` のサイズ制限付き指紋を記録します。完全なルール索引・依存検査ではなく、本文の記録やプロジェクトコマンド実行は行いません。git 検査失敗は unknown です。
- 信頼できるプロセス境界の `adapter_execution_profile` は要求モデル候補、注入・ツール方針、制限・承認、時間制限、再開要求、登録能力を記録します。永続セッションは起動時設定を保持します。CLI の実効設定を確認したものではなく、未確認のモデル・推論設定・バージョンは unknown。prompt、認証情報、provider URL、MCP 本文、コマンドテンプレートは記録しません。
- 新しい専用 UI やノード間環境同期は追加せず、worker ローカルのイベントです。完全な結論証拠台帳・完了検証の実装を意味しません。新バイナリの配備が必要です。

## ルーティング・権限・プランの境界

- 概念的な質問には高速回答を維持します。具体的なコードのシンボルやパスについてはツールなしの回答を避け、実際のソースを読みます。深いリポジトリ調査と、その文脈を持つ深掘りの追質問（Side を含む）は coding harness に委譲します。未委譲・待機中・承認待ち・失敗を、収束時の要約で完了扱いにはしません。これはネイティブ CLI の推論強度の切り替えや、結論ごとの証拠検証ではありません。
- グローバルなツールポリシーが上限で、タスクはさらに制限することしかできません。`extended` は OS 権限を追加しません。Codex は通常 `workspace-write`、制限時は `read-only` を使い、ツールポリシーにより `danger-full-access` へ変更しません。型付きの調査・コード質問も保存済みの承認によらず読み取り専用となり、読み取り専用サンドボックスのない native command は利用できません。
- `plan` 会話の入口ツールは明示的な読み取り専用宣言が必要で、ローカルのショートカットも同様です。`task_submit`/`task_budget` は制限付き委譲を維持します。不明な MCP ツールは宣言がないため既定で拒否します。信頼できる MCP 読み取り専用能力の設定は未実装です。スキルの読み取りは既存内容のみを参照し、組み込みスキルを暗黙にインストールしません。
- 多段階プランは各段階の `task_kind`、会話の権限、agent roster を保持し、ソース作業領域のサイズ制限付きスナップショットを入力にします。artifact 保存先の欠如、梱包失敗、ファイル省略はタスク作成前に失敗させます。遠隔段階は受信ノード自身のディレクトリを使用し、送信元の絶対 cwd は渡しません。成果物は artifacts で受け渡し、**元の checkout へ自動で書き戻したりマージしたりしません**。
- 作業領域のディレクトリ図や読み取りツールを持つ分類は、パスだけの永続キャッシュを使わず、未コミット変更後の古い判断を避けます。検証記録には、完了しエラーとされていないコマンドツール結果と、プログラム・引数の完全一致が必要です。`echo`、部分一致、未完了、失敗は認めず、複雑な shell 結合の実行経路は推測しません。この記録は独立した受入検証の合格ではありません。
- Side は独立した記録を持つ会話で、委譲を含む同じツールと権限・承認ゲートを使います。主スレッド履歴は参照のみで、Side はそこに追記も圧縮も行いません。高速/深度ルーティングとモデル推論設定は別の層で、ネイティブツールと同じ推論動作を保証しません。
- 遠隔プランにもプロジェクト記憶を渡しますが、別の project checkout は追加せず、ソーススナップショットと前段入力の順序を保持します。

## ステージの受け入れ・ブロック・スケジューリング

- 生成計画と YAML のステージでは `acceptance`、`success_definition`、`tools_policy`、`max_turns` を指定できます。パス、ポリシー、ターン上限 0..200 を検証し、ツールポリシーは権限付与や制限の解除を行いません。
- 監督の `blocked` 判定は外部環境または入力の変更を要し、タスクをレビューに保留します。未完了と判明した作業は承認だけで完了にならず、続行または拒否が必要です。
- 同じマシン上の独立した分岐は、依存関係、容量、リソースロックの範囲で並行実行できます。同一計画・優先度内では残りの重み付きクリティカルパス順にし、手動キュー順を優先します。

## 会話の復元と実行状況

プロバイダーが返す推論要約は回答と分けて保存され、表示専用です。推論を捏造したりモデルに再送したりしません。実行中の回答、要約、進行状況を定期保存し、再読み込み後も同じ操作 ID で停止できます。停止済みの回答と要約も保持します。

圧縮は元の会話を保持し、要約済みの接頭辞を除いてモデルへ再送します。旧版が削除した履歴や保存しなかった要約は復元できません。CLI のネイティブ認証とエンドポイントは維持され、Codex 注入は Responses を使用します。残高不足は許可された救済後に停止し、認証または残高の修正を必要とします。

完了後、元の会話には独立した報告を保存します（最大 24,000 文字。短縮時は元の出力へのリンクを明示）。モデル再生には短い要約だけを使用します。実際の手順、変更パス、独立した検証と未完了事項を既定表示し、全文と履歴は展開できます。検査記録のない `done` を検証済みとは扱いません。旧報告は同じ試行の出力のみを補完し、再試行による書き換えを防ぎます。TUI の前景結果とバックグラウンド完了は、結果・手順・検証・確認事項を表示します。

- 子タスク待機中の親は実行枠と作業ツリーのロックを解放し、ハートビート・キャンセル・デバイスの排他を維持します。再開前に枠とロックを取り直します。待機情報は attempt に結び付けられ、再試行・キャンセル・再起動時に解除されます。
- 隔離マージの失敗・基準の欠落・競合は入力変更を要するレビューで停止し、作業領域を保持します。承認だけでは完了しません。同じバッチの兄弟は不変のソーススナップショットを共有し、明示的な作業ディレクトリを尊重します。
- 計画グラフ全体を一つのトランザクションで公開します。カーネル生成の因果メタデータで変更と削除を保持し、子孫を祖先より優先します。同時の異なる変更は競合し、同じ結果は統合できます。新計画は対応プロトコルを宣言したノードにだけ送信し、基準のない複数の旧スナップショットは停止します。計画の出力は元の checkout に自動反映されません。
