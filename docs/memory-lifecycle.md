# 长期记忆与记忆图谱

[English](memory-lifecycle.en.md)

记忆图谱只展示已保存、符合长期保留标准的事实，以及保存这些事实的文件。姓名等事实只出现一次也可以入图。每日历史、任务输出、技能描述和梦境报告中的普通文字不会生成知识节点。

## 准入与分类

一条长期记忆应是已确认的事实、稳定偏好或可重复使用的约定，预计在后续会话中仍有价值。每条只描述一个属性，并保留适用的用户、设备或项目范围。推测、例子、临时要求和一次性结果不满足这些条件。

| 分类 | 内容 | 写入目标 | 稳定键示例 |
| --- | --- | --- | --- |
| identity | 姓名、职业等身份事实 | user / USER.md | user.name |
| preference | 语言、主题、回答详略等稳定偏好 | user / USER.md | preference.language |
| personal | 常住地、时区、长期需求等关键个人信息 | user / USER.md | user.timezone |
| environment | 可复用的系统、设备和环境事实 | memory / MEMORY.md | environment.os |
| convention | 跨会话适用的通用约定与纠正 | memory / MEMORY.md | logging.format |
| project | 项目架构、构建测试命令、项目约定 | project / 项目 MEMORY.md | test.command |

不写入长期记忆的内容包括今天或本次任务的要求、天气与日程、待办、成功或失败的任务摘要、原始输出、问句、未经确认的猜测和无关内容。凭证会由现有脱敏规则检查。即使请求中含有“记住”，临时内容也不会因此获得长期资格。

分类由入口模型结合上下文完成，Go 写入层再次校验分类、键、作用域和明确的临时内容标记。常见中英文姓名、偏好和环境事实可以自动识别；不明确的内容需提供 category 和 key。启发式校验不等同于完整的自然语言理解，模型仍应只提取已确认的原子事实。

## 更新与旧数据

memory_add 按稳定键更新或新增，键描述属性，不包含当前值。例如 preference.language 从“用户偏好中文回答”改为“user prefers English answers”，会更新同一属性。姓名、语言、主题等常见属性使用规范键，避免中英文表述产生重复条目。设备、服务和多个独立偏好应提供各自的键，例如 environment.server_a.os、preference.editor。

无法自动识别属性的旧条目可先通过 memory_read 查看，再用 memory_replace 的唯一文本匹配进行纠正，并补充 category/key。模糊匹配或空匹配会失败。个人事实更新会在同一个存储锁内清理 USER.md、MEMORY.md 和主题文件中的同键副本，并写入对应层；超过容量或验证失败时保留原数据。项目事实仅在所属项目内更新。多个可并存的事实应使用不同键，例如两种过敏原，不应共用单值属性键。

旧条目重新分类或更换属性键时，也会清理被替换属性的旧副本。跨文件更新在普通写入失败时恢复原文件字节，但不提供断电或进程崩溃时的跨文件事务。

文件仍使用 § 分隔条目。新事实带有可读元数据，例如：

    [fact:identity:user.name] 姓名：张三
    §
    [fact:preference:preference.language] 用户偏好中文回答

Web 和 CLI 的文件编辑功能仍可维护旧文本；图谱只投影能通过准入校验的条目，不会为清理图谱而删除用户原始文件。不明确的旧条目需要补充分类和键后才显示。事实节点的 ID 来自所属文件和属性键，内容变化时更新原节点。图谱不通过词频或共现猜测人与内容之间的关系。

## 每日记忆、梦境与项目记忆

每日历史记录任务与会话过程。同一天相同内容会去重，空内容不生成文件，外部来源标记保留。任务标题和模型生成的任务摘要均为外部来源；摘要经过模型改写也不能成为可信长期事实证据。

梦境仍在空闲时至多每日运行一次。它先检查候选是否有长期价值，再检查重复天数、评分和来源。未来日期的日志不参与。存在较新冲突值时，旧值即使重复更多次也不会晋升；同日冲突交给明确的记忆纠正。已保存的事实优先，旧日志不能覆盖后续用户修改。身份和偏好写入 USER.md，环境与通用约定写入 MEMORY.md。只有合格的可信观察才可能晋升，外部任务历史的重复不会打开晋升通道。没有合格候选时，本轮可以不新增记忆。

DREAMS.md 保留整理回执及原有失败重试机制。图谱中的晋升连线需要回执与当前保留的合格事实同时存在；已更新或删除的旧事实不会继续显示其旧连线。

项目长期知识保存在 projects/<name>/MEMORY.md，项目任务和摘要保存在 projects/<name>/daily/，不会进入个人梦境扫描。项目工具不能读取或更新其他项目及个人记忆。个人与项目每日历史均适用超过 30 天归档、超过 90 天删除的原有保留窗口，由后台调度器执行。

项目重命名会同时搬运长期记忆、每日历史和项目技能。项目历史写入与重命名、删除共用外层存储锁，避免文件搬运期间丢失正在写入的历史。

重命名遇到目标目录冲突或移动失败时，保留项目名称与当前项目指向；元数据更新失败时恢复原记忆目录。该协调覆盖记忆目录与项目元数据，任务和会话关联仍由各自存储更新，不是跨所有存储的崩溃事务。删除项目事实时，会同时清除该项目内同一属性的旧副本，防止旧值重新出现。

控制台沿用现有主题与样式规范，区分各类记忆的用途，展示事实分类与出处。图谱支持刷新、搜索和键盘选择；项目切换忽略旧请求的迟到响应。窄屏详情位于图谱下方，触屏操作保留可见按钮。
