# 会话规划与持续目标

Web、交互式 CLI 和 TUI 使用同一套会话服务。Web 输入框常驻“计划”按钮，新提案在右侧边栏展开为 Markdown。输入框上方的提案卡有两个入口：点卡片本身是阅读，点“审阅计划”打开同一个边栏，并弹出可提交调整或开始实施的对话框。退出规划不会丢弃提案，文本保留到确认实施为止；重新进入规划视为新一轮规划，旧提案作废，只留在提案归档里。点击聊天工具栏的「目标」，在右侧栏写下目标并启动。查看进度、编辑、暂停和继续都在同一处。

`/plan` 切换持续规划模式；`/plan 描述` 进入规划并提交描述。后续消息继续规划，切换会话和重启后仍然保留。规划覆盖当前权限选择，工具只能读取，不能写文件、修改配置或派发实施任务。退出规划恢复原有权限。

完整方案会保存为带版本的提案。Web 边栏底部的决策区给出两条路：写下要改什么（这段话作为下一轮规划输入，产出新版本），或直接点“开始实施”；终端输入 `/plan confirm 版本`。服务端只接受当前展示的准确版本，拒绝过期或重复确认。实施发生在当前会话，不会自动创建目标。实施轮没有自己的响应流，所以它把当前阶段（派发、分阶段计划、选设备、执行、工具、校验、重试、断网、整理结果）写在会话操作上，控制台每秒轮询的会话状态把它带出来，输入框上方显示为一行进度，并附一个直达该轮的“停止”——而不是让人对着一个转圈猜它是卡住了还是在跑。已有因规划而暂停的目标时，按钮明确显示“实施并继续目标”，实施成功并且关联任务收尾后继续该目标。

`/goal 目标描述` 创建并启动服务端持续目标。`/goal` 查看当前目标或进入编辑。Web 目标侧栏的控制和终端命令调用相同服务：

| 命令 | 行为 |
| --- | --- |
| `/goal edit 完整目标` | 修改完整目标，撤销旧执行代次并中断旧工作 |
| `/goal pause` | 暂停下一轮，让当前工作收尾 |
| `/goal stop` | 暂停后续轮次，同时中断当前轮次和子任务 |
| `/goal resume` | 用户明确恢复；清零连续阻塞计数 |
| `/goal clear` | 撤销运行资格、移除当前目标并保留历史 |
| `/goal --tokens 100000 完整目标` | 显式设置 token 预算并创建目标 |
| `/goal --tokens 200000 resume` | 显式提高预算后恢复目标 |
| `/goal -- edit the backlog` | 按原文 `edit the backlog` 创建目标 |

单独输入 `pause`、`stop`、`resume` 或 `clear` 才会触发控制操作。`/goal stop the bleeding in CI` 这样的完整描述会创建目标。Web 控制台清除已保存的目标时需要确认。

默认没有额外的目标 token 预算。预算在一轮结束后按入口请求和关联任务的实际用量结算，达到预算后不再启动新轮次；正在执行的请求可能越过预算。代理不能自行提高预算、修改目标或恢复暂停的目标。

目标活动且当前轮次及其任务树已收尾时，后台启动下一轮。待答问题、待审批、用户输入和其他运行中的会话工作会阻止自动推进。可以关闭网页，服务仍然运行。暂停与进入规划都只禁止下一轮；仅退出规划不会恢复目标，需明确选择实施或继续。规划中明确继续目标会同时退出规划，不会实施尚未确认的提案。

一次回答或一个任务成功不会完成整个目标。模型需要通过 `update_goal` 提交完整目标的完成核验，控制器还会检查关联工作与恢复流程已经收尾。编辑已完成目标会使旧核验失效，并转为暂停，等待用户明确继续。相同具体阻塞连续三轮才进入阻塞状态；显式恢复后重新计数。额度、预算、不可重试错误和连续空响应分别阻止无意义续跑。

状态及用量存储在 SQLite 中。每轮使用数据库租约和执行代次，多进程只能领取一次；重启先核对原有任务，仍运行的任务继续等待。中断的实施先对账，再依据历史和检查点继续。删除会话、替换或清除目标会先撤销资格，过期回调不能重新派发。

旧浏览器目标只显示为待恢复信息，用户选择恢复后才创建后台目标。分叉会话从普通模式开始，不复制自动运行资格。独立的 `panda plan run` 流水线命令不受会话规划模式影响。
