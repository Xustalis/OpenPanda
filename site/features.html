编排与监督

它不替你写 Agent，而是把你已经装好的 Agent 组织成一支能验收的队伍。以下每条能力都有对应的命令或配置入口。

意图分类与拆解

入口把一句话分成「直接回答 / 工具调用 / 单个任务 / 多阶段计划」四类；多阶段工作先拆成带产物接线的计划，而不是一口气丢给一个模型。

监督回路

入口模型持续判定完成度，执行器死掉时带着失败原因重新派发，直到完成或轮次预算耗尽；默认五轮。

多模型注册表与透明故障转移

panda model add / switch / test 管理多个提供方；额度耗尽或凭据失效（401/403）会自动注入备用模型，任务不中断。

并行多 harness

panda task add --agents a,b --mode parallel 把一条指令扇出成计划，收集多个 verdict 后给出裁定，而不是让你自己读四份答案。

分层审批

可逆操作自主执行；git push、删除、生产库变更这类不可逆命令暂停，等人在 panda approve 或控制台里明确同意。

执行透明与熔断

每条 Bash 命令、文件改动与工具调用连同负责的 Agent 和底层模型实时流到终端与控制台；循环检测与重试熔断阻止失控 Agent 烧光 token。

v0.1.4 起，完成判定看实际执行过的命令、失败的工具结果，以及声明的验证入口是否真的跑过；一句「测试通过」没有证据不算完成。

记忆与技能

偏好、项目事实与可复用流程分开存，跟随任务一起跨设备移动。

双层记忆

用户偏好写在 USER.md，项目事实写在 MEMORY.md，严格分开，避免把个人习惯当成仓库事实。

自演进技能

跑通的工作流被蒸馏成 SKILL.md 剧本，随时间累积，下次遇到同类任务可直接复用。

技能 Hub 与自主发现

panda skill hub 提供离线目录，panda skill import 从路径、URL 或归档导入；任务中途也能找到并安装所需技能。

随行上下文

委派给另一台机器的任务自带项目记忆与工作区摘要，执行端不必重新读一遍仓库才能开工。

多设备协作

节点之间是对等关系，没有主根、没有托管控制面。路由器按实测能力挑机器，链路断了由 DTN 托管。

LAN 发现与蓝牙式配对

同一局域网内 beacon 自动发现待准入设备，panda nodes admit 按指纹确认；panda pair 用两端核对的短码完成配对并密封下发共享密钥。

能力卡

每个节点自动声明 CPU、内存、操作系统、可用 Agent 与硬件执行器；panda card 可查看、重扫与编辑，改动热重载。

P2P mesh 与会话加密

认证 WebSocket 上协商逐连接 AES-256-GCM，密钥由共享密钥与两端 hello nonce 经 HKDF 派生；另有加密 UDP 数据平面承载大块数据。

三档信任区

panda nodes trust <id> mesh|guarded|open 给每个对端钉档，钳制发过去的委派暴露面与从它进来的准入；屏幕内容只在 mesh 档链路上移动。

能力路由与多跳

调度器按资源效率、优先级、节点等级、等待时间与链路延迟打分；Dijkstra 在链路状态图上取最便宜的第一跳，两跳外节点经 gossip 目录寻址。

工作树随行与产物回传

文件类任务把 checkout 打包带去执行端、跑完把结果带回；panda task artifact <id> 列出并取回报告、截图等产物。

断网时 DTN bundle 会暂存并加密签名，链路恢复后再投递；篡改过的 bundle 不会被送达。

会话与嵌入

对话是一等公民：可以分叉、压缩、被别的工具驱动。

会话树

panda session fork <id> --at N 在任意轮次分叉；在仓库里子会话的 worktree 从父会话分出，继承父会话写出的代码。

自动压缩

历史溢出时折叠成模型写的 running digest，而不是直接丢掉最旧的对话；存储里的线程保持完整。

MCP 与 RPC 嵌入面

panda mcp 把节点自身的任务、记忆与技能暴露成 MCP stdio 服务；panda rpc 提供 NDJSON-over-stdio 的状态与流式 ask 接口。

订阅 OAuth

panda auth login anthropic 用 PKCE 登录已有订阅并自动刷新 token，不必再单独配一把 API key。

界面与运行时

同一个内核，四种入口；二进制是纯 Go 静态构建，不依赖外部运行时。

终端 TUI

Bubble Tea 全屏交互，带首次引导、实时进度与轮中转向；PANDA_CLASSIC_REPL=1 保留经典行式 REPL。

Web 控制台

零配置看板、SSE 实时事件流、技能与会话管理、自动登录；panda web --lan 用一次性令牌在局域网共享。

语音入口

panda voice 跑唤醒 → 转写 → 派发 → 朗读的完整链路，与 REPL 共用同一条持久会话；需要单独的 Python 语音依赖。

脚本化 CLI 与自更新

panda ask 直接塞进自动化脚本；panda update check / apply 先探测暂存二进制，验签通过后才原地替换。

轻量常驻

空闲时守护进程常驻内存约 40MB，几乎不占 CPU；数据库是纯 Go SQLite，不需要 CGO。

内核分层

包结构来自仓库源码布局，按职责从入口到存储自上而下排列。

LAYER 职责
cmd/panda 终端 TUI、Web 控制台、CLI 与语音入口
askengine / entry / plan 意图分类、提示构建与多阶段拆解
commander / defense 三层执行（native / agent / manual）、分级闸门、熔断与防循环
memory / skills 双层记忆与自演进 SKILL.md
sessions / auth / updater 会话树、订阅 OAuth 与自更新
scheduler / trust 能力打分、延迟加权路由与逐对端信任档
bus / ledger WS 与密封 UDP 传输、会话 AEAD、Ed25519 身份与能力卡
artifact / security 分块可续传产物、沙箱、网络白名单与机密脱敏
storage 纯 Go SQLite（WAL 模式）

完整目录与边界说明见 docs/status.md 的能力对账表；本页只列稳定分层，不把实验性模块写成已发布能力。

它替代什么

把常见做法摆在同一张表里，差别就落在「谁持有你的代码」和「节点死了会怎样」。

单个 Agent CLI ssh + tmux + cron 托管编排服务 OpenPanda
驱动你已经付费的 CLI 一次一个 靠手写脚本 通常换成它自己的栈 十个适配器加一个通用桥
用上你所有的机器 不能 自己写脚本 租用它的云主机 局域网内发现自己的设备
节点中途挂掉 任务没了 任务没了 通常能续 带失败原因重新派发
代码与提示词在哪 你的机器 你的机器 服务商的服务器 你的机器，走加密 mesh
成本 订阅费 订阅费 按席位或 token 加价 用你已有的订阅

这张表是设计取向，不是性能基准；具体已验证与未做的边界写在项目现状页。
