版本兼容承诺

0.1.x 的补丁版可以加能力、修缺陷，但不破坏配置、存储数据与线协议；破坏其中任一项的改动属于次版本（0.2.0）。无法避免的破坏仍会给出弃用窗口与 Breaking changes 条目，不会无声抵达。

版本与发布通道

一条发布级版本线，规则写死在 CHANGELOG 里，不靠口头约定。

语义与兼容

0.1.x 补丁版可加能力、修缺陷，但不破坏配置、存储数据与线协议；破坏任一项属于次版本。无法避免的破坏会给弃用窗口与 Breaking changes 条目。

稳定通道

latest 只指最新稳定版；预发布版必须显式钉版本。安装器与自更新器都带降级保护，拒绝装回比数据目录 schema 更旧的构建。

签名发布

每个 release 附 checksums.txt 与 detached Ed25519 签名 checksums.txt.sig；官方公钥内置于二进制，同信道伪造的校验和会被拒绝。

五语记录

CHANGELOG 以中文为准，另有 English / 日本語 / Español / Deutsch 四份；本页的 0.1.x 版本集合与 CHANGELOG.md 由校验脚本逐版对账。

升级指引

绝大多数升级只要重跑一条命令；下面四条是需要额外看一眼的例外。

  • 0.1.x 内部的补丁升级保留配置、会话与数据；自动迁移会在首次启动时补上所需的索引或表，不需要手工改库。
  • 0.1.1 有一个明确的不兼容边：UDP 数据报平面与 0.1.0 节点不通。跨版本的 mesh 要整组一起升，不要留一台旧节点。
  • 0.1.2 与 0.1.3 各带一次自动迁移（合同表与一个附加索引），线协议没有新增帧；升级前备份数据目录仍是好习惯。
  • 自编译的旧构建没有内置发布公钥时会 fail-closed 拒绝更新；设 OPENPANDA_UPDATE_PUBKEY 指向官方公钥即可升入签名通道。
  • 升级前后各跑一次 panda version --json，比对二进制版本与 db_schema；两者不匹配时不要继续跑写库命令。

如何验证一次发布

不信任「我这边是好的」，信任可以复算的哈希与签名。

01checksums.txt

逐个归档核对 SHA-256；安装器在解包前就会做这一步。

02checksums.txt.sig

用二进制内置的官方公钥验 detached Ed25519 签名；自更新器一律强制验签。

03panda version --json

装上之后再确认版本与 schema，对「已安装的那份」复跑一次验证。

macOS 自带 LibreSSL 3.3 不支持 Ed25519，安装器会明确告警而不是悄悄跳过；OPENPANDA_REQUIRE_SIG=1 可把「无法验签」变成硬失败。
