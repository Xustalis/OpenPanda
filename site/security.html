先读这一段

  • 缺省下每个节点视为 mesh 档，节点之间同等完全信任。任一节点失陷即全网失陷，不要把 mesh 扩展到不完全受控的机器。
  • 「不可逆操作必须我审批」这条约束只在单机与可信内网成立。一旦网络里出现你不完全信任的节点，它不再成立。
  • 本页是 SECURITY.md 的站点摘要，不是替代。接入生产网络前请读完整原文，它按五语发布。

信任模型

五条边界决定了哪些流量可以被谁伪造，以及哪些操作必须有签名。

成员凭据与身份签名

总线成员凭据是 shared_secret（只经 OPENPANDA_SHARED_SECRET 注入）；hello 用带时间戳与 nonce 的 HMAC-SHA256 限制重放。tier-2 同意另带 Ed25519 签名，验签不过一律拒绝。

逐连接 AEAD

两端在 hello 里宣告 sessaead 且存在共享密钥时，握手后武装 AES-256-GCM，密钥由 HKDF 绑定两端身份与 nonce，逐拨号更新。协商不出加密的链路才过明文门禁。

审计链签名

task_events 与 audit_log 的哈希链逐行带 Ed25519 签名，验证时绑定本节点公钥；已签名链里再出现未签名行会被判为尾部剥离。

自更新验签

每个发布为 checksums.txt 附带 detached Ed25519 签名，官方公钥内置于二进制；与压缩包同信道送达的伪造校验和会被直接拒绝。

技能 URL 出站边界

panda skill install <url> 只允许 https（环回除外），拨号时拒绝环回、私网与链路本地地址，防止节点被当成内网探测跳板。

UDP 数据报平面全程 AES-256-GCM 封装，DTN bundle v2+ 的载荷同样加密并签名。明文链路只允许出现在已由底层加密的路径上。

完整性校验

两条命令都能在本地离线跑，用来确认审计链没有被改写。

panda audit verify校验全局审计链
$panda audit verify
panda audit verify --task <id>校验单个任务的事件链
$panda audit verify --task <id>

控制台的 GET /api/audit 走同一份校验逻辑。签名缺失、签名剥离或换钥重签都会报错。

部署红线

在补齐 per-node 密钥分发与可验签准入之前，以下五条不是建议，是前置条件。

  • 只走加密 overlay 互联。节点间经 Tailscale / WireGuard 相连，listen_addr 绑 overlay 网卡；绝不把总线端口直接暴露到公网或不可信局域网。跨公网时由反向代理终结 TLS，对端写成 wss://。
  • 密钥只经环境变量注入。shared_secret 只用 OPENPANDA_SHARED_SECRET 提供，不写进 config.yaml，不进任何公共仓库；生成用 openssl rand -hex 32。
  • 不给未知远端声明 tier-2 能力。capabilities.yaml 里的不可逆能力只授予你完全信任的节点。
  • 面板保持回环。panel_addr 只绑 127.0.0.1；非回环绑定且未配 panel_token 时会生成一次性令牌并大声告警。不要把带 token 的自动登录 URL 粘进聊天或工单。
  • 默认回环监听。总线默认只听回环；未配置 shared_secret 时监听器根本不启动，节点仅本地运行。

生命周期 hooks

hooks 是可选的本地扩展，默认关闭；打开后仍要守住执行面。

  • 子进程只继承白名单环境，不含模型凭据与对端 token；命令先过 tier 判定，被判为 tier-2 的默认拒绝，只有 hooks.allow_tier2 显式放行。
  • 任务值只通过 PANDA_HOOK_* 环境变量传入，模板里的 {title} 等占位符展开为变量引用而不是字面值；Windows 以 cmd /V:ON 延迟展开，值不进命令解析器。
  • 每次执行写一条审计行。可绑定 task_submitted / task_started / task_done / task_failed / task_review 五个事件，panda hooks list|test 查看与试跑。

漏洞上报

传输认证、权限 Tier 模型或密钥脱敏层的缺陷，请不要开公开 issue。

已知边界

这些不是待修的小 bug，是当前信任模型的结构性边界；改动它们等于换模型。

  • 共享密钥成员仍可为「接收端从未见过其公钥的节点」伪造同意（多跳中继加 TOFU 的固有边界）；该路径会打印警告，未钉住的身份按首次见到即信任处理。
  • 审计链的签名锚点在数据库本身，从未签过名的历史前缀无法与「被整体重写」区分；进一步收紧需要外部存证，仍在路线图上。
  • per-node 密钥分发与可验签准入尚未补齐；信任档是本机的单方面断言，能收窄你对某个对端的暴露，但不改变「持有共享密钥即为成员」这一底层事实。
