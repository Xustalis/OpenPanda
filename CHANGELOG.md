## Install

**macOS / Linux**

```sh
curl -fsSL https://raw.githubusercontent.com/Xustalis/OpenPanda/main/scripts/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/Xustalis/OpenPanda/main/scripts/install.ps1 | iex
```

**macOS (Homebrew)**

```sh
brew install Xustalis/openpanda/openpanda
```

After installing, run `panda init` to set the node up, or just type `panda` to drop into the REPL. An older install upgrades in place with the same command — user data is preserved.

## About

OpenPanda (**Open** **P**ersonal **A**daptive **N**ode-based **D**istributed **A**ssistant) is a personal task-orchestration kernel: one `panda` binary runs on each of your devices, nodes find each other over an authenticated WebSocket bus, an entry model turns each request into a direct answer or an executable task spec, and the scheduler routes every task to the device and agent best suited to run it. The CLI is the kernel's primary interface — bare `panda` drops into an interactive REPL — and the web console is a thin shell over the same store and engine.

## Versioning

- Versions follow `MAJOR.MINOR.PATCH`. `0.0.x` was the preview line: a patch release could add features, fix bugs and — exceptionally — break the wire, and each cut said so. From `0.1.0` on a release is release-grade, which is a promise about stability rather than about features: a `0.1.x` patch fixes defects and does not break configuration, stored data or the wire; new capability lands in a minor (`0.2.0`); and a break that cannot be avoided still gets a deprecation window and a **Breaking changes** entry rather than arriving unannounced.

- A release is cut by tagging `vX.Y.Z`; every commit since the previous tag belongs to the new version's section. `[Unreleased]` collects work since the last tag.

- Each version documents four categories: **Added** (new features), **Fixed** (bug fixes), **Changed** (improvements and refinements), **Breaking changes** (requires action when upgrading).

- Entries name the change and its user-visible effect in one to three lines; the introducing commit is cited where it aids archaeology.

- Entries may carry an **[Experimental]** tag: the feature works, but its interface, wire format or defaults are still evolving and may change in a later release without a breaking-change window — do not build a hard dependency on it.

- This is a curated changelog; some internal refactors and adapters are not listed here.

- This English file is canonical. The zh-CN / ja / es / de translations mirror it and may lag briefly around a release.

## [Unreleased]

### Added

- **OpenCode Zen and OpenCode Go are separate built-in model providers** — `panda model add opencode` registers the pay-as-you-go/free Zen catalogue on `https://opencode.ai/zen/v1`; `panda model add opencode-go` registers the Go/Go Plus subscription roster on `https://opencode.ai/zen/go/v1`. Both rows carry the live per-model context/output limits and prices, mark the free tier explicitly so it is never billed at the paid rate, and send the `x-opencode-session` header the Go gateway requires. The old single row and its `/inference` endpoints are retired; a saved config is rebased onto the current endpoint.
- `OPENPANDA_UPDATE_BASE` points the self-updater's download at a mirror of the release assets — the escape hatch for a network that reaches `api.github.com` but not `release-assets.githubusercontent.com`. `OPENPANDA_RELEASE_BASE`, the name the installers already honour, is accepted as an alias so one variable steers both.
- **The consent card shows the terms, not a summary of them** — the wizard and the Settings dialog used to render ten condensed clauses: a second copy of the legal text that could drift from the file it summarized. Both now render `TERMS.md` itself — all seventeen sections, in the console's language — through the same markdown renderer the transcript uses. The prose is never copied into the console: each translation is folded in from the repository's own file at build time, so there is one text to change.
- **The team you pick is the dispatch budget** — the per-round subagent limit was a hard `3`, so a conversation whose team was claude_code, codex, deepseek_harness and opencode dispatched three tasks and dropped the fourth before it was ever submitted: no card, no error, nothing on the receipt. The limit now derives from the roster (one task per agent you picked), `task_budget` lets the model declare a wider fan-out for work nobody enumerated (ceiling 8), and the thread's team is part of the entry prompt, so the model names your agents instead of inventing others.
- **The task card is one panel with five buttons** — the chat card mounted the task page's five sections as a stack, each folded by default: five titles and a scrollbar in a 360px flyout. One row of buttons now opens one shared panel at 420px, a section with nothing to say gets no button, and the execution trace answers which model, which adapter, which machine and with what permission — with a clock on every step.
- **The terminal now does what the console does** — a thread's roster was a web-only field. `/team` sets it from the REPL/TUI (bare opens a space-toggled picker), `/node` pins one turn to a machine, and `panda ask --team/--node`, `panda session ask --node` and the RPC surface carry both through `AskScope` — closing the hole where a roster chosen in the console did not bind turns sent from a terminal. The to-do board is reachable as `panda todo …` / `/todo` (list, add, edit, done, reopen, rm, and start-as-task), and `/task artifact <id>` reads the artifact pool from inside the session instead of failing on the id.

### Fixed

- **OpenCode runs on its free tier by default** — an unpinned run auto-selected the most capable model, so an account with no Go subscription or balance ended every task with "Insufficient account funds". Free models win by default, paid auto-selection is opt-in (`OPENPANDA_OPENCODE_ALLOW_PAID=1`), a billing/quota rejection retries once on the best free model, and `opencode-go` models are skipped when no credential is stored. v2 builds whose `opencode models` answers empty now take the `api model.list` catalog as the roster.
- **Panda's model reaches OpenCode on either wire** — the rescue path only accepted OpenAI-dialect models, so a node configured with DeepSeek's Anthropic endpoint could never hand a failed free-tier run to panda's model. The adapter now takes a dialect-neutral `OPENPANDA_MODEL_*` contract, writes an `@ai-sdk/anthropic` or `@ai-sdk/openai-compatible` provider fragment merged over the user's native config (MCP servers and permissions survive), and runs with `--standalone` so a v2 background service cannot keep serving its stale config.
- **"Auto" thinking means the provider default everywhere** — the REPL and entry client treated `thinking: auto` as an explicit reasoning request while the wizard and web form sent nothing; all surfaces now store it as unset and send no thinking field.
- **Advanced model knobs can be reset** — the settings API read `max_tokens`, `context_window`, `thinking_budget` and `max_retries` as plain integers, so the form's empty box (0) kept the old value and a stored retry budget could never be cleared or disabled. They are now optional fields: absent keeps, zero resets, a negative retry budget disables retries, and the REPL applies `--retry -1` instead of ignoring it.
- `panda update` survives a flaky asset host: release metadata is retried up to three times on a transport failure instead of failing the whole upgrade on a single reset, and the TLS handshake to GitHub's asset CDN gets 30s instead of the 10s default. The signed query string GitHub appends to asset URLs is redacted from the error, which used to push the actual cause off screen.
- `scripts/install.ps1` no longer aborts on Windows with `CRYPT_E_NO_REVOCATION_CHECK` (`0x80092012`): curl runs with `--ssl-no-revoke` when the local Schannel build supports it, so an unreachable certificate revocation endpoint can no longer stop the install. Chain, hostname and expiry are still verified, and the archive is still authenticated by SHA-256 against `checksums.txt`.
- **A task pinned to an agent the team excludes is refused, not re-staffed** — three tasks pinned to `agent:claude_code`, `agent:codex` and `agent:deepseek_harness` ran on a `[deepseek_harness, opencode]` roster, all three executed on deepseek_harness, and each printed `<name> 调用成功` for an agent that never started: three green passes, two of them fiction. The mismatch is refused before routing and the reason names both sides; a roster whose agents are not installed on this node says so instead of degrading to the unrestricted card.
- **The round roll-up waits for employees that never ran** — "本轮工作已全部完成" printed as soon as one employee reported, even with a colleague parked before execution ("尚未执行——批准后将继续执行"): `review` covered both a sign-off on finished work and a gate that never let the work start. A `review` row now holds the round open unless approving it accepts work that already exists (`accept_work` / `self_merge`).
- **A round's verdict counts the whole batch, not the last report** — a round where two employees finished and one failed was summed up in red as "本轮工作已结束（已失败）", and the recap printed the shared dispatch template once per job. The roll-up counts every report and names the split ("2 done, 1 failed"), amber when the round is mixed and red only when nobody finished; a common title head ending on a colon is printed once.
- **A substitute no longer passes for the agent that was asked for** — a task pinned to `agent:claude_code` that failed mid-run was finished by the fallback chain, and the transcript showed "DeepSeek Harness" above a job titled `连通性测试：agent:claude_code` with nothing saying why. The swap was recorded twice (an `agent_fallback` event, and a note at the head of the result payload) but the thread prints neither — it keeps one closing paragraph. The report line now names both sides.
- **The injection notice is one line, and it says which strategy** — the footnote prepended to a task's output repeated the same sentence in English and Chinese, which buried the agent's own answer, and a failure-time rescue read like a policy injection. The notice now names the agent, the model, the endpoint host and the strategy (`auto` / `always` / `rescue`); the `model_injection` event carries the same fields for the log, and `injection.model: never` no longer allows the rescue — "never" means the agent always uses its own model.
- **A custom relay keeps the dialect you configured** — with an aggregator provider (`opencode-go`) and your own OpenAI-compatible `base_url`, a `claude-*` model still took the route's Anthropic dialect and posted an Anthropic body to your relay: a 400 whose text pointed at nothing in the config. The dialect is now rebased only when the endpoint is the provider's own, exactly like the URL already was.
- **A refusal is an answer, and a nameless tool call is an error** — on the OpenAI Responses API the streamed path ignored `response.refusal.*`, so a model that declined produced an empty completion, which the caller read as "nothing was said" and paid a whole replay to hear again; the same round could also lose a tool call a proxy streamed as text only. Refusal text now streams and lands in the answer, the completion envelope fills whichever fields the deltas left empty, and arguments that arrive without their `output_item.added` fail with a diagnosis instead of a plausible empty answer.
- **One oversized stream event is reported, not replayed** — a single SSE event past the 1 MiB line buffer was classified as a transport drop, so the identical request was sent again — and billed again — until the retry budget ran out, ending on a message about tokens. The ceiling is 4 MiB now and `bufio.ErrTooLong` is final; the non-streaming client also waits 120s instead of 30s, because a thinking model passes 30s and each timeout used to buy another paid attempt.
- **`sandbox.mode: strict` refuses to run without its backend** — with no `sandbox-exec`/`bwrap` on the host the command was left untouched, so the isolation the operator configured did not exist and nothing said so. Strict now fails the run with the missing backend named; standard still runs (bubblewrap is a separate package on most Linux distributions) and `doctor` already reports the same condition as a failure.
- **A remembered "deny" no longer disables read-only tools** — one refused tier-2 operation made every tool in that project answer "工具执行被拒", `system_status` and `card_list` included, so the model lost its ability to observe anything and the thread never said why. The standing decision now applies to the operations that need authorization, which is what it was recorded for.
- **A streamed retry streams** — the guard that decides whether a response is JSON or prose was created once per call instead of once per attempt: a first answer that opened on `{` and then dropped mid-stream left the guard in "structured" mode, so the retry's text was withheld and the answer appeared in one burst at the end. Each attempt now decides for itself; what the user has already seen still counts across attempts.
- **Uploads between 16 and 25 MiB work again** — the API body cap was 16 MiB while the per-file limit was 25, so a legitimate upload died inside `io.Copy` and was reported as "save failed", which reads as a broken disk. Uploads and dictation get their own ceiling and an over-cap request answers 413 with the real limit. The same pass closed three smaller console gaps: `/healthz` no longer echoes database errors to anonymous callers, the event stream is capped at 64 concurrent connections, and a request body has to arrive within 60s.
- **A project's work directory cannot be the whole machine** — the console treats every project's `work_dir` as a readable root, so `{"work_dir": "/"}` turned one authenticated request into a viewer for the whole disk. The store now refuses a filesystem root, the home directory (or an ancestor of it) and the OS's own trees, wherever the project is created from.
- **A cached probe no longer outvotes the service** — a `run --help` that failed still cached "this build has none of these flags" for an hour, refusing restricted tasks with a diagnosis nobody had observed, and a model missing from a cached roster killed the task instead of asking the service again. Only a successful probe is cached, a roster miss re-probes before it is believed, and the cache files are 0600 with a clock change treated as an expiry.
- **A diagnostic probe no longer parks an agent** — `panda doctor` and `agents test` write their fresh verdict back into the routing cache, and that write dropped the "unknown" flag: an endpoint that merely timed out was recorded as definitely unreachable, so the next task skipped that agent for the cache TTL — the opposite of "what you printed is what routing uses".
- **Two memory writes no longer overwrite each other** — `memory_add` loaded MEMORY.md, changed the copy and wrote the whole file back, so two adds that overlapped each kept only its own view: a burst of 24 concurrent adds landed one entry, and every call reported success. The load and the save are one critical section now, behind a lock file in the store root, which also covers the CLI and the console editing the same file from another process.
- **The console stops re-running every agent probe on every open** — `/api/agents` spawns each installed CLI to read its version, and the settings page, the workspace, the node list and the team picker all fetch it, so opening the console paid for the same probes several times. Versions are cached for five minutes keyed by the resolved path (a newly installed CLI is a miss, not a stale hit) and failures are cached too, while the explicit test button always asks the CLI itself.
- **A pathological reply cannot take the message view down** — the Markdown parser recursed once per nesting level, so a wall of `>` markers or absurd indentation exhausted the JS stack with a RangeError instead of rendering. Nesting stops at twelve levels and the content is kept as text.
- **A busy node is no longer diagnosed as an owned one** — `nodeidentity.Acquire` reported every lock failure as "already running", so an unreadable config directory or a volume that refuses locks told the engine a daemon owned the row and it stood down. Only real contention maps to that error; the rest surface as themselves.
- **A promotion is recorded after it is written** — the Dreaming sweep announced each promotion to the audit log while the file was still unsaved, so a failed write left an "ok" record for an entry that never landed. The sweep also holds the store lock across load, score and save, so an entry an agent added mid-sweep is no longer overwritten.
- **Renaming a project moves its memory in one locked step** — the console copied the old memory file and then dropped the old directory as two separate steps; an entry added in between was either copied stale or erased by the drop.
- **A memory update that changes nothing writes nothing** — the store compared the result to the file it read and skips the rewrite, so a consolidation sweep that promotes nothing leaves the mtime (and every watcher) alone.

### Changed

- **Dispatch adapts to failures, and probes stop repeating** — adapter probes (`opencode models`, `api model.list`, `run --help`) are cached across adapter processes, keyed by the CLI's and config's fingerprints, so a burst of tasks pays each probe once; a rejected model still forces a fresh read. Local agent ranking now demotes an agent whose circuit the node's breaker holds open (still an alternate — never excluded), so the next task stops starting on the agent the last failures ruled out. The model breaker escalates repeated failures from 30s to 5 minutes and tries healthy fallbacks first, keyed by provider/endpoint/model so one provider's outage cannot cool down an alias on another endpoint.

## [0.1.0] - 2026-10-23 — "Constellation"

**The release-grade line begins here** — codename **Constellation**: the fleet drawn as one sky. Same-project tasks run in parallel through declared path scopes and isolated worktrees, under delegation bounds that tighten at every hop; a cross-network mesh carries work between nodes that cannot dial each other — two-key identity, blind relays, epidemic directory sync, K=2 rendezvous edges and the reachability ladder — and `panda://join` brings a new device in from one URI. One console commands it all: a verdict-first task page, a to-do board that hands work to the fleet, a thread roster, and a transcript that draws a screenshot as a picture — with the release audit's correctness and security work closed behind it, verified on a live Mac → relay → cloud chain.

Known limitations in this release: UPnP/NAT-PMP port mapping is not implemented; punch and directory frames do not yet converge on source signatures; mesh counters are not bridged across the panel's IPC; and cross-node hello replay remains an open protocol-level challenge-response. `docs/status.md` tracks each item.

### Highlights

- **The fleet reaches across networks.** Identity is two-key (a stable signing key plus a rotating one), a blind relay carries work between nodes that cannot dial each other, directories converge by epidemic delta sync, rendezvous edges are elected K=2, and the reachability ladder falls back from direct dial to hole-punch to relay to store-and-forward — with `panda://join` bringing a new device in from one URI.
- **One project runs in parallel.** `--paths` scopes a task to the directories it declares, `--isolate` gives it a private worktree merged back three-way, and delegation bounds tighten at every hop instead of being laundered by a permissive forwarder.
- **A release-grade safety posture.** Destructive commands can no longer pass as reversible, `sandbox.mode: strict` denies reading node secrets, an unreadable trust assertion fails closed, a relay can no longer reshape the scope the origin approved, and a known node cannot be impersonated by omitting its key.
- **The console became a place to work.** A task page that leads with its verdict, a to-do board that hands work to the fleet, a roster that hires a thread's own team, and a transcript that draws a screenshot as a picture.
- **Failure is now a state, not an exit.** A lost link waits for the network and replays the call, a model that reports failure is recorded as failed, every wire verdict is fenced by its dispensation attempt, and restart recovery resumes what survived instead of restarting it.
- **Self-evolution, off by default.** `panda self` carries signed patch sets through a queue, a merge worktree, an approval task, `make gate`, a staged swap and a `panda.release` rollback target — [Experimental], opt-in, and never in the path of ordinary work.

### Upgrading from 0.0.x

- No breaking changes: configuration, capability cards, stored data and the wire format are all carried forward, and migrations apply on first start.
- An existing install upgrades in place: `panda update` moves a node onto this cut, and a fresh install is `install.sh --version 0.1.0`.
- Building from source requires Go 1.26.10 (a security floor, not a preference — see the `govulncheck` entry below).

### Added

- **A model pin per agent** — `injection.model` was one node-wide decision, so a harness that speaks Anthropic Messages could only be injected by switching the node model to its dialect, which took the failure-time rescue away from every other agent. `injection.agents.<agent|adapter>` pins a model for that agent alone: unset fields inherit the node model, and the inheritance stops before `params`, `headers` and `thinking` — the transport knobs that would carry one dialect's body into the other.

- **The composer takes the voice** — dictation existed only for the TUI, whose sidecars open the microphone on the machine running the process: the wrong room when the console is opened over the LAN. The page now records 16 kHz mono WAV and `POST /api/voice/transcribe` relays it to an OpenAI-compatible `/audio/transcriptions`. The `asr` section is optional and inherits the active model, and a vendor refusal is reported as the vendor's own sentence.

- **A screenshot in the transcript is a picture, not a path** — a tool row that read or produced an image (`Read` of a `shot.png`, a capture that answered "saved to …") showed nothing but the filename, so checking what the agent actually saw meant opening the file by hand. The log now draws the picture under the call — a framed thumbnail capped at 220px — and one click opens it full screen with the path in the footer; Esc, a click outside or × closes it. `GET /api/fs/image` streams the bytes from the storage roots or the OS temp tree (images only, 16 MiB cap, `nosniff`), loads them lazily as the row scrolls into view, and a path that no longer exists leaves one quiet "preview unavailable" line instead of a broken icon.

- **To-do board: write it down first, decide later what Panda runs** — a new 待办 row in the rail: three lanes (to do / doing / done) where a note carries a title, description, priority, due date, tags and project; drag it between lanes, tick it off, and cancelled items fold into a footer line. "Hand to Panda" turns a todo into a queued task — its description becomes the prompt — and links the two. Todos live apart from the task queue on purpose: the queue drains itself, a todo only moves when you move it (migration v61, `/api/todos`).

- **A lost network no longer fails the turn — it waits for the link and carries on** — a transport drop used to spend the whole retry budget on a dead route within a few seconds and then fail the call, which is the wrong answer for a laptop that just went through a tunnel: an outage is measured in minutes, the retry ladder in seconds. A failed model call now probes the provider's own endpoint plus two public anchors first; judged offline, it waits — announcing "network unreachable, watching the connection" on the CLI status line, the TUI and the console — and replays the moment anything answers back, without spending a retry attempt. Endpoints that need no internet (a local model on loopback or the LAN) are exempt, `model.offline_wait: false` restores fail-fast, and the wait ends on your cancellation rather than a timer.
- **A note into a running task now says whether it arrived — and the console can send one at all** — `/queue` and `/inject` existed on every surface and were visible on none: the board kept the note but nothing told the user it was there, and the web console with a turn in flight silently dropped the text it had just accepted. Both are now first-class in the TUI — `/queue <text>` targets the task you last opened from the picker, an explicit id overrides it — and the console posts into the live turn instead of discarding it. Every user note carries a read receipt: a `✎n unread` badge in the task picker and on the board card stays until the round that folds it stamps `consumed_at`, and the `user_msg`/`user_msg_consumed` trace events record both halves, so "queued for the next round" is finally distinguishable from "nothing ever read this". An inject whose round belongs to another process still queues, but now says so rather than claiming an abort that never happened, and the TUI confirms delivery from the round loop's own callback instead of from a successful channel write.

- **A note you queued can be taken back, corrected, and escalated without retyping it** — mid-turn text now behaves the way a harness does, not the way a scratchpad does: Enter parks the line as your *next* turn and never folds it into the round already streaming, `ctrl+x` interrupts that round and leads the follow-up with the line, and `ctrl+d` takes the last parked line back before it is ever sent. Nothing typed mid-turn is appended to the prompt in flight any more, so the model reads each sentence once and the stored turn keeps the words that were actually sent with it. The console's pending strip — queue or inject, board-backed or process-local — gains a pencil and a trash: edits hit the row in place through `PATCH /api/sessions/{id}/notes/{key}`, so an inject stays an inject and keeps its place in line, and deleting a note the round already read is refused with a 409 rather than leaving the board disagreeing with the prompt. Attachments ride the note: a screenshot pasted into the composer uploads first and travels as `@path` in the note body, so the agent opens the file instead of reading a filename.

- **A thread hires its own team** — the composer's footer now carries a roster: every agent CLI the node knows, listed as a person with a face, a name and the job it is good at, and the picks become the only hands allowed to take that conversation's work. Empty (the default) keeps the scheduler free to choose per task; the pick is stored on the session, so a reopened thread still knows who works on it, and the roster is copied into every classified task's spec — which means it holds through plans, sub-agents and a hop to another node instead of being advice the model may ignore. A roster naming only agents this node does not carry degrades to unrestricted rather than stranding the task.

- **A `--json` failure is JSON too** — `--json` promised a machine-readable answer and then broke that promise on the first error: `panda task add --title ""` printed `task add requires --title` as prose, leaving a script to scrape stderr or ignore the reason entirely. Every non-zero exit now writes one object to stderr — `{"error": {"code": 2, "message": "task add requires --title"}}`, plus the `step` that failed when there is one — so a consumer parses a single format and branches on the code. stdout stays a clean payload stream, and the text paths are unchanged byte for byte.

### Changed

- **The workspace shows devices, not a map** — panels of agent marks replace the topology ring: the panel is the machine, the tile is the agent and whether it is working right now. And a round no longer closes on the first report of a batch — `roundStillOpen()` reads the task board, so "the round is finished" waits for the last one home.

- **A queue write no longer opens a network socket** — `panda task add`, `task send` and `task continue` reached their row through a full engine init, which claimed the node row's transport duties and bound the LAN-discovery port for the milliseconds between argv and exit. Eight parallel `task add`s therefore fought over `:7837` and printed `bind: address already in use` for work that was entirely local. Those three now take a local-only path: schema, store, card and identity key still come up, the discovery socket and the startup peer dial do not.

- **The toolchain floor is Go 1.26.10, and the gate runs `govulncheck`** — 1.26.9 carried GO-2026-6809 (crypto/x509 mishandles intermediates while building a chain), reachable here through the bus's own peer-certificate verification, so a node could be steered by a certificate chain it should have rejected. `make gate` now includes a `vuln` leg, so a vulnerable dependency or stdlib path fails the gate instead of being noticed at release time.

- **"查看任务" opens the task beside the transcript instead of leaving it** — the link under a dispatched task navigated to 队列·任务·项目, which cost the reader the conversation itself: its scroll, its draft, its place. It now opens the orchestration card with that task already picked — the thread's task list beside it — and the full page is still one click away in the card's footer, with ⌘/ctrl-click on the link going straight there.

- **A finished task reports who ran it and how it ended, not its whole transcript** — the session finalizer pasted the adapter's entire answer into the thread under a `[done]` tag: a two-thousand-word reply with its change list, its verification steps and the code fences inside them. The turn is now the orchestration line — state, the employee that ran it (`@claude_code`), and the job it was given — followed by that employee's closing paragraph, clipped at a sentence break, skipping a trailing code fence, table or "shall I keep going?" so the answer is not displaced by its own evidence. The play-by-play stays on the task page, and the model's history stops replaying its own past prose. Plan stages also carry the conversation id now, so a multi-stage run reports each employee's answer back into the thread instead of settling in silence behind a one-line receipt.

- **That report is drawn as a header, not printed as a wire tag** — the orchestration line arrived as literal text (`[done] @claude_code · 修复登录重定向`), so the first thing a reader saw in a Chinese thread was an English state token in brackets: the console leaking its own protocol. The tag stays in the stored turn (the history's unread dot reads it) and the transcript now draws it as a header — the state as a word in its own colour, the employee as a mono chip, the job's title in the primary ink — with the closing paragraph as ordinary Markdown underneath.

- **The task detail page is one column, and its facts no longer leave a hole** — the page split into a 636px reading column beside a 272px facts rail, but the facts are seven short values: the rail ran out 240px in while the event log kept going for another thousand, so the right half of the page stayed empty for the whole scroll. The facts are now a label-over-value band across the top (four to five per row, the UUIDs taking a cell of their own to wrap on) and everything under it — result, brief, board, delegation chain, sub-agents, log — shares one measure, which also gives tool output the width it was being wrapped out of. Timeline markers hang in the left margin, so every event's timestamp starts on the same line as the section titles above it.

- **The task detail page leads with its verdict, and folds what it cannot summarize** — the page opened on a facts band: five columns of grey ids, a trace strip, then a result section whose useful line was a 300-character error string, with the eighteen-row event log (55% of the page) printed in full underneath. A verdict block now comes first — the state badge, one sentence of what happened (the failure the run reported, its own verdict, or the last line it wrote), and what the answer cost (elapsed, rounds, tokens, money) — with the reason clamped to three lines and the rest one click away. Under it the reference facts fold into one header line (`#id · project · owner · created`), the brief folds to its first sentence plus a constraint count, and the log opens on its last five events. The result section no longer repeats the state, the reason, the tokens or the cost the verdict already states; it disappears when it carried nothing but a failure, and the log's final result row stops printing the same output a second time. Agent-session scratch files (`.claude/…`) no longer count as changed files.

### Fixed

- **Multi-hop tasks can pull their inputs through the relay again** — artifact fetch and chunk frames now ride the blind-transit plane, with a 2 MiB sealed-body budget that holds one 1 MiB chunk per frame. An executor two hops from the origin receives its project tree instead of failing with "peer not connected". Verified on a Mac → relay → cloud chain across a WAN link.
- **A model that reports `status:"failed"` is no longer recorded as done** — a clean adapter exit no longer masks the model's own failure. The reason reaches the retry loop, the delegator and the task timeline instead of only a trace event.
- **A peer's decline hands the task back to a capable origin** — when the best remaining place to run a declined task is this node, the queued row is claimed and executed locally instead of surfacing a false failure (and a synchronous submit no longer waits on a row nothing would run).
- **A known node cannot be impersonated by omitting its Ed25519 block** — once a node id has a key on record, a hello must present that key; a key change is an operator action (`nodes remove` / re-pair). Previously any mesh member could claim a known id keylessly and inherit its trust zone.
- **Delegated project packs are unpacked only after trust admission, with receiver-side bounds** — an `open` or refused origin can no longer write into project memory just by sending a delegate, and a compression bomb is bounded by decompressed size and free space rather than the sender's claim.
- **A datagram `hello_reject` can no longer kill the UDP plane** — connection-bound hello frames are dropped before dispatch, and the handler tolerates a nil connection. One sealed frame from a member used to end the single UDP read loop for the whole node.
- **`sandbox.mode: strict` denies reading node secrets** — the config/card, SQLite file (node Ed25519/X25519 private keys), its WAL/SHM siblings and the subscription OAuth token store are read-denied. Only the files are denied; parent directories stay readable so work trees keep working.
- **The standalone `panda-webui` sidecar serves the thread and skills APIs** — sessions, worktrees and the skill store are wired into the sidecar `make run-local` launches, so opening a thread or the Skills page no longer lands on a 404.
- **`panda model add custom <url>` no longer panics** — an empty positional list is a usage error, not an index-out-of-range crash.
- **Uninstall backups are private and abort deletion on failure** — the archive is written 0600 (it holds the mesh secret, provider keys and node private keys), and an unreadable file or full disk now stops the uninstall before anything is deleted instead of producing a partial archive and deleting the originals.
- **Session runtime state is never merged into the user's branch** — the whole `.openpanda/` tree (worktrees, composer uploads, task scratch) is excluded from the session merge's `git add -A`; a pasted screenshot or secret no longer becomes a commit.
- **`--json` forms exit non-zero on failure** for `agents test`, `config model test` and `session rm`, and `session rm` emits only JSON (errors included) instead of human text mixed into the stream.

- **The directory's share cap now counts the row's signer** — one member could sign rows for arbitrary fresh ids, and because a non-stable id is never pinned, those rows counted against nobody: its share stayed at zero while the table grew to the 1024-row cap, leaving an honest new peer with no room to publish its own row at all. One member could silence the fleet's directory. The signature covers the row's own key, so who signed a row is now proof, and the cap counts that.

- **A dial timeout no longer closes the connection it started** — the reachability ladder gave each candidate address a timeout and handed the same context to the connection's read loop, so the timeout's cancel closed the socket before the peer's hello reply was read. Every gossip-address dial and every rendezvous dial died on arrival and silently degraded to relay-or-punch. The dial budget and the connection lifetime are two different clocks now.

- **An unreadable trust assertion fails closed** — both directory lookups swallowed their SQL error, so a transient busy database made a `guarded` (or `open`) peer read as full-trust `mesh`: the send ceiling, the artifact-input clamps, relay admission and the screen-output exemption all applied. A peer whose tier cannot be read is treated as `open`.

- **A cross-NAT pairing can no longer take the node down** — a pairing that arrived over a relay has no connection, and the expiry sweep closed it unconditionally. The nil dereference was caught by the monitor's panic guard, whose cancel stopped the whole daemon. The sweep now uses the nil-safe close and drops the expired session.

- **A relayed punch request reaches the node that asked** — the request's origin rode the envelope, and a relay re-mints the envelope as itself, so the elected offerer punched the relay (already reachable) instead of the requester. The origin now rides the payload, and the regression test drives the real relayed path.

- **An unsealed transit frame is refused** — the exemption that lets a pair handshake ride a relay unsealed had no test at all: removing the guard left the suite green. A member could seal nothing around a delegate and have every relay that carried it read the plaintext.

- **A relay can no longer reshape the scope the origin approved** — the consent digest was a hand-maintained field list, and the task's declared write lanes and worktree-isolation flag were added after it was written: an authenticated relay could rewrite either and the origin's Ed25519 grant still verified. Both are bound now; chain and budgets stay unbound because relays legitimately rewrite them.

- **A child that loses its spawn bound fails instead of running weaker** — spawning persisted the child's depth, spawn cap, scope, isolation, work dir and budgets as warnings. The row is what every later hop and restart reads, so a lost isolation flag let a child promised a private copy run against the shared checkout, and a lost budget read as unbounded. Each failure now cancels the child and fails the spawn.


- **A destructive command can no longer pass as reversible** — the tier classifier judged a command by its verb, so `cp`, `mv`, `chmod`, `chown`, `ln`, `tee` and `kill` were auto-approved in every form: `cp payload /etc/cron.d/x`, `chmod u+s /usr/bin/find`, `ln -sf /etc/passwd ./shadow` and `kill 1` all ran without asking. Those verbs stay Tier 1 in their ordinary form — copying a file into your own tree is not an incident — but the form that reaches a system path, sets a setuid bit, overwrites a system file through a link, or targets init now requires authorization. Code run through an interpreter is covered the same way: `unlink`, `rmtree` and `rm -rf` spelled inside a script escalate like the shell command does.

- **A daemon that cannot bind its port exits instead of retrying forever** — a held `listen_addr` produced `websocket listening` (printed before the bind, not after), then a `listen failed, retrying` warning every five seconds, forever, with exit 0: a supervisor read that as a healthy node that could never accept a peer. The bind is now synchronous, retries are counted with a countdown, and after 60 seconds the daemon exits 1 naming the address, the attempt count and the last error. The grace window still covers the one case that resolves itself — a same-identity engine releasing the socket on exit.

- **A mistyped `--config` is an error, not a warning** — `panda nodes --config typo.yaml` warned, exited 0, and read the *default* config while writes went to the typo'd path, so a command could list node A's peers and write the edit into a fresh file beside nothing. It now exits 2 naming both the bad path and the usual one; `panda init` stays exempt, since its `--config` is the write target and must not exist yet.

- **"The daemon is not running" is no longer guessed** — when `ps` could not be read, the pid probe answered "no", so a hot-reload signal reported a stopped daemon on a machine where it was running. The probe is now tri-state (matches / stranger / unverified) and the message follows it: an unverifiable process produces "could not check", never a verdict it did not reach.

- **The unpacker stages through a random name, not `path + ".partial"`** — a fixed staging name is a pre-planted link away from an arbitrary write: an archive shipping an entry `x` would have the extraction open `x.partial`, and a symlink already sitting at that name (shipped one entry earlier, or left by an earlier extraction) would have carried the bytes somewhere else. The staging file is now created `O_EXCL` under a random suffix, so a planted name is neither followed nor reused, and the archive's mode still lands through the umask.

- **Delegated tasks re-route on executor lease expiry instead of dead-ending** — a dispatched task whose executor's lease lapsed used to fail outright; it now returns to the queue under a fresh attempt, the evicted executor is excluded from candidates, and when no alternate route exists the re-delivery parks in `task_outbox` waiting for that node's revival instead of manufacturing a false terminal verdict. Absolute deadlines still beat retry budget: a row past `deadline_unix` settles expired no matter how much retry remains, and pinned tasks are never silently re-pointed at a substitute (bf34652).
- **Every wire verdict is fenced by dispensation attempt** — `task_accept`/`task_decline`/`task_cancel`/`task_resume`/`task_result` now carry `attempt_id` end to end: a frame strictly older than the row's current dispensation is a stale echo of an attempt the delegator itself replaced and is dropped (an accept claims, a decline bounces, a dispensation cancel kills — each used to be able to hit the fresh attempt). Human cancels stay tree-scoped (`attempt_id` empty kills whatever the row holds), while expiry/supersede kills name their attempt and a parked `cancel_outbox` row keeps its scope across restarts (migration v55).
- **A re-delivered delegate may only supersede a copy its sender actually owned upstream** — the replacement frame now requires the sender to appear in the stored chain before this node, closing a hole where any peer could mint a fresh attempt id and wipe (or resurrect) somebody else's task row. A live copy being replaced is cascaded down first — runner killed, context reservation freed, downstream stand-down forwarded — instead of silently dropped under the new row.
- **Stranded and superseded runs can no longer write verdicts onto rotated rows** — runner-side completion/failure/pause/review writes are attempt-CAS'd (`CompleteAttempt`/`FailAttempt`/`Pause*`/`Review*`), the retry loop stands down when the row's attempt moved past its own, and the stranded-run cleanup only touches a running row this run itself claimed.
- **Custody-expiry and sweep verdicts bind the dispensation they convicted** — the lease monitor's expiry settle now skips a row that rotated between scan and settle (the lapsed lease convicts the scanned attempt only; an absolute deadline is re-checked on the fresh row and still binds), parked `task_outbox`/`resume_outbox` TTL and bundle-verify expiries expire only the attempt the custody was taken on (`MarkExpiredAttempt`), a stale context fetch's decline/hash/store failure can no longer fail the dispensation that replaced it, and the orphan sweep plus dispatch-error `failLocal` paths carry the attempt they observed rather than killing whatever the row holds later.
- **Store-and-forward custody orders correctly across a link flap** — parked cancels flush before parked delegates (the stand-down always beats the re-delivery it was meant to precede), a parked human cancel is never cleared by a newer delivery parking, task-outbox rows no longer resurrect terminal/failed work, and a restarted daemon reclaims its parked custody under its stable identity rather than the bounced instance id.
- **Delegated runs settle through the shared retry loop and ship slimmer output** — the three executor-side execution paths now funnel their outcome through `settleDelegated`, so checkpoint resume, budgeted retries and upstream decline behave identically for delegated and local work; context-resumed and artifact-resumed runs decline under the parked attempt rather than whatever the row happens to hold later; and output packs skip regenerable directories (a measured 389 MB result pack shrank to 84.6 MB) (f53ddcf).
- **Restart recovery resumes what survived and names what blocks** — interrupted runs are resumed instead of restarted from scratch, agent-switch progress surfaces early, project-key matching folds case, restart recovery no longer reclaims peer-executed rows, foreign-pinned queue tasks are unpinned correctly, exec-lock waits report who holds the lane, and malformed adapter JSON is guarded (e0c7bec, 5044f4a).

- **The Windows installer refuses a downgrade the way every other path already did** — `install.sh`, `panda install` and `panda update apply` all refuse a binary whose migration ceiling sits below the data directory's `user_version`; `install.ps1` copied the archive over the prefix unconditionally, so an older release could be installed over a newer database and leave a daemon that dies at startup with the data stranded behind it. The staged archive is probed with `panda version --json` before the prefix is touched, and `-Force` / `OPENPANDA_FORCE=1` covers a deliberate downgrade.

- **The shell installer verifies the release signature, not just the checksum** — `checksums.txt` arrives from the same origin as the archive, so SHA-256 could not catch both being substituted together. `install.sh` now verifies `checksums.txt.sig` under the same pinned Ed25519 key the self-updater enforces: a mismatch aborts the install, and only a host whose openssl cannot do Ed25519 (stock macOS LibreSSL) degrades to an explicit warning. `OPENPANDA_REQUIRE_SIG=1` makes an unverifiable release fatal.

- **`install.ps1` resolves versions from the repository it downloads from** — the API endpoint was pinned to the upstream repo while `OPENPANDA_REPO_URL` moved the download base, so a fork or mirror resolved a tag it does not serve.

## [0.0.12-preview] - 2026-10-19

The v0.0.12 preview — codename **Constellation**, the fleet drawn as one sky. This cut lets same-project tasks fly in formation — delegated children and hand-dispatched work run in parallel through declared path scopes and isolated worktrees, under delegation bounds that tighten rather than launder at every hop — while the console consolidates into the single place that constellation is commanded from: queue, plan board and projects merge into the Control page, the workspace page draws the whole fleet as a live topology map and fires turns straight into a picked thread, and a profile page answers who this node is and how busy it has been. Talking to a running task becomes first-class — queue a note, or steer the round in flight — a parked long task can be continued instead of only accepted or rejected, context overflow recovers through adaptive replay budgets, execution leases hold across processes, and the model catalogue moves to the current generation under a per-model token policy — with a hardening round keeping node secrets out of artifacts, user data owner-only, and cancelled agents from outliving their task.

### Added

- **Sibling tasks on one project fly in parallel — path scopes and isolated worktrees** — delegated children of a project used to serialize on the monolithic `project:<name>` lock even when their work touched disjoint trees. Two modes now unlock real same-node parallelism: a `paths` scope locks only the named project-relative directories (`scope:<project>/<path>`), so disjoint siblings share the worktree at once while overlapping, ancestor/descendant and undeclared scopes still serialize; `isolate` hands the child a private copy — a detached git worktree at HEAD overlaid with the uncommitted delta (dirty, renamed, deleted, untracked and ignored files), a skip-set copy off-repo — merged back three-way on success, with both-sides-diverged paths reported as conflicts that keep the main tree's bytes and a conflicted workspace kept and reported to the parent's board. The modes are first-class user choices on every surface — `panda task add --paths d1,d2 | --isolate`, the same flags on the REPL's `/task add`, and a parallel-mode selector on the console's new-task form — with kanban badges, a lane strip above the queue that lights up once two or more tasks genuinely run at once, parent links in the detail page and the REPL record, and per-lane prompts so a scoped run hears which directories it owns. A scoped/isolated claim that cannot mean what it says (no resolved project, both modes at once) is refused on every surface instead of silently degrading to a whole-tree claim. Delegation itself is bounded end to end: `delegation.{enabled,max_children,fan_out,max_depth}` in config (`panda config delegation`), the depth and cap riding `TaskDelegatePayload` with the tightest bound surviving each hop — a permissive forwarder cannot launder it — and anonymous tasks lock `task:<id>` instead of a global agent key, so independent work no longer queues behind a lock it never shared (d476a7d, 6a5ca17, bfc95ac, 93bcdc4, 50c24a3).
- **Talk to a task in flight: queue a note, or steer the live round** — `panda task send <id> -m …` lands a durable board note that folds into the agent's intent at its next supervision round — nothing interrupted, a queued task reads it at its first round — and `task send --inject` goes further: the note is marked steer-grade, the in-flight round aborts with its result discarded (never a failure), and the text leads the next round's intent ahead of the supervisor's follow-up — the queue/steer split Claude Code and Codex users know. Delivery is board-backed and restart-safe end to end, exactly-once via the round loop's seen-set with one slot per message; a steer landing while the judge deliberates grants one more round instead of closing the task unread (capped at four on-the-house rounds); a cross-process send degrades honestly to next-boundary delivery, and a task running on another node refuses with the executor named rather than accepting a note its agent would never see (5af3330, 2fb77da).
- **A review-parked task can be continued, not just accepted or rejected** — a task parked with `needs_followup` (the supervised round budget ran out mid-work) had two answers; `panda task continue [-m NOTE]`, `/task continue` and `POST /api/tasks/{id}/continue` add the third: the operator's note lands as a steer-grade board message, the row flips review → queued under an exactly-once CAS, and the daemon re-runs it under a fresh round budget reusing the persisted agent session and work dir — which is what makes the verb work from a CLI or a console while the daemon owns the run. The detail page shows Continue ahead of approve/reject only when the parked result really asked for it (7ee6fd0).
- **Context overflow recovers in flight** — the replay window now scales to the serving model's advertised context (3/16 of it in chars, clamped 8K–160K — a 128K model lands exactly on the old fixed 24K), wired through the REPL, `ask --continue`, session threads, RPC and the console. An agent run that overflows its window retries once in the same round: run notes fold into a supervisor-written digest (a hard-capped tail without one), the resumed handle and pooled session process drop with it, and the prompt rebuilds at a quarter budget with skills degraded to index lines; a second overflow parks for review as before, and the failed attempt's tokens still bill (f4a64c6).
- **Execution leases hold across processes** — inbound delegates, inline submits and a second core on one database bypassed the in-process run registry, so two executors could claim overlapping lanes at once; every run now funnels through a shared `exec_locks` table claimed under `BEGIN IMMEDIATE` (the registry's own worktree key set plus the resolved actuator). A GC trigger frees a task's rows on any transition out of the live states, and a per-run nonce predicates each release, so a late unlock can only drop the run's own rows — never the fresh rows of a re-execution under the same task id (c05b99e).

### Fixed

- **A finished task's digest is no longer cut in half** — the console folds a task's result into the thread as one assistant turn, and that turn was capped at 800 *bytes*, compared with `len()` rather than a character count: a Chinese result stopped after roughly 347 characters and ended on a `…` with no way to expand it, so a task that had finished read like a model that had stopped mid-sentence. The turn now carries the whole answer (and a failed task's whole reason). Nothing needed the cap: the transcript is local and append-only, and the replay window is bounded separately by the history budget.

While a turn runs the same line carries a live count that advances once a second — the finished number lands in the row it was already occupying instead of appearing out of nowhere.

- **A workspace's runtime scratch lives in a hidden `.openpanda`** — a work root that is not the node data dir is a user-visible workspace (an adopted launch directory or an explicit `storage.work_path`), and the daemon used to drop its `tasks/`, `plans/` and `projects/` scratch right there. All three now derive from `<work_path>/.openpanda`, and a git workspace additionally gets `.openpanda/` appended to `.git/info/exclude` — the checkout's status stays clean without touching the user's `.gitignore`. The node data dir keeps its top-level layout, and directories created by older builds are left in place (they may hold the user's only copy of a deliverable) (10b6208).

- **CLI state directories are platform-native** — macOS gets them nested inside the Application Support folder instead of scattering a second `~/.local` root through the home, and Windows inside `openpanda-data` instead of colliding with the install prefix `%LOCALAPPDATA%\OpenPanda`, where an uninstall would have taken the CLI's history with it. A one-shot migration folds the old unix root into the new location, so an upgraded box keeps its history (6d80afb).

- **Trailing flags no longer swallow their neighbours' values** — the argv-hoist step consulted a hand-kept table of value-carrying flags, and a flag missing from it was hoisted bare: its value slid back among the positionals, so the documented `panda pair --secret s --peer a` set the secret to `--peer` and printed usage, `plan run p.yaml --priority high` read `high` as the plan path, and `task artifact <id> --file f` handed the task id to `--file`. Every command now derives its value-carrying flags from its own FlagSet, so the table cannot drift from the definitions again.

- **Windows-packed artifacts no longer strip a checkout's executable bits** — a packer that cannot express POSIX exec bits ships every file at 0666, and unpacking such a tree over an existing project replaced each script's 0755 with 0644: a real run left `git status` reporting dozens of 100755→100644 flips. A landing file whose archive mode carries no exec bits now keeps the destination's — new files still get the archive mode verbatim, and a symlink at the path is deliberately not consulted — so re-adopted trees stay runnable.

- **User notes into a task carry a real timestamp** — `PostUserMessage` left `sent_at` at zero, so every note sent with `task send` or an inject rendered as "~57 years ago" on `panda task board` and fell out of time ordering. The note now stamps the send time like every other board post.

- **Transcripts, memory files and installed skills are now owner-only** — session transcripts, the memory store (`MEMORY.md`, daily logs, `DREAMS.md`), the skill hub's installed copies and the state around them were created 0644/0755 inside the user's data directory, readable by every other local account, though a transcript is verbatim user text and routinely carries pasted secrets. New files now land 0600 and directories 0700, and a pre-existing session directory or daily/dream log is tightened on next use — the same posture the config store already kept.
- **Artifact extraction refuses to be walked out of its destination** — unpack followed symlinks that existed at the destination before the archive was opened, so an archive (or a pre-existing link inside the project) could redirect a member's write anywhere the daemon could reach; every ancestor on a member's path must now resolve inside the destination root, while links shipped inside the archive may still point inside it. The entry count is capped against inode floods, and permission fixes skip symlink targets instead of writing through them.
- **Commands refuse stray arguments instead of running with them ignored** — a leftover word after a command that takes no positionals (a mistyped subcommand, a path pasted behind the wrong command) used to vanish into `fs.Args()` and the command ran as if it had never been there. Commands with no positional arguments now print the offending arguments with their usage line and exit 2, so a mistyped invocation is corrected before its side effects land.
- **The console's folder picker stops hanging and resolves `~/`** — a native dialog left open parked the picker's handler goroutine, and each repeated click stacked another osascript/zenity/PowerShell behind it; the invocation now carries a 5-minute timeout and the helper is killed with it. The directory listing also resolves paths the way file browsing does, so typing `~/projects` expands the home prefix instead of failing as a literal path.
- **A probing relay no longer convicts the agent behind it** — a probe deadline was treated like a refusal, so an endpoint queuing behind its own upstream account pool — Claude Code behind cc-switch answering 200 in 3–6 s one moment and 18–40 s the next — dropped out of rotation for the failure TTL while the very next request succeeded. `ProbeVerdict` now carries an `Unknown` grade set only for a deadline, a rate limit is no longer read as a credential rejection, and a slow relay gets room to answer before the verdict lands (f1e903f, 5c16c85, b1e5a07).
- **A failed round brings its reason home** — three places threw away why a task died: the claude_code adapter rode out ten exponential backoffs on a sustained 429/529 while emitting nothing the silence watchdog could read, so a rate limit was killed as a hang and the work was lost anyway; the verdict line dropped the cause with it. Rate limits now abandon the round instead of riding the backoff, and the failing round's reason reaches the task record, the trace and the panel instead of a bare "failed" (efaba97).
- **Queued work stops dead-lettering** — an owning engine (`panda web`, a QueueTasks REPL) never heartbeated its node row and went stale ~90 s after init — dead to peers, and dead to a consumer-liveness probe that was itself process-local — so enqueues and board notes vanished without a word. Row owners heartbeat now, consumer liveness consults the store, sends against a dead store surface the warning, engine-less delivery paths can no longer accept a note for a task a remote node owns, and board messages relay hop-by-hop under origin binding so a note reaches its owner across the partial mesh (ae08a10, 48326e2, 2fb77da).

## [0.0.11] - 2026-10-15 — "Rendezvous"

The stable v0.0.11 — codename **Rendezvous**, the orbital meeting. This cut folds the preview line — per-session AEAD inside the signed hello, Bluetooth-style pairing, signed discovery beacons and stable `k:<pub>` identities, hard node pins across multi-hop routes, the partial-mesh data plane, the inter-task message board, and git rollback for agent work — together with this cycle's additions: desktop nodes grow computer-use eyes and hands (screen capture and synthesized input as first-class actuators, on POSIX and stock Windows alike), task output becomes retrievable as packed artifacts from the CLI and the console, and display content travels under its own mesh-only trust rule end to end — through delegation, pushes, pulls, and a screen stage's output consumed as the next stage's input.

### Added

- **Computer-use eyes and hands** — two new reference actuators make a desktop node usable for GUI work: `drivers/panda-screen` captures the screen (macOS `screencapture`, Linux grim/scrot/ImageMagick, Windows PowerShell) as `hardware:screen_capture`, and `drivers/panda-input` synthesizes input (cliclick+osascript / xdotool / ydotool / PowerShell — move, click, dblclick, type, key, scroll, pos) as `hardware:gui_input`, gated at tier 2 because clicks and keys are irreversible. `DetectActuators` probes the bundled `drivers/` tree automatically (`OPENPANDA_DRIVERS_DIR` overrides it exclusively, then PATH, then the shipped layout), `panda install` and release packages ship the drivers, and actuators declared `Interface:"desktop"` are only advertised when a GUI session plausibly exists — console-owner check on macOS, `DISPLAY`/`WAYLAND_DISPLAY` on Linux, non-Services session on Windows, `OPENPANDA_GUI_SESSION` to override — so a headless daemon never claims a screen it cannot see. The routing prompt teaches the capture → reason → actuate chain.
- **Task output artifacts are retrievable** — a bare task's private work dir is now packed and adopted as its output artifact (an actuator's screenshot, an agent's report file no longer strand under `work_path`; empty dirs pack nothing, pinned/project dirs are never bulk-packed). Retrieval surfaces: `panda task artifact <id> [--list|--file <path>|--out <dir>]`, three authenticated panel endpoints (`GET /api/tasks/{id}/artifact`, `/artifact/files`, `/artifact/file?path=`), and a console ArtifactSection that lists the manifest, previews images and text inline, and downloads single files or the whole bundle. `artifact.Store` gains `Entries`/`OpenEntry` — manifest listing without unpacking and single-file streaming with path-traversal checks.
- **[Experimental] Screen-capture tasks are mesh-exclusive** — display content gets its own trust bit instead of riding the ordinary participant check: `requires`/`action_spec` hits on `hardware:screen_capture` (including broad tokens like `hardware:*` that could resolve to it) mark the task; guarded peers are filtered at send, non-mesh origins are refused at admission (`trust_policy_refused`), and the artifact-serving side releases screen-bound output to mesh peers only — participation and signed grants cannot widen it. Because an operator-defined `screen_sensing` actuator id is only classifiable on the producer's own card, the executor stamps a persisted `screen_output` mark at claim time (migration v45) that rides `task_result` so every delegator hop re-stamps its row; cached authorization verdicts remember the screen bit and re-check the peer's tier on every hit, so a trust demotion cuts a transfer mid-flight. A screen stage's output handed to the next stage as an input keeps its binding the same way: the orchestrator stamps a provenance mark on the input ref, and a consumer of display bytes is itself display-bound — its working tree, and therefore its produced artifact, can embed the pixels — so the mark cascades stage to stage. `network.trust.send.guarded.screen: true` is the explicit same-owner override.
- **Windows computer-use entry points** — `drivers/panda-screen.ps1`, `drivers/panda-input.ps1` and `drivers/panda-notify.ps1` run the eyes/hands/notify drivers on a stock Windows node — same CLI and exit codes as their POSIX siblings, no git-bash required. Detection resolves them into `pwsh -File <script>` (pwsh first, the inbox PowerShell 5.1 as fallback), and -File hands every argument to the script as a literal string, so text arriving from an action_spec stays text; batch wrappers are deliberately not auto-resolved because cmd.exe parses its command line by its own rules and an argument carrying `&`, `%` or a quote can split into a second command (golang/go#27199).

### Fixed

- **Signed update channel closes the last gaps** — the official Ed25519 release key is compiled in as the default `ReleasePubKey`, so every build verifies `checksums.txt.sig` out of the box instead of failing closed on key-less dev builds; `OPENPANDA_UPDATE_UNSIGNED` is the explicit escape hatch for self-hosted unsigned channels; `install-local` keeps `~/.local/bin/panda` a symlink into the release-prefix tree so `panda update` swaps the image the supervised daemon actually runs.
- **`panda-input` BSD sed** — the key-name capitalization used a GNU-only `sed` escape; on macOS it mangled `key up` into `uup`. Explicit casing now.
- **A Windows node advertised no bundled driver** — the probe only looked for the extensionless POSIX scripts: os.Stat never reports an execute bit on Windows and LookPath cannot match a file without an extension, so a Windows desktop node declared no `hardware:*` actuator at all and the computer-use pair silently existed on macOS/Linux only. Resolution is now per-platform (`.ps1`/`.exe` on Windows, the bare script on unix) and the card carries the invocation rather than a bare path, so PruneUnavailableActuators keeps exactly what this host can run.
- **Agent CLIs installed outside PATH are found on Windows too** — `InstalledBinary`'s fallback dirs were Homebrew/usr-local paths and its runnability check required a unix execute bit (never set on Windows), which made the whole fallback dead code there; dirs and check are now per-platform (`%APPDATA%\npm`, winget Links, scoop shims, cargo).
- **`panda-input key tab` / `key F5`** — the documented named keys were lowercased before the backend tables matched them case-sensitively, so Tab and the F-keys died as "unknown key" on macOS and typed literal letters through the Windows branch; the canonical names are now spelled out for both backends.
- **`panda metrics --runtime` reports the daemon's load on Windows** — the daemon line there was liveness-only (no `ps`); RSS now comes from GetProcessMemoryInfo and CPU/uptime from GetProcessTimes, with CPU printed as consumed time ("cpu=4.2s") rather than an instantaneous percentage a single sample cannot give.
- **Bare `panda --help` lists the new task verbs** — the top-level usage never mentioned `task artifact` or `task board` (the `task` sub-usage, shell completions, and the READMEs all did), so the artifact-retrieval surface was undiscoverable from `--help` alone.

## [0.0.11-preview] - 2026-10-14

The v0.0.11 preview — codename **Rendezvous**, the orbital meeting. This cut consolidates the whole line: peer links negotiate per-connection AEAD encryption inside the signed hello; devices join a node network the way Bluetooth pairs — pick a device, compare the code, confirm on both sides — instead of copying secrets by hand; work pins to a node two hops out through the gossiped topology, with contexts and artifacts relayed hop by hop; and sibling stages of one plan now pass notes to each other on a bounded message board instead of waiting for terminal results. Agent work on a real checkout is reversible — `panda task revert` restores a pre-task git baseline. Trust tiers clamp what untrusted peers may carry, and every stage of a task's life reports where it actually stands. The preview was validated end-to-end on a real three-device fleet (macOS ↔ Windows ↔ Linux SBC) including mid-run node kills, reconnects, and replay. (The alpha/beta line ran as *Periapsis*; the name was retired because it already belongs to v0.0.9.)

### Added

- **[Experimental] Bluetooth-style LAN pairing** — `panda pair` discovers devices on the LAN, both sides show the same short code, both confirm, and the devices join the node network; no secret copying, no address typing. Unsigned beacons are refused at admission, and secrets provided via environment variables stay off disk.
- **[Experimental] Encrypted peer sessions** — every connection negotiates a per-session AEAD key (HKDF over the shared secret and both nonces) inside the signed hello. Legacy peers fall back to cleartext only under an explicit policy (`network.allow_cleartext_for`); plaintext dials off encrypted underlays are refused.
- **Zero-config LAN discovery** — Ed25519-signed discovery beacons (replay-guarded, with single-use punch frames), a stable node identity keyed by `k:<pubkey>`, and auto-dial for a verified key across IP and instance drift. `panda nodes` marks signed beacons and warns on unsigned ones.
- **Hard node pins, end to end and multi-hop** — plan stages and tasks carry their node pin through planning, routing and execution: the work runs on the named node or the task fails with an honest reason — never silently rerouted. `--preferred` and plan-stage `node:` pins resolve through the gossiped topology: a node two hops out (present only in an online peer's link-state advertisement) routes over the cheapest advertised path while the wire keeps the ultimate destination identity, and every hop re-resolves it; a node already in the delegation chain still refuses the loop. Results record the executor and its workspace, so "where did this run" is answerable from the queue, the task card and the result itself.
- **Partial-mesh data plane** — pointer-context snapshots and stage artifacts relay along the delegation chain: an executor that can only reach the node that handed it the task pulls its snapshot and inputs through that hop, each relay validates the content hash and the source identity before forwarding (artifact chunks route only to their askers, deduplicated per offset), and stale relay entries are swept. Two-hop pipelines and pins no longer die on "context source unreachable" or "artifact not held" one hop short of the bytes.
- **[Experimental] Inter-task message board** — sibling stages of one plan, and a parent with its delegate children, exchange short notes mid-run instead of waiting for terminal results: agents post via the structured `messages` result array or the `PANDA_MSG` line marker, the scope owner resolves addresses (`stage:<id>`, `parent`, `children`, member task ids and unique prefixes) against the roster it alone holds and fans out to each member's node, and received posts fold into the sender's next supervision round under `[sibling board]`. Slots are one-per-(sender, recipient) so a chatty task cannot evict anyone else; a per-episode budget meters sends (`messages.budget`, default 8); `panda task board <id>` inspects a task's boards. Delivery is best-effort — the slot model makes a dropped note correctable by the next post — and a post naming a non-member (sender or recipient) is refused as scope drift.
- **[Experimental] Git rollback for agent work** — a run on a real git checkout now gets an undo point: the whole pre-task tree (tracked + untracked) is snapshotted to `refs/heads/panda-base-<id>` through a scratch index without touching the user's index or branch, and `panda task revert <id>` restores it and sweeps post-baseline files (nested trees included). Session merges land `--no-ff` and record `refs/openpanda/` merged/premerge refs, so `panda session revert` resets cleanly or `git revert -m 1`s when later commits sit on top — refusing on a dirty checkout rather than entangling user work. `session diff --stat` (and `session merge` pre-flight) prints a numstat roll-up plus binary/sensitive-path flags (`.env`, key material), and the web console surfaces the same diff stats and revert verbs. `task delete` drops the task's panda-owned refs.
- **Interactive task queue + follow-up turns** — `/tasks` opens a selectable list mirroring scheduler order (drag seq → priority → FIFO) that refreshes in place on completion watch events while keeping its cursor; pressing Enter on a terminal task, `/task followup <id>`, or `panda task followup <id>` feeds the recorded result back through the model as a real streamed ask turn — the prompt carries task identity/state and a rune-bounded result digest. Completion notifications point at the follow-up entry, closing the submit → queue → continue loop.
- **Operable memory console** — entries in USER.md, MEMORY.md, topics and projects are filterable/editable/deletable/quick-addable through one shared list component; daily diary files can be deleted singly or pruned under the 30d/90d retention windows on demand (archive files no longer exempt); the memory graph's edges carry evidence weights (promotion-marker and mention counts) with wheel zoom, drag pan, arrowheads and weight badges; and the retriever ranks with BM25-lite (IDF + length normalization) instead of raw token overlap.
- **[Experimental] Binary data frames and bounded queue reads** — the bus negotiates binary frames for artifact transfer; settled-task retention and bounded queue reads keep long task histories cheap.
- **`timeouts.native_s`** — wall-clock budget for one native-ability command, replacing the built-in five-minute default only on executors that kept it; an explicit per-command timeout is never stretched by the global knob.
- **Transit-node visibility in management tools** — `card_list`/`card_show` report devices reachable only via relay ("reachable via <peer>, two hops out"), so the orchestrating model no longer concludes a live device "is not in the device network" and refuses work the mesh could route.
- **Live execution narrative in the console** — the SSE trace stream carries the agent-activity set (tool calls, thinking, progress notes, usage, fallback, judge, supervision, result) with oversized payloads clipped, and every listed task ships a `last_event` stamp so a mid-flight task narrates real work on first paint instead of a bare "running". The kanban live line, the orbit pill, and the detail timeline all read from it.
- **Task brief card** — the detail view renders the task spec (target, constraints, scope, success definition) as a readable brief instead of hiding it inside `spec_json`.
- **Console and session UX** — the web pairing flow and node probe on admit, a fleet-page hardening pass, thread-rail pin/batch operations with live sync, pinned threads with bulk delete, and a session fingerprint on the change feed.

### Added — trust zones preview (still experimental)

- **[Experimental] Trust zones** — `network.peers` entries may carry a `trust:` tier (`mesh` default = pre-feature behaviour, `guarded`, `open`), settable per entry in config or live via `panda nodes trust <id> <level>` (or the stable `k:<pubkey>` identity, which follows a node across instance-id changes); `nodes add`/`nodes admit` take `--trust`, `panda pair --trust` pins the tier at join time (modern and legacy `--secret --peer` paths), the REPL mirrors all verbs, and the web console's node card carries a tier selector (`POST /api/nodes/{id}/trust`, `k:` identities included) that also rewrites the matching `network.peers` entries so a config reload cannot resurrect the old pin. `guarded` clamps what delegates toward it may carry (context capped at a pull-pointer, project packs / artifact inputs / consent grants stripped; tasks that would lose their pack or inputs re-route instead) and admits work it originates under `network.trust.accept.guarded` (`auto` | `review` | `refuse`, with an optional zero-tool `policy_llm` classifier that can never relax the deterministic gates). A task parked for review holds the delegator's lease with progress beats (bounded at 24h) so slow human decisions don't expire into a duplicate re-route, and the hold re-arms after a daemon restart. `open` peers sit in the directory; on every node that pins them they can neither receive nor originate push-mode work (trust is a local, subjective assertion — a node that has not pinned them treats them as mesh, so the offer/bid market they exist for is not built). A peer key change demotes a mesh pin back to guarded alongside the existing verification reset.
- **[Experimental] Signed task acceptance** — executors sign `task_accept` with their Ed25519 node key over (task, attempt, signer, timestamp); delegators and relays verify the self-contained proof, dropping malformed, stale (>5 min skew) or key-mismatched frames. Unsigned frames from pre-feature peers are still accepted.
- **[Experimental] Local reputation in routing** — `routing.reputation: true` folds each executor's smoothed success rate out of this node's own `delegation_metrics` into the DCPS score (weight 0.1, Laplace-smoothed; peers with no observations get no bonus). Off by default.

### Fixed

- **A verdict produced during a link outage now converges** — terminal results, cancels and approvals park in durable outboxes and re-deliver on the next hello, and a reconnect-time sweep re-pushes recent terminal verdicts even when no outbox row exists (a frame written into a half-dead socket used to vanish silently, stranding the delegator in `dispatched` until a lease lied about a timeout). A late `done` also reconciles a lease-expired failure — but never revives a human-rejected task.
- **The real daemon always wins its edge** — hellos carry an authority bit set only by the lock-holding daemon, so it reclaims the peer edge from a stray same-identity process; a daemon whose listen port is held by such a stray retries the bind instead of dying, and the stray demotes its mesh duties the moment the daemon takes the node lock.
- **Approvals cannot strand or lie** — an accepted decision mirrors to the sibling copy parked on the peer; a double approval no longer kills the delegator's copy; consent-parked copies converge on the executor's verdict; and a parked approval renders as an honest delivery receipt instead of a model-invented "still waiting for approval".
- **Plans are followed to their verdict** — a started plan is watched until every stage settles or a human gate is reached; approving a parked stage re-enters the plan watch and surfaces the next gate, rather than ending the turn at one task's receipt. Plan stages also resolve tier-2 consent through the caller's verdict gate — `StartPlan` used to skip it entirely, so stages went out with `authorized=false` and restricted-mode executors refused them outright, even under `approval.mode: never`.
- **Stuck agents die visibly** — the silence watchdog now defaults to killing an agent that produces no output for 240 seconds (`timeouts.silence_s`; `-1` disables the kill), and a periodic heartbeat reports "agent still running" so a silent run is never mistaken for a dead one. The entry model also retries once on an empty completion instead of failing the whole turn.
- **Windows output round-trips** — remote stdout is transcoded from the executor's console code page (GB18030/ShiftJIS/EUCKR/Big5), so CJK output no longer arrives as replacement characters; the scheduled daemon task runs through a wrapper script that keeps `daemon.log` rolling; adapters decode subprocess output as UTF-8 explicitly and pin UTF-8 stdio with an MBCS fallback.
- **Delegation no longer deadlocks or double-runs** — the parent/child resource-key deadlock is broken (a parent holding a `project:` queue key that folded while a child queued behind the same key deadlocked permanently — observed live at 7+ minutes; such children are now annotated as outstanding instead of awaited), children an agent spawns mid-run (`task add --parent-id $PANDA_TASK_ID`) are folded from per-round row re-reads, a restricted session can still ask, the executor's plan sweep no longer kills delegated stages, and a zombie hello cannot resurrect an evicted connection.
- **Kernel hardening** — shared-ledger ownership and artifact boundaries are enforced, consent grants sign the final payload, and peer addresses bind before the dial tie-break so a task is never routed onto an unproven link.
- **Honest decline and restart reporting** — a task refused by the pinned or capable node used to surface as a bare "no capability matches"; queue-time declines now fail with the enriched refusal trail ("declined by X (capacity full)") and remote-origin rows relay the real verdict up the chain. An executor restart that recovered a mid-run task to `failed` now records the interruption cause on the recover event, so the delegator sees `interrupted`, not "task is failed". And `task show` renders never-ran failures as `✗ failed`, not `✗ exit 0`.
- **Silent artifact-chain break** — the ask engine's scheduler core had no artifact pool attached, so stage output packing returned empty: stages reported done with no `output_artifact` and successors ran against empty directories. The pool is attached at engine init, and a pool-less pack now fails loudly at the stage that owns it instead of two hops later.
- **Fixed five-minute native timeout** — long-running native commands were killed at 300s with no way to extend. Configurable via `timeouts.native_s` (see Added).
- **Speculative artifact probes logged as errors** — the fetch window's past-end reads were denied and WARN-logged on the serving node; they now answer the empty `EOF` marker the client contract expects, so small-artifact pulls are silent.
- **Home-directory ambient packs** — a project rooted at `$HOME` walked the entire home tree (permission-denied `.Trash`, multi-minute scan) before tripping the size limit on every task. Such packs are refused up front, and source packs now prune credential-shaped directories (`.ssh`, `.aws`, `.gnupg`, `.kube`, …) and files (`.env*`, `.netrc`, `id_*` keys) at any depth — home-shaped dirs (`.config`, `.local`, `AppData`, `Library`) only when the pack root actually is `$HOME` — while unreadable entries land in the manifest's `pack_skipped` instead of sinking the whole pack.
- **Honest agent workspaces** — host-state masking used to swallow every agent change (the default layout puts `openpanda.db` inside the work root, so marking `filepath.Dir(DBPath)` host-owned made the whole snapshot look untouched and correct work parked in review); `config.HostStatePaths()` now enumerates precise state files. Anonymous tasks also ran inside the node work dir — output landing next to the live database, concurrent tasks sharing a filesystem — so plain tasks now execute in private `tasks/<taskID>` dirs, project tasks without inputs run in their project work dir, and orphaned workdirs are reaped only after the owning row leaves the store.
- **Credential withholding on untrusted chain segments** — a task admitted over a guarded/open chain ran the agent subprocess with this node's model key and forwarded adapter credentials in env — one `printenv` away from the wire. `network.trust.accept.guarded.model_creds` (default `withhold` for sub-mesh tiers, `provide` for mesh) suppresses model-env injection, credential forwarding, and the auth-failure injection retry at the single env-build point, with the verdict folded from the stored chain so delegate/resume/push-resume/queue-adoption all converge on it.
- **Unsigned updates refused** — a build without a release key accepted checksum-only updates, but the sums and the archive cross the same channel — nothing on the wire could anchor them. `downloadRelease` now fails closed unless the operator sets `OPENPANDA_UPDATE_UNSIGNED`.
- **Daemon survives a goroutine panic** — every bare goroutine now routes through `guard.Go`/`guard.Call`: a panic in a conn loop, watchdog, or spawned task used to take the whole daemon down with an unformatted stack. Fixes found while sweeping: the cliui spinner bound its stop/done channels lazily (pairing race across Start/Stop); askengine read the listen address where a config reload could swap it; TUI/REPL ask workers now deliver an error outcome on panic instead of hanging the pump; and a bus writeLoop panic closes the conn.
- **Message-board forgery refused** — a member→owner board post authenticates the sending node, not the task id it claims; the owner now also verifies the named sender is on the scope's roster before writing the slot, so a reachable node can no longer post under a stranger's identity.
- **TUI composer duplication** — `mainChatView` sized the frame to exactly the terminal height, so the last row landed on the bottom line and scroll-on-write terminals shifted every repaint up a row — the composer's stale tails piled up down the screen (#44). The frame now paints one row short, and the approval card / asking-footer hit boxes follow the rows the frame actually paints instead of assuming a bottom-anchored layout.
- **Migrations under connection pooling** — migration transactions now pin a dedicated `*sql.Conn`; under the widened pool a bare `BEGIN IMMEDIATE` could scatter DDL and COMMIT across connections (SQLITE_BUSY / "no transaction").
- **Silent content loss paths** — a reply with an empty answer but a non-empty note no longer discards the note; the streaming delta guard now mirrors `ParseOutput`'s first-`{` decision exactly (lead-in cap, illustrative markers, fence handling) instead of a looser approximation, and answer text suppressed mid-stream is restored at flush.
- **Web formatter field mismatches** — `agent_usage` read `tokens`/`cost` while the wire carries `input/output/cache_*_tokens`; token tags now sum the real fields.
- **TUI frame corruption** — titled box edges spliced border runes into ANSI escape sequences; titles now render over an escape-aware edge.
- **Silent agent substitution** — an `agent:X` requirement falling back to a different harness ran invisibly; the result now names the requested and actual agents.
- **Approval-gate download detection** — fetch-to-disk now covers the spellings the `-o` flag scan missed: redirects (`curl url > file`), pipeline sinks (`| tee file`, PowerShell `| Out-File`), process substitution (`bash <(curl …)`), and `iwr`/`Invoke-WebRequest` — all grade Tier 2 like `curl -o`, while `make > build.log`, `2>&1` dups, `grep curl notes.txt`, and non-shell `=>`/`->` stay Tier 1.
- A wire `task_resume` from the delegator could un-park a task held for trust admission review — the gate that exists to check that very delegator. Admission parks now carry their own `admission_review` disposition: local `panda approve` resumes them like any pre-execution park, but wire resumes against them are refused with the held verdict.
- Reconnect re-pushes of review verdicts now carry the typed approval disposition. A `resume_execution` park reaching the delegator used to degrade to the conservative `accept_work` default, after which the executor's real result could never close the mirrored review — the copy stranded.
- A `task_accept` signature check that pinned the signer to the immediate wire sender dropped valid acceptances relayed over a multi-hop chain; the proof is now verified for what it actually binds (task, attempt, signer key, timestamp).
- The optional trust `policy_llm` classifier call is bounded (15s) and fails closed to `review` — a stalled endpoint can no longer freeze a peer's inbound message loop.
- Admission trust now folds the least-trusting tier across the whole delegate chain, so an open peer can no longer launder work through a mesh relay by naming a mesh origin in `chain[0]`.
- `context_fetch` now enforces a `summary` send ceiling on the pull side too — a peer declared unable to hold snapshots can no longer pull them on demand. (`pointer` remains pull-on-demand by design: it is an audited transport tier, not a secrecy bound.)
- `artifact_fetch` enforces the `inputs` ceiling on the pull side with direction awareness: a requester downstream of this node in the task chain is refused under `inputs: false` even when it learned the hash out of band, while an upstream delegator pulling its own task's outputs stays unaffected — that read is an output, not an input.
- A non-mesh origin's `authorized=true` consent grant used to buy the unrestricted local tool face on the executor — the origin user's yes standing in for this node's owner. `network.trust.accept.<tier>.foreign_consent` (`strip` default, `honor` for same-owner nodes on untrusted segments) decides whether a foreign grant survives admission; stripped tasks run restricted and park their irreversibles in the local review queue.
- `trust.NeedsOf` now counts `ContextType: "file"` as needing inputs, matching the store- and submit-side derivations — a file task can no longer pass one gate and trip another.
- Trust resolution folds the configured addr hint even when a row pin exists (least-trusting wins both ways), and reputation aggregates by the peer's proven Ed25519 key instead of its instance id — a restarted node no longer cold-starts its track record.
- **Signed update channel wired end to end** — the fail-closed updater above shipped without its key infrastructure: release CI never received a signing secret, no `checksums.txt.sig` was produced, and the publish list omitted it anyway — so this build refused every release it was offered. `make package` now runs under `OPENPANDA_REQUIRE_RELEASE_KEY` (a missing `OPENPANDA_RELEASE_KEY` aborts instead of warning) and the signature asset is published; `panda update` also selects `lite-` assets for lite builds via a build-flag probe and refuses up front on platforms the release matrix does not ship.

### Changed

- `timeouts.silence_s` semantics: unset or `0` now means the 240-second default kill (previously disabled); `-1` disables the kill while keeping the heartbeat.
- **SQLite write concurrency** — file-backed stores run a 4-connection WAL pool with `_txlock=immediate` (in-memory stores keep one connection); artifact-transfer wire handlers cache positive peer authorizations for a minute instead of re-querying per chunk, and the push waterline persists once a second per transfer instead of per frame.
- **Deduplication cost** — the inbound-frame dedup key is a struct (no string allocation per frame) under its own mutex, off the peer-registry lock.
- **SSE trace stream starts at the current watermark** — connecting no longer replays the full event history; hydration comes from `last_event` and the task payload.
- **Console design pass** — kanban cards lift on hover with an entrance animation, views fade in, quiet bookkeeping rows render as thin lines, changed-file chips filter VCS/dependency noise and collapse past twelve, and the composer, scroll button, and message bubbles are re-balanced.
- **Event-row folding** — a run of "no output" silence heartbeats collapses into one counted line, and tool calls get readable argument summaries (an opaque `{argc:3}` renders as "3 args").
- **Source-pack privacy baseline** — see "Home-directory ambient packs": the privacy filter applies only to source packs; executor-output packs still round-trip the tree verbatim (a `dist/` or `.env` the run produced is the result, not a leak).
- **Workdir snapshots are bounded and resilient** — the pre-task snapshot now batches existence checks and paces staged prunes, reports partial coverage (`files_truncated`), and skips the drift intercept on truncated diffs; markdown renders are cached across TUI frames.

## [0.0.10] - 2026-10-07 — "Apoapsis"

The stable v0.0.10 — codename **Apoapsis**, the far point of the orbit. This cut folds the preview line (LAN auto-discovery with fingerprint-confirmed admission, TOFU key pinning, worktree-carrying delegation, the clarification loop, actuator dispatch, Ed25519-signed audit rows, OS-level sandboxing, UDP/NAT traversal, measured-capacity scheduling, and the Panda Paper console redesign) together with this cycle's additions: sessions are now a tree you can fork at any turn boundary, overflowing history compacts into a model-written running digest instead of being dropped, `panda rpc` opens an NDJSON-over-stdio embedding surface, and `panda auth login` brings subscription OAuth to the entry model. The release also relicenses the project to AGPL-3.0-or-later with dual commercial licensing — installs holding MIT-era consent re-confirm the terms once on first launch.

### Added

- **Session branching** [Experimental]: sessions are now a tree. `panda session fork <id> [--at N]` splits a thread at a turn boundary into a child session that inherits the parent's history prefix and project; in a repository the child's worktree branches off the parent's branch, so it sees the code state the parent produced. `panda session tree [id]` renders the family tree, `/fork` does the same inside the REPL/TUI and re-attaches to the child, and the panel exposes `POST /api/sessions/{id}/fork`.
- **Auto-compaction** [Experimental]: overflowing conversation history is folded into a model-written running digest instead of being dropped. Bare-mode convo files keep the digest as a leading synthetic turn (self-maintaining across compactions); sessions store it in the new `Summary` field and replay it as a context note. `panda session show` reports compacted threads. When no model is reachable, the replay degrades to the previous bounded window — the stored thread stays whole and compacts on the next reachable turn.
- **`panda rpc`** [Experimental]: an NDJSON-over-stdio protocol for embedding OpenPanda — `status`, `ask` (with delta/status/reasoning events), `session.list/get/new/fork`, `convo.get`. `scripts/panda_rpc.py` is a minimal stdlib-only reference client.
- **Subscription OAuth** [Experimental]: `panda auth login anthropic` signs a Claude Pro/Max subscription in via PKCE (browser consent → paste code), stores the token set under the CLI state dir (0600), and refreshes it transparently. `model.auth: anthropic` makes the entry model authenticate with that Bearer token (adds the `oauth-2025-04-20` beta flag); `auth status`/`logout` inspect and remove credentials. Other subscription providers slot in once the entry client speaks their wire protocol.
- Exit notice after the full-screen TUI closes: with a bound session it prints the saved session id and the `/resume` hint; with a bare chat it notes the conversation was saved to the convo file and reloads on the next launch — the alternate screen no longer makes the transcript look lost.
- `make tui-pty-exit-test`: a second real-pty contract (alongside `tui-pty-test`) asserting failed-turn persistence, the exit notice, and clean terminal restoration; wired into `make gate-all`.

### Fixed

- Bare-mode failed turns persist again: the TUI's done handler cleared `pendingPrompt` before `recordErrorTurn` could read it, so a failed ask left no trace in the convo file or `/history` — the attempt is now recorded (user prompt + marked error) exactly like the classic loop.
- Entry-layer model error text is localized: the ClassifyError guidance (unreachable, timeout, 401/403, 404, 400 with provider detail, 429, 5xx, missing key, generic), the DSML tool-call reject/ignore/unparsable messages, the output-validation error, the max-tokens truncation marker, and the primary→fallback switch note now follow the conversation locale instead of always rendering in Chinese.
- TUI session tests sandbox `XDG_STATE_HOME` and the CLI config path, so running the test suite no longer writes into the developer's real conversation store.
- Session JSON files and the OAuth token store write atomically — a crash mid-write can no longer leave a truncated file that silently drops a thread from the session list or forces a re-login.

### Changed

- **Relicensed to AGPL-3.0-or-later with dual commercial licensing**: the project moved from MIT to the GNU Affero GPL — derivative works, and modified versions offered to users over a network, must publish their source under the AGPL; a commercial license covers closed-source use (see `COMMERCIAL.md`). Versions published before the change remain under MIT. Consent recorded under MIT does not cover the new terms, so installs holding a stale `ui.terms_accepted` re-show the license step once — the TUI renders the card (now localized to all five languages) and quits on decline, the web console reopens its terms step — then record `ui.terms_version` so future terms changes can re-prompt the same way.

## [0.0.10-preview] - 2026-10-06

The v0.0.10 preview — codename **Apoapsis**, the far point of the orbit: the line that reaches outward from the core to the LAN around the node and the hardware at its edge. Nodes discover each other on the LAN with fingerprint-confirmed admission and can pin each other's keys by hand; delegated file tasks carry their worktree to the executor and bring the result back; a blocked agent can ask the user a question instead of guessing; and tasks can drive physical actuators — servo, mic, camera, notify, serial MCU — on the node that owns the hardware. Underneath, the trust floor hardened: `task_events` and `audit_log` rows are Ed25519-signed and verified against this node's key, remote agent runs without a consent grant clamp to read-only tools, plaintext `ws://` dials are refused off encrypted underlays, and the updater can demand an out-of-band release signature. Steady-state cost dropped with it: idle WAL writes are change-gated, the queue and reminder scanner relax when empty, capability matching allocates nothing, and the artifact plane pools its chunk buffers. Beyond the headline items, the entry model can now search and read the live web, `sandbox.mode` puts every spawned subprocess under an OS deny-default profile, the adapter wire grows a v2 with sessions and typed transcripts, scheduling reads measured capacity (with `nodes drain` maintenance and `--nodes` fan-out), and the web console takes a light-first redesign.

### Added

- **[Experimental] LAN auto-discovery with fingerprint-confirmed admission** — nodes now broadcast a small unauthenticated UDP beacon (`panda-beacon/1` on `network.discovery_addr`, default `:7837`, `"off"` disables) carrying only id/address/version/pubkey — never credentials. `panda nodes` shows LAN-discovered rows under a "not paired" section with the advertised fingerprint; `panda nodes admit <id>` turns one into a configured peer (the `/nodes admit` REPL twin live-dials it), and the pending table expires stale entries and caps at 64 rows so a hostile LAN degrades to noise, not growth. Admission is unchanged: the shared secret and the signed Ed25519 hello are still what let a node in — a beacon is a hint, not a key.
- **[Experimental] Node fingerprint + TOFU verification** — `panda nodes` renders each row's Ed25519 fingerprint, green-✓ when human-compared; `panda nodes verify <id>` records the check (`employee_cache.key_verified`, migration v31). A key that changes under a still-verified row clears the stamp and logs loudly — reinstall, rotation and impersonation are indistinguishable at this layer and none may inherit trust; the self row carries its own fingerprint by construction.
- **[Experimental] Worktree travels with delegated file tasks** — a `context_type=file` task whose target is a repository checkout now packs its tree (skipping `.git`, `node_modules`, vendor and cache dirs, capped at 256 MiB) as a `__worktree__` artifact input; the executor unpacks into a private per-task directory and runs there, and the produced tree is packed back, fetched, and extracted into the origin checkout (`EvProjectSync` trace + `output_artifact` on the result). Delegated file edits now reach the machine that asked instead of dying on the remote host.
- **[Experimental] Clarification loop (§4.3)** — an agent blocked on a decision only the user can make ends its turn with a `PANDA_QUESTION:` line; the task parks in review with the question propagated to the delegator (`task_result.question`), and `panda approve <id> -m "answer"` resumes it on the executor with the reply folded into the re-run's intent. The hint rides every agent prompt in all five locales.
- **[Experimental] Structured result contract** — `task_result.files_changed` reports the workdir-relative paths the run actually touched (capped at 200), computed from before/after snapshots rather than agent prose; the supervise judge receives the same list as evidence, `panda task <id>` renders the changed paths, and a parked clarification preserves its partial footprint.
- **[Experimental] Project-residence routing** — capability summaries now advertise which projects each node hosts (`employee_cache.projects`, gossiped in heartbeats); `scheduler.RouteP`/`RouteAtP` score residence so a project-bound task prefers the node that already holds the tree.
- **[Experimental] Actuator dispatch (§7.1/§7.2, Jarvis track)** — a task can now drive a physical action on the node that owns it. Cards declare `actuators` with a `hardware:*` id, a driver `command`, and an argv template carrying `{intent}`/`{action}`/`{param:<name>}` placeholders; the entry model emits `spec.action_spec` (target actuator, action verb, scalar parameters), it rides `spec_json` across delegation, and the executor substitutes it into real argv — never a shell line — before running the driver natively. `task_submit` accepts an `action_spec` argument, `panda task add --action-spec '<json>'` (and the `/task add` REPL twin) dispatch actuators without the model, and `ValidateTaskSpec` vets the spec at the boundary (required fields, scalar params, 32-parameter cap).
- **[Experimental] Reference actuator drivers** — `drivers/` ships five portable drivers packaged in every release archive: `panda-servo` (gpiozero PWM servo, 0-180°), `panda-mic` (arecord WAV capture, bounded at 300 s), `panda-camera` (fswebcam/imagesnap/ffmpeg snapshot fallback), `panda-notify` (notify-send/osascript/powershell toast), and `panda-mcu` (pure-stdlib POSIX termios serial/UART — Arduino, ESP32, RP2040, AT modems; `--send`/`--send-hex` with `--expect`/`--expect-regex` read windows, no pyserial). - **[Experimental] Pi adapter** — `adapters/pi.py` plus a registry entry for the multi-provider Pi CLI: credential detection across the vendor env vars and `~/.pi/agent/{auth,models}.json`, a read-only restricted face, and `.pi/mcp.json` as its project-level MCP discovery point — `Capabilities.MCPProjectFile` lets each CLI declare its own convention and the passthrough materializes that file instead of assuming `.mcp.json`. A polyglot `ModelEnv` (`APIType: ""`) means the agent speaks the configured model's own protocol, carried down as `OPENPANDA_MODEL_API_TYPE`.
- **[Experimental] Built-in generic executor** — a card declaring `adapter: "generic"` (no `.py`) gets the same argv-template expansion implemented in-process, so a node with no Python runtime (bare Windows/macOS, minimal containers, embedded boards) still serves agent-tier work; only that adapter is exempt from the interpreter check, `{env:NAME}` placeholders resolve operator-declared variables forwarded through the sandbox, and the template's first token probes via `splitArgv` so a quoted path survives.
- **Signed audit rows** — `audit_log` entries now carry the node's Ed25519 signature over their own chain hash (migration v37): a DB writer can no longer rewrite an entry and re-hash the chain end to end. `panda audit verify`, `/audit` and `GET /api/audit` all verify against this node's key.
- **[Experimental] Out-of-band update verification** — `OPENPANDA_UPDATE_PUBKEY` (hex/base64 Ed25519) makes a release's `checksums.txt.sig` mandatory — a detached signature over the checksums, the trust anchor the channel's own hashes cannot provide — and `OPENPANDA_UPDATE_REPO` repoints the update channel at a self-hosted `owner/repo`. - **[Experimental] web_search and web_fetch tools for the entry model** — two Tier-1 tools give the model a live window past its training cutoff: `web_search` queries a configured provider — SearXNG (self-hosted, keyless `base_url`), Brave, Tavily or Bocha (`api_key`); `auto` picks whatever is configured, `off` drops both tools — and returns titled links with published-date hints, while `web_fetch` reads a model-chosen URL through the SSRF guard (https only, public-unicast IPs, policy held across redirects). An unconfigured search returns setup guidance the model relays, never a dead end.
- **Configurable model retry budget** — `model.max_retries` replaces the hardcoded transport retry budget (absent/0 keeps the default of 5, a negative disables retries entirely); per-step backoff is capped at 30 s so a deep budget waits instead of busy-looping, and the knob surfaces in the web settings model form, the panel model endpoints, `/model add --retry` and `config.example.local.yaml`.
- **[Experimental] Live capacity metrics, drain mode and named-node fan-out** — heartbeats now carry measured mem-free/disk-free/GPU-util samples (`-1` = unmeasured, clamped against corrupt values) and advertise queue depth alongside in-flight count; scoring discounts efficiency by measured memory headroom and routing hard-drops nodes whose work disk is nearly full — measured data only, so unprobed peers are never excluded. `panda task add --nodes` fans one task out to named nodes (one pinned copy each) and aggregates the per-node outcome, and `panda nodes drain [--off]` writes a shared settings flag the running daemon picks up: heartbeats say "draining", inbound delegates are declined, in-flight work runs to completion.
- **Stable-identity outbox custody** — outbox custody used to key on the instance id, so a restarted peer re-helloed under a new id and its parked results, cancels, bundles and artifact pushes were orphaned until TTL; custody now keys on the authenticated Ed25519 identity (`k:<pub>`, bound by the signed hello) with `task_id` as the operation id, all four outbox tables persist under the stable key, flush claims the union of stable key and every recorded instance id, and bundle `DestEID` carries the stable key resolved to the current instance through the directory.
- **Repository plumbing is protected on the worktree return leg** — a hash-correct, traversal-free archive could still carry a top-level `.git` whose hooks and config (which can embed credentials) land straight on the user's checkout; `ExtractExcept` adds a first-element skip set so adoption never materializes peer-supplied `.git` or `.panda-shadow` content — nested matches stay, since a vendored checkout's own `.git` is legitimate output — and skipped entries are counted in the manifest and logged.
- **[Experimental] OS-level subprocess sandbox (`sandbox.mode`)** — `security.Sandbox` gains real confinement beyond env filtering: `sandbox.mode: standard|strict` wraps every spawned subprocess — native commands and agent adapters alike — in the platform's deny-default mechanism (sandbox-exec/seatbelt on macOS, bubblewrap on Linux, honest no-op elsewhere with a startup warning). `standard` leaves the workdir and whitelisted runtime dirs writable with everything else EPERM, while `deny_write_paths` (db dir, memory, config, card, artifact pool, `.panda-shadow`) stay protected even under a whitelisted parent; `strict` adds read-denial of OS credential locations. `panda doctor` reports whether a backend actually confined the node.
- **File-shaped writable mounts and a shared protected-path set** — bare credential files at `$HOME` root (e.g. `.claude.json`) now declare via `WritableFiles` and bind as files on Linux / fold into the writable set on macOS, instead of a guessed inode type that mounted the wrong thing; the daemon's hard-coded deny list is now `commander.ProtectedPaths`, shared with the embedded engine so ask/repl/web/voice sessions get the same contract, `Options.ConfigPath` lets the engine's own config file join the write-deny set, and the desktop keyring joins `SystemSecretPaths`.
- **Web console refresh** — the warm-paper light theme is now the single source of truth in the token layer (dark stays available via `[data-theme='dark']` and the `prefers-color-scheme` fallback); fleet, memory and skills promote to top-level grouped routes with legacy `#/settings?tab=*` links redirecting, the chat composer and new-task form expose node picking, and a memory graph view joins the console. The onboarding terms step expands to ten sections — self-hosted/no-SLA clarification, third-party model and peer-node terms, AI-output and professional-advice disclaimers, execution safety, warranty and liability — in all five locales.

### Changed

- **Acceptance criteria reach the executor** — the spec's `success_definition` and `constraints` are folded into the run intent (`taskSpecEnvelope`), so the agent prompt states what "done" means and the supervise judge verifies against the same criteria instead of grading prose alone.
- **Per-task execution controls survive delegation** — `tools_policy` and `max_turns` moved onto `entry.TaskSpecDetail` (the struct that persists into `spec_json` and crosses the wire); the executor applies them via `commander.WithToolsPolicy`/`WithMaxTurns`, and adapters parse `max_turns` from the request envelope.
- **Raw user prompt preserved through distillation** — the original request is appended to the stored intent at submit and travels with the delegation, so peers and retries see the user's words alongside the entry model's distilled intent.
- **Idle write traffic is change-gated** — the heartbeat only rewrites the self row when the advertised capacity actually changed (with a 30 s freshness floor, safely under the 45 s liveness check and 90 s stale-peer sweep), the 5 s neighbor refresh and the per-beat residence publish now read-compare-write (`ledger.UpdateAdjacencyIfChanged`), and the panel's node fingerprint quantizes `last_seen` to the minute so a heartbeat no longer pushes a "nodes changed" event to every connected console. An idle node's WAL write rate drops roughly an order of magnitude.
- **Queue poll relaxes when the queue stays empty** — after ~30 s without a ready row the scheduler's fallback poll steps from 400 ms to 2 s (`queueIdleAfter`/`queueIdlePoll`); a live queue and in-process `Wake()` keeps the fast cadence, so only wake-less cross-process pickup pays the slower tail.
- **Reminder scanner idles on an empty board** — with nothing pending the scan interval relaxes to 60 s instead of 15 s (rows added by another process surface within that bound), while `Store.Add`/`AddEvery`/`Delete` wake every scanner in the same process so an in-process reminder still fires within a second of its due time.
- **Offline-peer reconnect logging is throttled** — a dead peer used to emit a `peer dial failed`/`punch offer failed` WARN every redial (~30 s steady-state) into LaunchAgent's unrotated `/tmp` logs; the first failure and each ~20th are logged with a `consecutive` count, and a recovery line reports how long the outage ran. The panel/web engine's `MaintainPeers` redial loop follows the same policy.
- **Change-gated writes are single-statement** — `HeartbeatIfChanged`/`UpdateAdjacencyIfChanged` now let SQLite's `WHERE … IS NOT …` gate decide whether the row moves, so a steady beat or neighbor tick is one no-op UPDATE round-trip instead of a SELECT plus a conditional write — and the compare is atomic with the write.
- **Message dedup sweeps are amortized** — `claimMsgID` used to walk the whole `msgSeen` map on every inbound frame (O(capacity) per message on a hot mesh); expiry now runs at most every 30 s, which only ever makes dedup more conservative, never weaker.
- **Poll projections stop dragging payloads** — the queue's `ListReady` poll now selects the six columns the scheduler reads (`ListReadySummaries`) instead of every queued task's spec/intent/result JSON, and the panel's per-second SSE fingerprints hash dedicated stamp rows (`TaskStamps`, `ledger.NodeStamps`) rather than full task and node rows.
- **Agent prompts open with a checkable execution contract** — the closing rider is now verifiable bullets in all five locales (read the project's own sources before editing, prove the success definition with the project's own build/test convention before claiming done, stay inside the declared scope, report the commands run and their outcomes, name any criterion that could not be verified), an `[execution context]` frame states the task, project and workspace-as-cwd up front, and `spec.scope` folds into the run intent alongside the success criteria.
- **Steady-state CPU and allocation drops** — capability matching tokenizes on the fly with zero allocations (2709 ns/40 allocs → 1619 ns/0 allocs per candidate), the artifact data plane borrows 1 MiB chunk buffers from a `sync.Pool` and no longer writes `sent_through` per chunk (the receiver's ack decides retransmission), the panel's session finalizer probes `task_events` once instead of re-reading every task's timeline, and `RouteAtP` skips the seen-map on the common empty chain. `make bench` pins the numbers (routing match/decision, control + 1 MiB frame codec at ~86/184 MB/s, dispatch dedup).

### Fixed

- **Peer addresses validate the real wire grammar at every write path** — `nodes add`, REPL `/nodes add`, `pair --peer`, the panel's `POST /api/nodes/add`, and `config` load all shared only a bare `net.SplitHostPort` check, so `punch:<id>` entries slipped through on a technicality, non-numeric ports (`peer:smtp`) were stored and only failed silently at dial time, and the panel's error message still demanded host:port. `config.ValidatePeerAddr` now owns the grammar (punch:<node-id>, ws(s):// URL, host:port with a numeric 1–65535 port) and every entry point calls it.
- **Panel add-node surfaces the cleartext gate** — `POST /api/nodes/add` used to swallow the dial error into a generic "not reachable" line; the response now carries `cleartext_hint` so the console can point at `network.allow_cleartext` (or wss:// / punch:) the way the CLI does.

- **MCP stdio servers no longer die with the request context** — spawn and handshake used to inherit the caller's 30 s request ctx, so settings changes killed the server process; the child now outlives the request (`TestServerSurvivesSpawnContextCancel`).
- **Ask engine runs on model-less nodes** — `askengine.New` no longer fails without a configured model; Ask paths report `ErrNoModel` lazily, so edge nodes can execute delegated work without an API key.
- **Work-dir derivation handles relative roots** — `stageWorkDir`/`attachedWorkDir`/`projectWorkDir` normalize the root with `filepath.Abs` before the traversal proof; `NewCore`'s `"."` default no longer fails the escape check (regressed delegated tasks parked for pushed inputs).
- **Test fixture paths resolve beside their YAMLs** — `testdata/*.yaml` storage paths are anchored to the config file's directory as documented, and a stray `testdata/testdata/` tree is ignored/removed.
- **WebSocket ping period is clamped** to a legal fraction of the pong wait, preventing starvation on misconfigured keepalives.
- **Hardware-only nodes can execute** — `NewCore`/`ReloadCard` built the commander router only when the card had native, agent or manual abilities, so a node whose entire capability set was actuators (the Jarvis edge case) declined every task routed to it as "no capability matches"; actuators now count toward router creation.
- **`{action}` placeholder fails closed** — a driver template naming `{action}` used to substitute an empty string when the task carried no action_spec (or an action-less one), handing the driver an empty verb; it now rejects like a missing `{param:<name>}` — the disagreement is reported, not executed.
- **`action_spec` cannot be stranded on a non-actuator plan** — a task carrying a spec that targets `hardware:x` but whose `requires` resolved a plain ability used to drop the spec and run the intent as a shell command; the run gate now fails the dispatch, and submission boundaries lead `requires` with the spec's `target_actuator` so `MatchActuator`'s first-match ordering resolves the intended actuator (`ledger.RequiresForActionSpec`, applied in `toTaskInput`, `task add` and `/task add`).
- **REPL `/task add --action-spec` accepts real JSON** — `splitArgs` only grouped double quotes, so a JSON payload's own quotes toggled the tokenizer mid-token and were stripped; single quotes group now, and `--agents` combined with `--action-spec` is refused instead of silently dropping the spec.
- **Discovery bind validates its port** — a non-numeric `network.discovery_addr` port passed `SplitHostPort` shape-checking then bound an ephemeral socket that announced to port 0; `net.ResolveUDPAddr` now vets it at startup, and the `:7837` default lives in one `DiscoveryAddrOrDefault()` helper shared by daemon and embedded engine.
- **Event-chain verification is anchored to this node's key** — `VerifyTaskEventChain`/`VerifyChain` used to verify each row against whatever `sig_pub` it carried, so a writer who rewrote the chain could re-sign it under their own keypair and still pass; signatures must now come from this node's key, and once a signed row exists every later row must be signed, so stripping the tail's signatures is caught. Relayed consent grants whose origin key is unknown still adopt (refusing would stall every relayed tier-2 task) but now log loudly.
- **Dedup eviction follows expiry order** — `msgSeen` overflow dropped an arbitrary quarter of the table in map order, which could evict a fresh id and re-admit its replay while stale ids survived; oldest-first eviction means a replay only slips through after its own dedup window would have closed anyway.
- **Permission-tier classifier bypasses closed across shells, remotes and stores** — `TierFromCommand` only ever saw the binary's name, so a destructive payload could ride inside a benign one; the embedded command line is now extracted and classified — `find -exec`/`-execdir`/`-ok`/`-okdir` payloads, `ssh` remote commands and `-o ProxyCommand`, `parallel`'s opaque command string, `tmux send-keys`/`screen -X stuff` keystroke injection into live terminals — and the verb/object gaps close too: `systemctl`'s power-state family (reboot/suspend/hibernate/isolate/firmware-setup), `pmset` sleeps and scheduled power-downs, `launchctl bootout`/`reboot`, and container destruction.
- **Self-update actually installs** — three real defects behind the report: an ephemeral panel token was regenerated on exec restart, stranding every open console at the token gate (the token now rides `OPENPANDA_PANEL_TOKEN` through the restart and stays out of task subprocesses via the env allow-list); a service-managed `panda daemon` kept its old image after the binary on disk changed (`applyRelease` now asks the service manager to restart); and macOS archives are repacked with `COPYFILE_DISABLE=1` plus an xattr strip. `panda update --force` on a degraded check no longer prints a phantom `downloading v<current>` — `--force` waives the newer-than test, not the need for a known release — the updater gets a bounded `http.Client` (30 s metadata, 30 min asset window), and the panel explains the post-apply state.
- **TUI dead commands and shared-state races** — `/model`, `/sessions`, `/projects` with arguments were swallowed by the slash-panel interception (bare still opens the panel, args now reach exec); `/tasks watch` consumed its `watch` token so the live board never started, and its 2 s repaints flooded the transcript on exit (only the latest frame commits now); `watchQueueTo` hardcoded `i18n.Detect()` and ignored `/lang`. Multi-chunk exec output panicked the whole TUI — a value-receiver copy of a non-zero `strings.Builder` detonated on chunk two, killing any streaming slash/shell command (`/agents`, …) — the redundant model mirror is deleted and the view renders the mutex-accumulated buffer.
- **Mesh transport stalls and blackholes** — replies looked up `connFor` alone, so a peer reachable only over a punched datagram route never received decline/result/ack responses; `sendTo` is now the shared path (conn first, bound UDP endpoint second, outbox on failure). UDP routes carry `udpHeard` and expire after silence — a dead endpoint kept "working" because UDP writes report success at write time, so sends were acked, outbox rows deleted, and the peer never re-punched; keepalives refresh only on an exact endpoint match. The inbound deadline refreshes per dispatched frame once the conn is bound (a rejected hello no longer earns the 60 s window, a slow handler can't starve a healthy link), heartbeat/card broadcasts fan out concurrently instead of one wedged peer delaying the rest by `writeWait` each, the WS upgrader gets a `HandshakeTimeout`, and UDP keepalives surface upstream only after the AEAD open succeeds.
- **Adapter wire decoding and registry scoping** — `AgentResult.ExitCode` carried no json tag, so the wire's `exit_code` never unmarshaled and adapter timeouts (124), missing binaries (127) and malformed requests (2) all surfaced as exit 0, corrupting retry classification and failure reporting; every `AgentResult` field now carries its wire name explicitly. Registry resolution keyed on the adapter script alone conflated every `generic.py` card entry — a custom CLI inherited zcode's binaries, credentials and endpoint; `agents.Lookup(name, adapter)` now requires both to match.
- **Input-boundary caps and flags** — mutating panel `/api/*` requests had no body limit (a 16 MiB `MaxBytesReader` now wraps POST/PUT/PATCH/DELETE); non-streaming provider responses read unbounded (64 MiB cap); path-like adapter names (`../x.py`) are rejected at card-write instead of only at spawn; `session_mode` reports `session_dead` on the result envelope so the one-shot fallback no longer races the async `cmd.Wait` marker; and the panel sends a strict same-origin CSP (`script-src 'self'`, no objects/frames) for non-loopback exposure.
- **Actuator exclusion, delegate parsing, lease waits and state hashing** — two drivers on one GPIO pin is a fault, not parallelism: queue resource keys now merge every `hardware:*` requirement plus the `action_spec` target actuator, and `run()` takes a per-actuator mutex at the execution point so delegated accepts and inline submits both serialize. `PANDA_DELEGATE` parsing tolerates pretty-printed payloads and markdown fences, collects every request in a turn, and dispatches children in parallel with a budget; remote waits poll the persisted lease so a renewing executor's beats keep it alive past the old fixed deadline; and a work tree over the hash-walk cap fingerprints via git's own index (`HEAD` + porcelain + capped diff streams) instead of skipping the oscillation check.

### Breaking changes

- **Plaintext `ws://` dials are refused unless the underlay encrypts** (5d06d37) — the hello handshake proves mesh membership but authenticates nothing after it, so a network MITM on a cleartext link could read the task plane and inject a forged `task_delegate`. `cleartextOK` now gates outbound dials: `ws://` to a bare `host:port` passes only for loopback and Tailscale (CGNAT 100.64.0.0/10, the fd7a:115e:a214::/48 ULA, `*.ts.net` MagicDNS), which ride an encrypted-or-local underlay; `wss://` and `punch:` peers pass through. **A peer configured as a plain LAN `192.168.x.x:7836` will fail to dial after upgrade** — switch it to `wss://`, tunnel it over Tailscale, or set `network.allow_cleartext: true` on the dialing node to restore the previous behavior on a trusted LAN.

## [0.0.9] - 2026-09-25 — "Periapsis"

The v0.0.9 stable release — codename **Periapsis**. For a single-machine setup this is a comfort release: approvals can be remembered instead of re-answered, the CLI explains itself better (a status that says whether *this* node is up, an empty queue that suggests the next step, a first-run pointer, release notes printed by the updater), the web console attributes every answer to the agent and model that produced it and pins the node's liveness and version into the sidebar, and the TUI survives the ordinary command sequences that used to corrupt it. For fleets it completes the line the beta opened: an authenticated datagram plane with NAT traversal, encrypted DTN payloads, scheduled contact windows, cryptographic node identity with signed consent, direct stage-to-stage artifact handoff, and a lite build for constrained nodes.

### Added

- **Remembered approvals, on every surface** — a tier-2 prompt no longer has to be re-answered every time: a decision can be remembered for the session or for the project (answering once stays the default). The engine keeps session-scope decisions, a project row carries its own policy (mode override + default scope + remembered decision, migration V26), and a remembered *deny* short-circuits with a refusal instead of re-prompting. The scope is picked where the question is asked: the approval card's once|session|project row (1/2/3 keys, clickable cells), `/approval` and `panda project approval` for the effective policy, `panda ask`/`session ask`, and a scope picker in the web console's queue and session views — which also surface parked tier-2 tasks.
- **Task-activity heatmap** — a year of per-day task counts renders as a grid on the welcome banner, via `/heatmap` in the REPL, and as `panda heatmap [--weeks N]` for scripts; NO_COLOR/dumb terminals get a glyph ramp, non-unicode consoles ASCII cells.
- **`panda agents test <name>`** — one-shot diagnostics for an installed agent CLI: credential source, resolved model, endpoint reachability with status detail and latency; `--json` and `--config` flags, non-zero exit when the agent is unusable.
- **Execution attribution** — a subdued `agent (model) · node` line runs through ask output (human, JSON and stream), REPL task blocks, TUI turns and the panel approve path (restored from persisted ResultJSON), so every answer names the executor that produced it. The web console carries the same attribution in the session and detail views, and the system version card shows `v0.0.9 Periapsis` at full weight.
- **Node chip in the web sidebar** — the console's sidebar footer now shows this machine's name, a running/offline dot and the running version, one click away from the System view; `GET /api/self` additionally reports the release codename.
- **Decentralized DAG runtime** — Ed25519 node identity end to end: a persistent keypair minted on first start, signed hellos (`PubKey`/`EdSig`, with an HMAC fallback so mixed-version meshes keep working; a peer key is recorded only when its signature verifies — migration V28), and signed tier-2 consent: the origin node signs `Authorized` with AuthSig/AuthPub/AuthTs, the executor verifies it against the recorded key and drops forged grants (`consent:forged` in the audit log); the grant persists on the task row (migration V29) and re-emits verbatim through queue forwards and decline re-routes. Stage outputs hand off directly: an artifact fetch carries an orchestrator-signed grant bound to plan/consumer/producer/hash, so the producer serves a consumer it has no task row for; successors adopt output immediately while a hub replica streams in the background, and input fetch falls back to the orchestrator when the producer is unreachable. Dynamic sub-DAGs: `panda task add --parent-id/--preferred`, the `panda_subtask_spawn`/`panda_subtask_await` MCP tools, and `PANDA_TASK_ID` injected into agent environments.
- **DTN contact plan** — `network.contacts` declares scheduled transmission windows per peer (a [start, end) window plus optional `period` and `rate_bps`), gossiped in heartbeats and capability summaries and stored in `employee_cache.contacts_json` (migration V27). `scheduler.ContactNextHop` runs earliest-arrival Dijkstra over the union of live edges and advertised windows, so an offline node with a published plan is a valid custody intermediate — the case live-topology routing cannot express; a window that cannot fit the transfer and a path arriving after the bundle's lifetime are both pruned. With no plan anywhere the search falls back to live topology unchanged, and an empty advertised plan clears the cached one (an absent field from an old node still leaves it alone).
- **UDP datagram plane (farsky track)** — `internal/bus/udp.go` adds a second transport: AES-256-GCM-sealed envelopes and HMAC-signed punch frames on a shared UDP socket, keyed from the mesh secret under a domain separator and bounded to one 1400-byte datagram. `network.udp_listen` defaults to the `listen_addr` port on the wildcard interface (every datagram is authenticated, so the any-interface bind exposes nothing a LAN could not already see); `"off"` disables the plane. `sendTo` still prefers the WebSocket conn and falls back to a confirmed UDP route when none exists.
- **NAT hole punching coordinated through the mesh** — `network.peers` accepts `punch:<node-id>` entries for peers that cannot be dialed. A `punch_offer`/`punch_ready` pair travels over the live conn or is relayed along the link-state graph (TTL-bounded, re-enveloped at each hop with the origin preserved in the payload's `Src`), then both sides spray signed punch frames at the exchanged candidates until an ack confirms the pinhole. The bound endpoint becomes a UDP route refreshed by 25 s keepalives and re-punched when lost.
- **Reflexive-address discovery without an external dependency** — the same UDP socket answers RFC 5389 binding requests, so any mesh member with a public address is the fleet's STUN server (`internal/bus/stun.go`, zero dependencies); `network.stun_servers` adds external servers only for deployments that run or trust them. Hello replies also carry `you` — the IP the listener observed — so a NAT-bound node learns its public address for free.
- **Encrypted DTN bundle payloads (v2)** — `bus.Bundle.Seal` encrypts the payload with AES-256-GCM under a bundle-domain key derived from the mesh secret, binding the signed header as associated data; `Open` unseals v2 and verifies v1 cleartext bundles, so mixed-version meshes keep working. Relay custody stores only the sealed blob — intermediate hops forward ciphertext they cannot read.
- **Lite build for constrained nodes** — `go build -tags lite` / `make build-lite-linux-{amd64,arm64,armv7}` drops the embedded web console (the panel endpoint serves a small notice instead) and the Bubble Tea TUI while keeping the daemon, mesh, DTN, queue, ask and the classic line REPL — a slimmer binary without the frontend dependency chain for Raspberry Pi and CLI-only devices. `install.sh --lite` selects the `panda-<ver>-lite-<os>-<arch>` archive and accepts 32-bit ARM; the deploy scripts default to it on SBC-class targets.
- **Release codename** — `internal/version.Codename` names this line "Periapsis"; `panda version`, `panda --version`, `/api/version` and the system view display it.
- **Queue-management tool family for the ask engine** — `taskq_approve` (Tier-2, so the model cannot widen a gate it is about to walk through), `taskq_reject`, `taskq_clear` (history/review/all scopes) and batch `task_ids` on `taskq_cancel`; `taskq_list`/`taskq_show` annotate each task's approval disposition, and `taskq_priority`/`taskq_move` refuse to silently reorder tasks that are not queued.
- **Multi-harness tasks from `task add`** — `panda task add --agents claude_code,codex` fans one task out to several agent harnesses: `parallel` (the default) releases every stage at once, `--mode serial` chains each stage on the previous one's output. Each stage pins its harness with an `agent:<name>` requirement and routes to a node that actually has it — the existing plan/DAG machinery, reachable without writing a YAML file.
- **LAN sharing for the web console** — `panda web --lan` binds every interface and prints a shareable `http://<lan-ip>:<port>?token=…` line per detected LAN address, so a second device on the network opens the console directly. A non-loopback `network.panel_addr` without a configured token now gets an ephemeral one — `/api/*` still never runs open — instead of refusing to start; the same rule applies in `panda web`, the REPL's `/web` and the standalone sidecar.

### Changed

- **Hello advertises the datagram plane** — `HelloPayload` carries `udp_port` and the reply carries `you` (the peer-observed source IP): the listener learns every connected peer's punch hint, and each node learns its own public address without configuration.
- **Bundle wire format v3: relative lifetime** — the wire bundle's absolute `DeadlineUnix` becomes a BPv7-style (created, lifetime) pair: every custody holder re-anchors expiry to its own clock instead of trusting the origin's, which is what makes parked bundles behave correctly across unsynchronized nodes. v1/v2 bundles still verify — the decoded raw slot is preserved for signature/AAD and their absolute deadline is normalized to a lifetime for custody logic only.
- **`panda init` seeds the mesh secret and knows the model catalogue** — a generated config used to ship `shared_secret` empty (the WS listener then refuses every inbound peer until someone runs `pair`/`nodes add`); init now mints it up front. The interactive model picker enumerates the provider registry — the same catalogue `panda model add` and the web settings page offer — instead of a frozen five-entry list of retired defaults, honours NoAuth providers (Ollama skips the key prompt), and writes provider/context-window/max-tokens alongside the endpoint. Under `--defaults` the documented `OPENPANDA_MODEL_*` env vars are adopted into the file.
- **`panda doctor` checks the network planes** — an empty `shared_secret` now fails the self-check (it silently disabled inbound peering while the daemon looked healthy), and the datagram plane reports its bind or the deliberate `udp_listen=off`.
- **Agents are probed before dispatch** — a minimal authenticated POST against the resolved endpoint decides whether an agent CLI is dispatchable: a definitive-credential 401/402/403/429 rejects, 5xx/transport failure marks unreachable, an anonymous 4xx counts as alive. `AgentDispatchable` gates matching, execution and capability advertising, so a configured-but-broken agent no longer wins a plan and fails at exec.
- **Updates and installs refuse a binary older than the data directory** — `storage.LatestVersion` exposes the binary's migration ceiling and `panda version --json` reports it (plus the data directory's live `db_schema` when reachable); the updater probes the staged binary before swapping, `panda install` refuses an older-schema copy, and `install.sh` probes the downloaded archive the same way — a downgrade that would die at startup with "schema version newer than binary" is refused up front (`--force`/`OPENPANDA_FORCE=1` for deliberate downgrades).
- **Everyday CLI polish** — `panda status` names the node directory correctly (it claimed "no tasks in the store") and says whether this node is running or has ever registered; `panda queue`'s empty board suggests the next step; the no-model message points at `panda model add` or web settings instead of a yaml field; the classic REPL prints a first-run pointer when no config file exists; `panda update apply`/`upgrade` print the release notes of the version they just installed; `init`'s closing line names `doctor`/`web`/`panda` as the next step.
- **Unified version identity** — `v0.0.9 Periapsis` prints the same way from `--version`/`version`, the REPL welcome banner, the TUI splash and the lite startup line — unquoted, at the same weight — and the web sidebar's node chip carries it.
- **Cross-process queue pickup is ~5× faster** — a task enqueued by another process (`panda task add`, `panda plan run`, MCP submissions) was discovered only on the queue scheduler's 2 s fallback poll, since the wake channel cannot reach across processes. The poll is now 400 ms, so a submitted task starts markedly sooner while in-process wakes still fire instantly.

### Fixed

- **All tool calls in one model response now execute in that round** — the engine ran only the first `tool_use` per turn and noted the rest, so a model issuing several queue operations burned the whole tool budget re-sending them (the reported "clean up the task queue" failure). Native responses execute every call and replay as one assistant `tool_use[]` plus one user `tool_result[]` turn per the Anthropic protocol; DSML invokes execute in order and replay as prose.
- **DSML parser accepts the formats DeepSeek actually emits** — single- and double-pipe `<｜DSML｜>` variants, loosely quoted invoke names and JSON argument bodies no longer leak protocol markup into the reply.
- **Approval states now expose their real semantics** — `approval_disposition` (accept_work / resume_execution / needs_changed_input) is surfaced in `taskq_list`/`taskq_show`, the task API payload and the queue/detail views, which disable Approve where the input must change; tasks that already produced output are no longer indistinguishable from tasks awaiting authorization.
- **`Approve` on a resume_execution task re-queues adoptably** — the resume branch marks the row `scheduled=1` so `ListReady` can claim it; a direct Approve no longer produces a `queued` row no scheduler will ever pick up.
- **Tool-loop exhaustion degrades to a digest** — a burned-out tool budget returns a summary of the calls that did execute instead of a bare "max tool rounds" error.
- **TUI command execution no longer corrupts or crashes the front end** — ordinary sequences (`/clear`, a few turns, a mistyped command) reached the real terminal around Bubble Tea or left unpaired history. `/clear` repaints through `tea.ClearScreen`; the exec pump feeds commands an empty stdin and recovers handler panics into an error block; captured output is ANSI-stripped on commit and on live render; state-mutating commands (`/new`, `/resume`, `/project`, `/authorize`, list mutations) run on the Update goroutine via shared helpers instead of duplicating state writes; a failed turn persists as a paired user+error turn so the next ask is not a 400; `/history` falls back to the persisted conversation and `/new` clears both memory and the file.
- **Outboxes flush over punched datagram routes** — `sendableTo` treated a peer reachable only via a UDP pinhole as unflushable, so parked bundles for punch-only peers waited forever for a WebSocket conn; they now drain over the UDP route.
- **DTN relay accounting survives restarts** — the per-bundle relay hop budget lives in `dtn_relay_log` (migration V25) instead of memory, and `parkBundle`'s upsert updates `via`, so a redelivered bundle's no-echo rule follows its latest inbound path.
- **Skill URL imports can no longer probe the internal network** — `ImportURL` (the path behind `panda skill install <url>`, `panda_skill_install`, `skill_install` and `/api/skills/import`) now requires https for any non-loopback host and validates every resolved IP at connect time: loopback, RFC1918/ULA, link-local (cloud metadata endpoints), multicast and unspecified addresses are never dialed, and redirects must satisfy the same classification, so an agent- or index-supplied URL cannot turn the node into an SSRF trampoline (hardening: `internal/skills/fetchguard.go`).
- **STUN binding answers are rate-limited per source IP** — 10 answers/source/second with a bounded tracking map caps the UDP socket's ~2× reflection factor without hurting real clients (RFC 5389 retransmits on the seconds scale).

### Breaking changes

- **`?token=` query-parameter auth on `/api/*` removed** — the panel API only accepts `Authorization: Bearer <token>` now, because a credential in a URL lands in browser history and proxy access logs. The bundled console already sends the header everywhere including the SSE stream (fetch-based, not EventSource), and the `/?token=` auto-login URL `panda web` opens is unaffected — it is the static page, not the API. External scripts and third-party clients must switch to the header.
- **No built-in model vendor default** — a config with an empty `model:` section used to mean "silently use a bundled vendor endpoint": it materialized into generated configs, showed on the banner as if it were the user's own choice, and routed an unconfigured node's prompts to that vendor. `entry.NewClient` now returns `ErrNoModel`, and `panda ask`/`voice`/REPL/TUI gate on a configured model and point at `panda init`/`panda model add`; `config.example.yaml` ships the section commented out with instructions, and credential injection (`injection.model`) requires a real endpoint. If a deployment relied on the implicit default, set `model.provider`/`model.base_url` or run `panda init`.

## [0.0.9-beta] - 2026-09-23

The v0.0.9 beta completes the hybrid transport/DTN architecture: mesh routing is now latency-weighted, DTN bundles actually move over live links and park for offline ones, delegation token budgets are enforced with real accounting, preempted work survives via shadow copies, and hardware actuators gained an execution path. It additionally gives delegated agents a managed path back into the node's own tooling, lands the full model-configuration surface, and rebuilds the model-management TUI around a full-width registry plus a single-screen form editor.

### Added

- **Latency-weighted mesh routing** — neighbours gossip per-link RTT samples in heartbeats (`HeartbeatPayload.Links`, persisted as `employee_cache.links_json`), and `graphFirstHop` now runs Dijkstra over measured link cost instead of hop-count BFS; unmeasured edges cost `unknownLinkCost`, so a proven multi-hop path can beat an expensive direct link (§4.1).
- **DTN bundles on the wire** — parked delegated tasks are wrapped in signed CBOR bundles (HMAC-SHA256, EID, TTL) stored in `task_outbox.payload_blob` and shipped byte-for-byte in a `dtn_bundle` envelope; receivers verify integrity/deadline, deliver to the destination EID, or relay/park for the next hop (§8.3, §9.1).
- **Periodic outbox sweeps** — `sweepOutboxes` retries result, cancel, and task outboxes on a timer instead of only on peer hello, with a per-peer flush claim so concurrent flushes cannot interleave; expired bundles drop cleanly and mark their task expired.
- **Mesh-wide token budgets** — migration V20 adds `tasks.token_budget` (0 = unbounded/legacy, positive = remaining quota, -1 = exhaustion sentinel); `SpendTokens` decrements atomically, agent and supervisor/judge usage is billed after each model call, and an exhausted task converges to review instead of spending a dead quota (§6.1).
- **Shadow work copies for yields** — a task asked to yield now snapshots its declared scope into `.panda-shadow` before cancellation, and the resuming task merges non-conflicting files back (conflicts keep the winner's bytes and are reported in a system note), replacing lose-everything cancellation (§5.2).
- **Actuator execution path** — capability-card actuators can declare `command`/`args`/`tier`; the commander routes matching tasks through the native executor with `ActionSpec` placeholder substitution, and `panda card invoke <actuator-id> [action] [name=value ...]` tests them locally with `--dry-run`/`--authorize` (§7).
- **Agent self-management surface (`panda mcp`)** — the node now ships its own MCP stdio server exposing OpenPanda's management face as first-class agent tools: `panda_status`, `panda_nodes`, `panda_queue`, `panda_task_status`, `panda_task_submit` (shells out to `panda task add`, capped at 8 submissions per session), `panda_skill_list`, `panda_skill_install` (hub name or http(s) URL), `panda_skill_import` (raw SKILL.md), and `panda_card`. Under `routing.tools_policy: extended` the commander materializes an `openpanda` entry in the work-dir `.mcp.json` next to any configured `mcp.command` passthrough, so MCP-capable agent CLIs discover it automatically; shell-capable agents get a prompt hint pointing at the `panda` binary on PATH. `routing.panda_tools: false` opts the self-management surface out while keeping the extended tool face.
- **Chunked, resumable artifact push (`artifact_push`)** — fat-bundle payloads above the inline cap are now streamed in 1 MiB frames instead of being left to the pull path: migration V21's `artifact_push_outbox` persists sender custody across restarts, receivers stage chunks on disk under `<pool>/.staging/` and report a contiguous waterline, and a reconnect resumes from the acknowledged offset rather than restarting. A dtn task whose inputs have not landed parks in `waiting_context` instead of failing, and a relay that forwarded the task pushes the artifact onward once it lands (chained custody, §8.3).
- **Unbounded artifact transfers** — the 512 MiB `artifact.MaxBytes` cap is lifted: pools are unlimited by default and the filesystem's free space is the bound, so a declared `total` the volume could never hold is refused before the first byte lands (`ErrNoSpace`). `storage.artifact_max_bytes` / `OPENPANDA_ARTIFACT_MAX_BYTES` reimpose a fixed cap on nodes where artifacts share a small disk.
- **Multi-volume artifact pools** — `storage.artifact_extra_paths` / `OPENPANDA_ARTIFACT_EXTRA_PATHS` adds volumes to the pool: writes pick the volume with the largest usable space (`free − storage.artifact_min_free_bytes`, default 256 MiB headroom; explicit 0 disables the watermark), reads search every root, and staged chunks live on the chosen volume so the commit rename stays atomic. Extra paths add capacity — they do not replicate artifacts, and the receiving node alone decides where inbound data lands.
- **DTN multi-hop relay** — `relayBundle` no longer waits for a direct link to the destination: `scheduler.DTNNextHop` runs a destination-aware weighted path over the gossiped topology (intermediate hops must be online; the destination may be offline), forwards the signed bundle verbatim to a closer connected next hop, never echoes it back to the incoming peer (`task_outbox.via`, migration V22), and recomputes the hop on every outbox flush. A per-bundle relay log bounds forwarding at `dtnRelayMaxHops` and expires with the bundle deadline.
- **Agent session checkpointing** — migration V23 adds `tasks.agent_session_id`/`agent_session_node`: the adapter's conversation handle is persisted after every round (`context.WithoutCancel`, so a yield-cancel cannot lose it), reported to the delegator on the result wire (`agent_session_id`), and offered back only to the node that minted it via `resume_session_id` on re-dispatch. An interrupted task resumes its agent's own conversation instead of cold-starting; adapters without session support leave the field empty and keep the shadow-copy fallback (§5.2).

### Changed

- **Heartbeat gossip now carries adjacency + link metrics** — `Core.broadcastHeartbeat` publishes live neighbours and measured RTTs; `handleHeartbeat` folds them into the directory so routing decisions reflect real link cost, refreshed as RTT samples arrive.

### Fixed

- **Windows classic consoles now render colour instead of raw escape sequences** — the palette emitted SGR codes on any Windows TTY, but the legacy console host (cmd.exe, Windows PowerShell 5.1, double-clicked binaries) does not interpret them until the process enables VT processing. `internal/cliui` now turns `ENABLE_VIRTUAL_TERMINAL_PROCESSING` on for stdout at first use and gates colour on it, so `panda ask` / `doctor` / the classic REPL print clean plain text where VT cannot be enabled instead of `[31m` garbage.
- **Windows classic REPL got a real line editor** — the fallback was a plain scanner line read: no cursor movement, no history, no Tab completion, and Ctrl-C during a running ask hit the console control handler and killed the whole REPL. A new console-API editor adds in-line editing, persisted history, slash-command and argument-position completion, real terminal-width reporting, and Esc/Ctrl-C cancellation of the running ask (double-tap exits, as on unix).
- **`panda uninstall` now sweeps default-location config and the capability card** — a config at the per-user default (e.g. `%APPDATA%\openpanda\config.yaml`) was judged "custom location — kept", leaving the API key and shared secret on disk, and the capability card was never part of the plan. Both are now owned when they live in the standard per-user or system config directories.
- **Windows browser open no longer breaks on URL special characters** — `cmd /c start <url>` parses `&`, `^` and parentheses as shell syntax; `panda web` now opens the token-carrying URL through `rundll32 url.dll,FileProtocolHandler`.
- **Windows install/uninstall hardening** — the installer's self-check now fails on a non-zero exit instead of reporting success for a broken binary; PATH comparisons expand `%VAR%` entries so re-installs do not append duplicates; cancellation via `taskkill` no longer flashes a console window; hardware probes prefer `pwsh` and fall back to `powershell`; `SystemConfigDir` falls back to `C:\ProgramData` when `ProgramData` is unset; REPL history now lives in `%LOCALAPPDATA%\openpanda` instead of a unix-style `~/.local/state`.

## [0.0.6] - 2026-08-27

The cross-device compute release takes shape: a request that needs different machines for different steps is now a first-class plan whose stages run where the hardware is, and both surfaces — the CLI and the web console — gained the presentation layer they lacked: live feedback while an ask converges, real Markdown in the browser, and the input editor a daily driver needs.

### Added

- **Plan plane — pipelines whose stages run on different machines** — a stage is an ordinary task (CAS state machine, lease, retry, supervision, review parking), so a pipeline inherits everything a task already has; a finished stage's work dir is packed and chunked over the bus to the machine running the next stage. Two entry paths: `panda plan example > train.yaml`, `panda plan run train.yaml [--dry-run]`, `panda plan show <id>` — or one sentence via `panda ask`, the model emitting a plan precisely when a request must change machines. No stage carries tier-2 consent: an irreversible stage parks in review for a person (c10b8af).

- **Routing by declared hardware** — `resource_profile` is a hard filter (`ledger.Fits`) and the scorer ranks free capacity + queue depth + tier, discounted by heartbeat freshness, so two tasks published at once land on two machines; the entry prompt carries each node's real hardware so the model fills the routing filter sighted, not blind (c10b8af).

- **`panda voice`** — wake word → ASR → the same entry pipeline → TTS: the desk-pet entry for a device with no keyboard (c10b8af).

- **`panda card show | rescan | edit | set`** — one command family over the capability card: print it (and which file it came from), re-scan hardware + installed agent CLIs (`rescan` prints a diff, `--write` applies it and keeps a `.bak`, hand-written decisions preserved), open it in `$EDITOR`, or set fields headlessly. `panda detect`, the card rescan, and the panel now share one detection layer (`internal/hwinfo`) (fdb56b8).

- **A presentation layer for the CLI** — `internal/cliui`: one palette resolved once, and a live status line (spinner, verb, elapsed, token count — both were already recorded, just never shown) that degrades to a static line on pipes. The line editor learns bracketed paste and multi-line input (a pasted multi-line prompt is one ask, and history recalls it as one), Ctrl-R incremental history search, and argument-position completion for the ids nobody retypes. Unknown commands get a did-you-mean; `/help` prints inline grouped by intent; new commands cover what a session reaches for after the first ask works (`/cost`, `/model`, `/status`, `/doctor`, `/export`, `/clear`) plus `@file` attach and `!cmd` passthrough so the prompt is never left (c538ab6).

- **The web chat surface catches up** — a hand-written Markdown renderer (zero `innerHTML`, so no sanitizer dependency; 29 node tests) replaces literal `**bold**` and \`\`\` fences in replies; the composer's primary action while streaming is a stop button (the SSE reader takes an AbortSignal); autoscroll stops yanking the view once the reader scrolls up; Cmd+K palette over the same navigation vocabulary as the sidebar; mobile thread drawer replacing `display:none` (c538ab6).

- **A status page** — `docs/status.md` records what works, what is only built, and what is missing, with the flagship pipeline's verification state (76c5b69).

- **Stale node rows can be removed** — `panda nodes remove <id>` and a Remove button on offline node cards drop a directory row that no live peer backs (a renamed machine, a changed identity, a decommissioned node). The local node's own row and online nodes are refused — both re-register themselves, so removing them would be a no-op wearing a success message.

- **Release-notes tooling** — the release workflow publishes the version's CHANGELOG section plus per-platform install commands as the release body and fails the build when the section is missing; the 0.0.5 release page was rewritten to that standard with an English-only body and language switcher, and every CHANGELOG now leads with one-command install (4e12779, c25a3cb, 98e10df, 600ffb3).

### Fixed

- **Queued tasks and plan stages actually route now** — the queue path kept a local "if I can do it, I do it" short-circuit that the router itself had removed, and it was the path every panel task and plan stage took: the hardware filter never ran where the flagship pipeline actually runs (a GPU stage stayed on the Pi whenever the Pi held the ability; a burst of tasks all stayed on the node that accepted them). The decision belongs to the scheduler; an empty ability list means "no constraint", not "nobody matches"; plan stages get a resource key each, so independent stages fan out instead of queueing behind each other (a5b792e).

- **A finished run's result fits a frame** — `task_result` output is clamped to the bus frame size, so a completed run's result reaches the submitter instead of overflowing the frame and vanishing (c1310da).

- **Memory fences cannot be closed from inside** — the `<memory_data>` fence wrapped the body without touching the body's own tags, so an entry containing the literal closing tag ended the fence early and had its remainder read as instructions — and memory is writable by the model's own tools, the panel, and promoted dream candidates. Tags inside are neutralized; the text stays visible for audit (3f18994).

- **A node no longer describes another machine's hardware** — every one of these was a hardcoded value standing where a probe belonged: the default node name was "macbook", so every node that never ran `panda init` announced itself under the author's laptop name; macOS/Windows had no machine-id source, so renaming the machine looked like a different node; the Windows sandbox stripped PATHEXT/SYSTEMROOT/TEMP — which is why a Windows compute node could not launch an adapter at all; `python3` is not a portable interpreter name (probed now, `py -3` first on Windows); a timed-out task hung forever on Windows because the harness could not kill a process tree (`taskkill /T` now); a card advertising a native ability whose command is absent won the route and died with 127 (pruned at load); a GPU whose size no probe could read wrote 0 and was excluded from exactly the work it exists for (unknown is a third state now); `deploy-pi.sh` defaulted to one developer's LAN address (required now) (fdb56b8).

- **i18n regressions closed** — hardcoded Chinese in the voice path, ask/repl plan output, conversation summaries, uninstall errors, and one hint in `panda help` moved into `internal/i18n` across all five locales — ja/es/de users were seeing Chinese in those surfaces (c538ab6).

- **The REPL opens in under a second, not after the peer dial timeout** — interactive startup dialed every configured peer serially before the banner and then waited for them to settle: an offline peer burned the dialer's full 10s timeout as dead air before the first prompt. The REPL, `panda session`, and `panda voice` now dial peers in the background (an offline peer is routine in a long-lived session, and its failure no longer prints WARN lines mid-keystroke), and one-shot `panda ask` dials peers concurrently so an unreachable peer stops gating a reachable one.

## [0.0.5] - 2026-08-25

The three-device lab patch: the first real macOS + OrangePi + Windows cluster — installed from the public installers, linked over LAN, driven end-to-end — exposed that queued tasks never left their origin node, tier-2 consent died at the delegation boundary, and a locked-out agent CLI could attract routing and hang for minutes. Five commits, all verified on that hardware.

### Added

- **`panda task add --requires`** — declare the abilities a task needs (`--requires gpio:read`, comma-separated); a queued task without a local match is routed to a device that has them, the same root-scheduler policy `panda ask` has always used (c4e1bc7).

### Fixed

- **Queued tasks now route cross-device** — tasks from `panda task add` and the web console were claimed and executed by the origin node only: a task requiring an ability only another device had failed outright (`route: no capability matches` for `pi.uptime` filed on a Mac). On claim the scheduler now consults the root scheduler; with no local match the claim is re-targeted to a capable peer (declined-by loop protection, lease so a dead executor is detected), and the peer's result completes the origin's row. Verified in all three directions on the lab: Mac→OrangePi, OrangePi→Mac, Windows→OrangePi (c4e1bc7).

- **Tier-2 authorization travels with delegation** — `--authorize` consent was local to the submitting node, so an agent task delegated to a peer bounced at the executor's defense layer even though the user had approved it. Consent now propagates on the authenticated bus and the executor honors it: a credential-less OrangePi filing an authorized coding task at the Mac's claude completes instead of dying in review (c4e1bc7).

- **Locked-out agent CLIs no longer attract routing** — a capability card is static, but an installed CLI can be unusable: `claude.exe` on the Windows box with no login state and no model key advertised `agent:*` to the fleet, routing sent it a coding task, and it hung for minutes before failing on a network error. The local fallback chain and the capability summary advertised over hello now gate on viability — CLI on PATH *and* a reachable model (own credentials or injection); the Windows summary now advertises only `win.sysinfo` (2db530f).

- **`panda web`** **no longer dies on a taken port** — a second `/web` (or a leftover process) errored with `bind: address already in use` and printed a token to copy by hand. The console now falls forward to a nearby port and says so; the browser opens already authenticated (the token is never printed), and `/web` while it runs re-opens the browser logged in. `--no-browser` still prints a token-carrying URL for manual use (c4e1bc7).

- **Peer hello reports the real version** — all three hello paths advertised a hardcoded `0.1.0-dev`, so `panda nodes` showed wrong versions across a mixed-version fleet; they now report `version.Version` (all three lab devices show 0.0.5) (2db530f).

- **The capability card next to the resolved config wins over** **`./capabilities.yaml`** — starting a daemon from a directory that happens to contain a capabilities.yaml (a repo checkout, another node's card) silently loaded the wrong card; the init-written card next to the config file now takes precedence, `--card` still overrides (2db530f).

- **Windows data directory no longer collides with the install prefix** — the default state dir `%LOCALAPPDATA%\openpanda` and the install prefix `%LOCALAPPDATA%\OpenPanda` are the same directory on case-insensitive NTFS: the SQLite store, memory, and projects lived inside the install prefix and an uninstall swept them away. The data dir is now `%LOCALAPPDATA%\openpanda-data`; Windows nodes coming from 0.0.4 start with a fresh store (fc50721).

- **Installers survive a rate-limited GitHub API and a broken WinPS 5.1 HTTP stack** — `api.github.com` allows 60 unauthenticated requests per IP per hour; when exhausted, both installers now resolve the latest version through the `/releases/latest` 302 redirect instead. `install.ps1` forces TLS 1.2 up front, prefers the bundled `curl.exe` (Windows 10 1803+) with `Invoke-WebRequest` fallback, and adds timeouts so a broken WinINET proxy fails fast instead of hanging. Both behaviors were hit during the real three-device install (109b567).

- **Homebrew tap push authenticated** — the release workflow's tap-update step failed with `could not read Username` when the job token lacked the grant; the push URL now embeds the token (6868a63).

### Fixed

- **Homebrew / any-cwd startup failure (SQLITE\_CANTOPEN 14)** — default storage
  paths were `./data/openpanda.db` and friends, so `panda` failed to open the DB
  whenever you launched it from any shell directory other than the project root
  (common with Homebrew installs). The fix is multi-layered:

  1. `config.Default()` now anchors DB/memory/projects/skills/work paths to
     `UserDataDir()` — platform-standard per-user state (`~/Library/Application
     Support/openpanda` on macOS, `${XDG_DATA_HOME:-$HOME/.local/share}/openpanda`
     on Linux, `%LOCALAPPDATA%\openpanda` on Windows).
  2. `config.Load()` runs `resolveRelativePaths()` against the YAML's own directory
     so legacy configs written by pre-v0.0.4 `panda init` keep reading next to the
     YAML file, never next to the shell cwd.
  3. `storage.Open()` MkdirAll's the DB's parent directory even for exotic
     manually-specified paths.
  4. `panelStore()` (used by REPL, `panda web`, panel commands, queue, task, …)
     now creates the full storage directory set just like `runDaemon` already did.
     Smoke-tested: `panda queue` from `/` with a fresh HOME auto-creates the user data
     dir, initializes `openpanda.db`, and prints the empty queue.

- **Missing-key misdiagnosis on the Anthropic path** — a non-streaming call with no
  API key sent the empty-key request anyway and surfaced the provider's 401 as
  "invalid key" instead of "not configured". All call paths now return the
  actionable `panda init` / web-settings hint, the REPL banner marks an
  unkeyed model inline, and the panel reports configuration gaps as 503 (same
  family as "engine not configured") rather than a server-fault 500.

- **Tier-2 authorization UX** — a tier-2 refusal now carries an actionable hint
  (`--authorize` or a `tier: 1` card declaration) and skips the retry budget
  straight to review: retrying cannot produce consent. Registry-driven credential
  probing covers Claude Code's new `~/.claude/config.json` + `settings.json`
  locations. Scope parsing extracts path tokens only, so natural-language
  descriptions like “工作目录下的 haiku.txt” no longer trip drift warnings on
  legitimate file operations.

- **Installer / uninstaller** — `install.sh` resumes partial downloads (`curl -C -`),
  persists PATH with the same marked block `panda install` writes, and its generated
  LaunchAgent/systemd services rely on the daemon's config auto-discovery instead of
  hardcoded `--config`/`--card` paths. `panda uninstall` sweeps the distribution
  prefix (bin/, adapters/, example configs) while refusing Homebrew Cellars (keg
  stays whole, `brew uninstall openpanda` hint) and source checkouts.

- **Any-cwd adapter resolution** — delegation from a temp working directory failed
  with "can't open file …/adapters/claude\_code.py"; the resolver now walks up from
  the cwd to locate `adapters/` and falls back to the absolute adapter path.

- **Ask-engine device visibility** — an ask engine built against a fresh database
  self-registers its node under the daemon's stable runtime ID, so the entry model
  no longer sees an empty device list on first use.

### Changed

- `panda nodes` output gained a `Kind` column (physical | vm) so distributed setups
  can tell the host-backed nodes apart from provisioned VM identities at a glance.

- **Shared adapter harness** — the seven agent adapters now share one harness
  library (`adapters/_harness.py`) for the `{ok, result, exit_code}` framing,
  argument parsing, and timeout handling, cutting the per-adapter boilerplate.

- **One-question init** — `panda init` asks a single question (configure a model
  now?) with hardware detection filling in name, resource class, kind, and a VM
  identity when the host probes as a guest; `--defaults` / `--non-interactive`
  drop even that prompt. The example capability cards are rewritten to the real
  `ledger.Card` schema with agent tier semantics.

- **Default model moves to** **`deepseek-v4-flash`** — the `deepseek-chat`/`reasoner`
  aliases were retired by the provider on 2026-07-24; the pro model is
  deliberately never a default (cost control). Card discovery also looks next to
  the resolved config file, matching the daemon's discovery order.

- README: added identity singleton rule section, kind/identity reference rows in the
  node config table, and a `panda nodes` command mention to surface the new
  visibility surface.

## [0.0.3] - 2026-08-23

### Added

- **Multi-agent adapter registry** — `internal/agents` is the single source of truth for the agent CLIs PANDA delegates to (adapter script, probe binary, install command, docs URL). `panda detect`, `panda agents`, the web settings API, and the commander's availability probe all read from it, so adding an agent is a one-entry change.

- **Four new agent adapters** — Grok Build, DeepSeek Harness (`dsh`), OpenClaw, and Hermes join Codex, Claude Code, and OpenCode: each a small headless Python bridge that runs the CLI and returns `{ok, result, exit_code}`.

- **`panda agents`** — `list` (default) probes every agent on PATH with a best-effort version; `test <name>` runs a connectivity check; `install|update <name>` prints the install command + docs link. When nothing is installed, the output lists every missing agent's install command and download URL.

- **Web settings agent roster** — the settings page's agent list now shows, for each missing agent, its install command and a download link (`/api/agents` returns `install_hint` + `install_url`).

- **Superior task review (`上级完成度判定`)** — after an agent runs, the entry model judges the result against the task's success criteria (`entry.Supervise`, outputs `done`/`continue`). A `continue` verdict re-delegates the follow-up instruction (what remains + next step) to the agent chain, looping until the reviewer accepts the work or a capped round budget (default 5) runs out.

- **Terminal routing by risk** — a completed reversible task lands in **done** (已完成); an accepted irreversible (Tier-2) task — pushes, deletes, irreversible state changes — parks in **review** (待审批) with its result for human sign-off; a task the reviewer keeps rejecting parks in **review** with a `needs_followup` marker. The review events replay in the web task detail.

- **One-line installer** — `scripts/install.sh` (POSIX) and `scripts/install.ps1` (PowerShell) download the matching release archive, verify its SHA-256, unpack the binary plus its agent adapters into a per-user prefix, and link `panda` onto `PATH`, with an optional auto-start service (`panda daemon` at login). A Homebrew tap (`brew tap Xustalis/openpanda && brew install openpanda`) covers macOS.

- **Release packaging** — `scripts/package.sh` (and `make package`) cross-compile every supported platform into `dist/panda-<version>-<os>-<arch>.tar.gz` / `.zip` plus a `checksums.txt`, ready for GitHub Releases.

- **Self-update** — `panda web` and the REPL `/web` check the release channel for a newer CLI while running; the web console downloads and verifies the update and, once the task queue is idle, applies it in one click (atomic binary swap, adapter refresh, restart). Discarding a downloaded update leaves no residue; on Windows the swap's `.old` sidecar is swept on the next start.

### Fixed

- **Multi-line** **`--version`** **banner** (e.g. Hermes) no longer pollutes the one-line agent table — version output is truncated to its first line in both the CLI and the web settings API.
