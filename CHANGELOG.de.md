## Installation mit einem Befehl

**macOS / Linux**

```sh
curl -fsSL https://raw.githubusercontent.com/Xustalis/OpenPanda/main/scripts/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/Xustalis/OpenPanda/main/scripts/install.ps1 | iex
```

**macOS (Homebrew)**

```sh
brew install Xustalis/openpanda/openpanda
```

Nach der Installation führst du `panda init` aus, um den Knoten einzurichten, oder tippst einfach `panda`, um in die REPL zu kommen. Eine ältere Installation wird mit demselben Befehl an Ort und Stelle aktualisiert — Benutzerdaten bleiben erhalten.

## Über das Projekt

OpenPanda (**Open** **P**ersonal **A**daptive **N**ode-based **D**istributed **A**ssistant) ist ein persönliches Task-Orchestrierungs-Kernel: Ein `panda`-Binary läuft auf jedem deiner Geräte, die Knoten finden sich über einen authentifizierten WebSocket-Bus, ein Entry-Modell verwandelt jede Anfrage in eine direkte Antwort oder eine ausführbare Task-Spezifikation, und der Scheduler leitet jede Aufgabe an das am besten geeignete Gerät und den passenden Agenten. Die CLI ist die Hauptschnittstelle des Kernels — ein nacktes `panda` öffnet die interaktive REPL — und die Web-Konsole ist eine dünne Hülle über demselben Store und derselben Engine.

## Versionsregeln

- Versionen folgen `MAJOR.MINOR.PATCH`. `0.0.x` war die Vorschau-Linie: Ein Patch-Release durfte Funktionen hinzufügen, Fehler beheben und — ausnahmsweise — das Protokoll brechen, und jedes Release sagte das auch. Ab `0.1.0` ist ein Release „release-grade“, und das ist ein Versprechen über Stabilität, nicht über Funktionsumfang: Ein `0.1.x`-Patch darf Fähigkeiten ergänzen und Fehler beheben, bricht aber weder Konfiguration noch gespeicherte Daten noch das Protokoll; was diese drei bricht, landet in einem Minor (`0.2.0`); und ein unvermeidbarer Bruch bekommt weiterhin ein Deprecation-Fenster und einen Eintrag unter **Breaking Changes**, statt unangekündigt zu kommen.
- Ein Release wird durch das Tag `vX.Y.Z` geschnitten; jeder Commit seit dem vorherigen Tag gehört zum Abschnitt der neuen Version. `[Unreleased]` sammelt die Arbeit seit dem letzten Tag.
- Jede Version wird in vier Kategorien dokumentiert: **Hinzugefügt** (neue Funktionen), **Behoben** (Fehlerkorrekturen), **Verbessert** (Verfeinerungen), **Breaking Changes** (erfordert Handeln beim Upgrade).
- Jeder Eintrag benennt die Änderung und ihre sichtbare Wirkung in ein bis drei Zeilen; der einführende Commit wird zitiert, wo das der Archäologie hilft.
- Einträge können eine **[Experimental]**-Markierung tragen: die Funktion funktioniert, aber Schnittstelle, Wire-Format oder Defaults entwickeln sich noch und können in einem späteren Release ohne Breaking-Change-Fenster geändert werden — baue keine harte Abhängigkeit darauf.
- Dieses Changelog ist kuratiert: einige interne Refaktorierungen und Adapter sind hier nicht gelistet.
- Die englische Datei ist maßgeblich. Die Übersetzungen zh-CN / ja / es / de spiegeln sie und können um ein Release kurz verzögert sein.

## [0.1.1] - 2026-10-27 — "Constellation"

**Der Patch auf der reifen Linie** — Codename **Constellation**: die Flotte bleibt ein Himmel, die Nähte sind enger. Der Entry-Client spricht OpenAI Responses und Google Gemini nativ, Kader und Knoten-Pin eines Threads erreichen das Terminal neben der Konsole, das Dispatch-Budget folgt dem Team, das du wirklich gewählt hast, schreibende Zugriffe über Prozessgrenzen hinweg sind hinter einer Dateisperre atomar, und eine Aufgabe kann sich ein eigenes Arbeitsverzeichnis anheften. Ein Projekt kann aus einer authentifizierten Anfrage nicht mehr ein Betrachter der ganzen Festplatte machen. Konfiguration und gespeicherte Daten bleiben unverändert — keine Schema-Migration, kein umbenannter Schlüssel — und der Draht bekommt keinen neuen Frame. Die einzige Formatänderung ist die paarweise Versiegelung der UDP-Datagramme, die ein 0.1.0-Knoten nicht öffnen kann: aktualisiere ein Mesh gemeinsam (siehe **Inkompatible Änderungen**).

### Hinzugefügt

- **Modellpräferenzen pro Agent** —— `routing.agent_models.opencode` (oder ein beliebiger Agentenname) ist eine geordnete Liste von Modell-Ids, die das CLI dieses Agenten bevorzugen soll; `panda config routing set agent_models opencode opencode-go/kimi-k3,opencode-go/deepseek-v4.1-flash` schreibt sie. Der Adapter nimmt den ersten Eintrag, den seine Installation bedient und authentifizieren kann; ein Go-Abonnent kann damit Abo-Modelle benennen, ohne die automatische Auswahl kostenpflichtiger Modelle generell zu aktivieren. Einträge, die nicht bedient werden, keine Go-Anmeldung haben oder keine Tools aufrufen können, werden im Fortschrittsstrom erklärt, und der nächste wird versucht.
- **OpenCode Zen und OpenCode Go sind getrennte eingebaute Modellanbieter** —— `panda model add opencode` registriert den nutzungsbasierten/kostenlosen Zen-Katalog unter `https://opencode.ai/zen/v1`; `panda model add opencode-go` registriert den Katalog des Go/Go-Plus-Abos unter `https://opencode.ai/zen/go/v1`. Beide Zeilen führen die aktuellen Kontext-/Ausgabegrenzen und Preise pro Modell, kennzeichnen die kostenlose Stufe ausdrücklich (damit sie nie zum Bezahltarif abgerechnet wird) und senden den von Go verlangten Header `x-opencode-session`. Die alte Einzelzeile und ihre `/inference`-Endpunkte entfallen; eine gespeicherte Konfiguration wird auf den aktuellen Endpunkt umgeschrieben.
- `OPENPANDA_UPDATE_BASE` lenkt den Download des Selbst-Updates auf einen Spiegel der Release-Assets um — der Ausweg für Netze, die `api.github.com` erreichen, `release-assets.githubusercontent.com` aber nicht. `OPENPANDA_RELEASE_BASE`, der Name, den die Installer bereits auswerten, wird als Alias akzeptiert, damit eine Variable beide steuert.
- **Die Zustimmungskarte zeigt die Bedingungen selbst, nicht ihre Zusammenfassung** —— Assistent und Einstellungsdialog zeigten zehn zusammengefasste Klauseln: eine zweite Kopie des Rechtstexts, die von der Datei abweichen konnte, die sie zusammenfasste. Beide rendern jetzt `TERMS.md` selbst — alle siebzehn Abschnitte, in der Sprache der Konsole — mit demselben Markdown-Renderer wie das Transkript. Der Text wird nicht mehr in die Konsole kopiert: Jede Übersetzung wird beim Bauen aus der Datei des Repositories eingebunden, es gibt also nur eine Stelle zu ändern.
- **Das Team, das du wählst, ist das Dispatch-Budget** —— das Subagenten-Limit pro Runde war ein festes `3`, also verteilte ein Gespräch mit dem Team claude_code, codex, deepseek_harness und opencode drei Aufgaben und verwarf die vierte, bevor sie je übergeben wurde: keine Karte, kein Fehler, nichts auf dem Beleg. Das Limit leitet sich jetzt aus der Liste ab (eine Aufgabe pro gewähltem Agenten), `task_budget` erlaubt dem Modell, für Arbeit, die niemand aufgezählt hat, eine breitere Fächerung zu erklären (Obergrenze 8), und das Team des Threads steht im Entry-Prompt, sodass das Modell deine Agenten nennt, statt andere zu erfinden.
- **Die Aufgabenkarte ist ein Panel mit fünf Schaltflächen** —— die Chat-Karte montierte die fünf Abschnitte der Aufgabenseite als Stapel, alle standardmäßig zugeklappt: fünf Titel und eine Bildlaufleiste in einem 360px-Flyout. Jetzt öffnet eine Knopfreihe ein gemeinsames Panel bei 420px, ein Abschnitt ohne Inhalt bekommt keinen Knopf, und die Ausführungsspur beantwortet, welches Modell, welcher Adapter, welche Maschine und mit welcher Berechtigung — mit Uhrzeit an jedem Schritt.
- **Das Terminal kann, was die Konsole kann** —— der Kader eines Threads war ein reines Web-Feld. Jetzt setzt ihn `/team` aus REPL/TUI (ohne Argument öffnet sich eine mit Leertaste umschaltbare Auswahl), `/node` bindet einen Zug an eine Maschine, und `panda ask --team/--node`, `panda session ask --node` sowie die RPC-Oberfläche tragen beides über `AskScope` — damit ist die Lücke geschlossen, in der ein in der Konsole gewählter Kader Terminal-Anfragen nicht band. Die To-do-Liste ist als `panda todo …` / `/todo` erreichbar (list, add, edit, done, reopen, rm und start als Aufgabe), und `/task artifact <id>` liest den Artefakt-Pool endlich aus der Sitzung heraus statt an der ID zu scheitern.
- **Eine Aufgabe kann sich ein eigenes Arbeitsverzeichnis anheften** — eine Aufgabe, die ein Arbeitsverzeichnis benennt, läuft dort und hält die Sperre dieses Verzeichnisses statt der des Projekts; so laufen zwei Fachbereiche in getrennten Bäumen nebeneinander her, statt sich anzustellen. Der Pin hält die Aufgabe zudem auf diesem Knoten: ein Gegenüber hat keinen solchen Baum zum Ausführen. Im Baum des Projekts selbst degradiert der Pin zu einem Scope-Blatt, damit eine Projekt-Aufgabe und diese nicht denselben Checkout gleichzeitig beschreiben.

### Behoben
- **`golang.org/x/net` ist 0.62.0** —— GO-2026-6860 (quadratische Laufzeit beim Zusammenfassen von Textknoten in `html`) ist über `htmlToText` der Web-Werkzeuge erreichbar; das Modul folgt der Version mit dem Fix und `govulncheck` ist wieder sauber.

- **Das Warten auf eine geparkte Aufgabe konkurriert nicht mehr mit seinem eigenen Cursor** —— die Abschluss-Überwachung vergleicht die Task-Id jedes Ereignisses mit der verfolgten Zeile und las diese Id aus derselben Variable, die die Warteschleife bei jedem Durchlauf neu zuweist. Der Listener läuft in dem Goroutine, der das Ereignis schreibt, innerhalb seiner Transaktion, sodass der Race-Detector die beiden ungeordneten Zugriffe meldete. Die Id wird vor dem Start der Überwachung kopiert; das Verhalten bleibt gleich.
- **Der OpenCode-Go-Session-Header folgt dem Endpoint, nicht nur der Provider-Id** —— eine eigene `base_url` auf `https://opencode.ai/zen/go` trug den richtigen Go-Schlüssel, antwortete aber mit 400 MissingSessionID, weil nur die benannte `opencode-go`-Zeile `x-opencode-session` erzeugte. Der Client erkennt nun den OpenCode-Endpoint (auch die Harness-Kurzform ohne `/v1`) und erzeugt eine eigene Id; ein fremder Relay erhält diesen Header nicht. Die Id folgt dem Gespräch und nicht dem Client: eine Engine bedient jeden Thread eines Knotens, und eine gemeinsame Id steckte sie alle in eine Provider-Sitzung. Eine in `model.headers` geschriebene Id gilt weiterhin für alle.
- **Der injizierte Endpoint ist der des Providers selbst** —— mit einer Provider-Id und ohne `base_url` fiel die Injektion auf einen fest verdrahteten Anbieter zurück (`api.openai.com` oder DeepSeeks Anthropic-Endpoint), sodass `provider: opencode-go` mit einem OpenCode-Schlüssel diesen Schlüssel an einen nie genannten Anbieter gab und jeder Lauf an einem 401 scheiterte, das nichts aus der Konfiguration nannte. Jetzt wird wie im Entry-Client aufgelöst — explizite `base_url`, sonst die der Zeile, und eine nur wiederholte Katalog-URL wird auf die Fläche umgeschrieben, auf der das Modell tatsächlich dient — und der Adapter erfährt den aufgelösten Dialekt, nicht den gespeicherten.
- **Ein Modell ohne Endpoint wird gar nicht injiziert** —— die Auflösung endete weiterhin bei einem fest verdrahteten Anbieter: eine Provider-Id, deren Katalogzeile keinen Endpoint deklariert (`custom`), ohne eigenes `base_url` löste zu `api.openai.com` auf — oder zu DeepSeeks Anthropic-Endpoint, wenn der gespeicherte Typ Anthropic war — und beides konnte den Schlüssel dieser Zeile an einen nie genannten Dienst geben. Jetzt wird ein leerer Endpoint zurückgegeben und die Injektion mit einer Begründung abgelehnt, die den fehlenden Endpoint nennt. `custom` ist heute diese Zeile, der Fall war also über eine handgeschriebene config.yaml erreichbar, obwohl `panda model add` und die Konsole eine leere URL ablehnen.
- **doctor sagt, warum ein Modell nicht injiziert wird** —— die Endpoint-Prüfung entfiel ganz, wenn die Auflösung nichts ergab; eine Konfiguration, deren Katalogzeile keinen Endpoint deklariert (`custom`) und kein `base_url` hat, zeigte also nur „Modell-API-Schlüssel gesetzt“, während jeder Agent-Lauf ohne injiziertes Modell startete. `doctor` nennt jetzt den fehlenden Endpoint und den Anbieter und verweist auf `panda model add`; ein Knoten ohne jedes Modell bleibt still, weil die Schlüsselzeile das schon sagt.
- **Ein injizierter Lauf behält die Einstellungen des Agenten** —— die Injektion ersetzte die gesamte Adapter-Umgebung und ließ damit `routing.agent_models` und die eigenen Zugangsdaten-Variablen des Agenten aus jedem übernommenen Lauf verschwinden. Jetzt wird zusammengeführt, und die HTTPS-Prüfung gilt dem Endpoint, der wirklich angerufen wird, statt nur einer zufällig gesetzten `base_url`.
- **Ein abgelehntes Modell geht zur nächsten Präferenz über** —— ein vom Katalog abgelehntes Modell löste eine neue Probe mit heuristischer Auswahl aus, und eine Abrechnungsablehnung sprang direkt auf die kostenlose Stufe, sodass aus `routing.agent_models` nur der erste Eintrag je versucht wurde. Beide Wiederholungspfade gehen jetzt die Liste entlang; die kostenlose Stufe bleibt der Rückfall, wenn sie erschöpft ist.
- **Die Subcommand-Flags des Modell-CLI erreichen den Subcommand** —— `panda model add … --force`, `--type`, `--url` und die übrigen wurden vor den Subcommand-Namen sortiert und vom übergeordneten Parser als unbekannt abgelehnt (`flag provided but not defined: -force`). `panda model` hebt jetzt nur `--config` heraus und reicht alles andere unverändert weiter, egal wo das Flag steht.
- **OpenCode nutzt standardmäßig die kostenlose Stufe** —— ein Lauf ohne festgelegtes Modell wählte automatisch das leistungsfähigste Modell, sodass ein Konto ohne Go-Abo oder Guthaben jede Aufgabe mit "Insufficient account funds" beendete. Kostenlose Modelle gewinnen nun standardmäßig, die automatische Auswahl kostenpflichtiger Modelle ist ein ausdrückliches Opt-in (`OPENPANDA_OPENCODE_ALLOW_PAID=1`), eine Abrechnungs-/Kontingentablehnung wird einmal mit dem besten kostenlosen Modell wiederholt, und `opencode-go`-Modelle werden ohne gespeicherte Anmeldedaten übersprungen. Bei v2-Builds, deren `opencode models` leer antwortet, dient der Katalog aus `api model.list` als Liste.
- **Pandas Modell erreicht OpenCode über beide Protokolle** —— der Rettungspfad akzeptierte nur Modelle im OpenAI-Dialekt, sodass ein Knoten mit DeepSeeks Anthropic-Endpunkt einen fehlgeschlagenen Lauf der kostenlosen Stufe nie an Pandas Modell übergeben konnte. Der Adapter nimmt jetzt einen dialektneutralen `OPENPANDA_MODEL_*`-Vertrag entgegen, schreibt je nach Dialekt ein Provider-Fragment mit `@ai-sdk/anthropic` oder `@ai-sdk/openai-compatible`, mischt es über die native Konfiguration des Nutzers (MCP-Server und Berechtigungen bleiben erhalten) und läuft mit `--standalone`, damit ein v2-Hintergrunddienst nicht weiter seine veraltete Konfiguration ausliefert.
- **„Auto" bei Thinking bedeutet überall den Anbieter-Standard** —— REPL und Entry-Client behandelten `thinking: auto` als ausdrückliche Denk-Anforderung, während Assistent und Webformular nichts sendeten; alle Oberflächen speichern es nun als nicht gesetzt und senden kein Thinking-Feld.
- **Erweiterte Modellparameter lassen sich zurücksetzen** —— die Settings-API las `max_tokens`, `context_window`, `thinking_budget` und `max_retries` als einfache Ganzzahlen, sodass das leere Formularfeld (0) den alten Wert behielt und ein gespeichertes Retry-Budget nie gelöscht oder deaktiviert werden konnte. Sie sind jetzt optionale Felder: fehlend behält, null setzt zurück, ein negatives Retry-Budget deaktiviert Wiederholungen. Ein negatives Budget überlebt nun auch den Config-Writer (der positive Setter verwarf es beim Speichern), das Formular akzeptiert -1, und `--retry -1` im REPL wird tatsächlich angewendet.
- `panda update` bricht bei einem wackeligen Asset-Host nicht mehr komplett ab: Die Release-Metadaten werden bei einem Transportfehler bis zu dreimal erneut abgerufen, und der TLS-Handshake zum Asset-CDN von GitHub erhält 30 s statt der standardmäßigen 10 s. Die signierte Query-Zeichenkette, die GitHub an Asset-URLs hängt, wird in der Fehlermeldung unkenntlich gemacht — sie hatte die eigentliche Ursache bisher aus dem Sichtfeld geschoben.
- `scripts/install.ps1` bricht unter Windows nicht mehr mit `CRYPT_E_NO_REVOCATION_CHECK` (`0x80092012`) ab: curl läuft mit `--ssl-no-revoke`, wenn der lokale Schannel-Build dies unterstützt, sodass ein nicht erreichbarer Sperrstatus-Endpunkt die Installation nicht stoppt. Kette, Hostname und Gültigkeit werden weiterhin geprüft, und das Archiv wird weiterhin per SHA-256 gegen `checksums.txt` authentifiziert.
- **Eine Aufgabe, die einen Agenten nennt, den das Team ausschließt, wird abgelehnt statt umbesetzt** —— drei Aufgaben mit `agent:claude_code`, `agent:codex` und `agent:deepseek_harness` liefen auf einer Liste `[deepseek_harness, opencode]`, alle drei auf deepseek_harness, und jede gab `<name> 调用成功` für einen Agenten aus, der nie startete: drei grüne Durchläufe, zwei davon erfunden. Der Widerspruch wird vor dem Routing abgelehnt und die Begründung nennt beide Seiten; eine Liste, deren Agenten auf diesem Knoten nicht installiert sind, sagt das, statt auf die unbeschränkte Karte zurückzufallen.
- **Die Runden-Zusammenfassung wartet auf Mitarbeiter, die nie liefen** —— „本轮工作已全部完成“ wurde gedruckt, sobald ein Mitarbeiter berichtete, selbst wenn eine Kollegin vor der Ausführung parkte („尚未执行——批准后将继续执行“): `review` deckte sowohl die Abnahme fertiger Arbeit als auch ein Gate ab, das die Arbeit nie beginnen ließ. Eine `review`-Zeile hält die Runde jetzt offen, es sei denn, das Genehmigen akzeptiert bereits vorhandene Arbeit (`accept_work` / `self_merge`).
- **Das Urteil einer Runde zählt den ganzen Stapel, nicht den letzten Bericht** —— eine Runde mit zwei fertigen und einem fehlgeschlagenen Mitarbeiter wurde rot als „本轮工作已结束（已失败）“ zusammengefasst, und die Nachlese druckte die gemeinsame Dispatch-Vorlage einmal pro Auftrag. Jetzt zählt sie jeden Bericht und nennt die Aufteilung („2 fertig, 1 fehlgeschlagen“), bernsteinfarben bei gemischter Runde und rot nur, wenn niemand fertig wurde; ein gemeinsamer Titelkopf, der auf einem Doppelpunkt endet, wird einmal gedruckt.
- **Ein Ersatz gibt nicht mehr als der angeforderte Agent aus** —— eine auf `agent:claude_code` festgelegte Aufgabe, die mittendrin scheiterte, wurde von der Fallback-Kette beendet, und das Transkript zeigte „DeepSeek Harness“ über einem Auftrag mit dem Titel `连通性测试：agent:claude_code`, ohne zu sagen warum. Der Tausch wurde zweimal festgehalten (ein `agent_fallback`-Event und eine Notiz am Kopf der Ergebnis-Payload), aber der Thread druckt keines von beiden — er behält einen Schlussabsatz. Die Berichtszeile nennt jetzt beide Seiten.
- **Der Injektionshinweis ist eine Zeile und nennt die Strategie** —— die Fußnote vor der Ausgabe einer Aufgabe wiederholte denselben Satz auf Englisch und Chinesisch, was die eigentliche Antwort des Agenten begrub, und eine Rettung nach einem Fehler las sich wie eine Policy-Injektion. Jetzt nennt sie Agent, Modell, Endpoint-Host und Strategie (`auto` / `always` / `rescue`), das `model_injection`-Event trägt dieselben Felder für das Log, und `injection.model: never` erlaubt die Rettung nicht mehr — „never“ heißt, der Agent nutzt immer sein eigenes Modell.
- **Ein eigener Relay behält den Dialekt, den du konfiguriert hast** —— bei einem Aggregator-Anbieter (`opencode-go`) und einer eigenen OpenAI-kompatiblen `base_url` nahm ein `claude-*`-Modell weiterhin den Anthropic-Dialekt der Route und schickte einen Anthropic-Body an deinen Relay: ein 400, dessen Text auf nichts in der Konfiguration zeigte. Der Dialekt wird jetzt nur noch dann neu gesetzt, wenn der Endpunkt dem Anbieter selbst gehört — nach derselben Regel, die für die URL schon galt.
- **Eine Ablehnung ist eine Antwort, und ein namenloser Tool-Aufruf ist ein Fehler** —— im Streaming-Pfad der OpenAI-Responses-API wurde `response.refusal.*` ignoriert, sodass ein Modell, das ablehnte, eine leere Completion erzeugte; der Aufrufer las das als "es wurde nichts gesagt" und bezahlte eine komplette Wiederholung, um es erneut zu hören. In derselben Runde konnte außerdem ein Tool-Aufruf verloren gehen, den ein Proxy nur als Text streamte. Ablehnungstext wird jetzt gestreamt und zählt zur Antwort, der Completion-Envelope füllt die Felder, die die Deltas leer ließen, und Argumente, die ohne ihr `output_item.added` eintreffen, scheitern mit einer Diagnose statt mit einer plausibel wirkenden leeren Antwort.
- **Ein übermäßig großes Stream-Ereignis wird gemeldet, nicht wiederholt** —— ein einzelnes SSE-Ereignis über dem 1-MiB-Zeilenpuffer galt als Transportabbruch, also wurde dieselbe Anfrage erneut gesendet — und erneut abgerechnet — bis das Retry-Budget erschöpft war, und am Ende stand eine Meldung über Tokens. Die Obergrenze liegt jetzt bei 4 MiB und `bufio.ErrTooLong` ist endgültig; der Client ohne Streaming wartet außerdem 120s statt 30s, weil ein denkendes Modell 30s überschreitet und jeder Timeout einen weiteren bezahlten Versuch kaufte.
- **`sandbox.mode: strict` verweigert den Lauf ohne sein Backend** —— ohne `sandbox-exec`/`bwrap` auf dem Host blieb der Befehl unverändert, die konfigurierte Isolierung existierte also nicht und nichts sagte das. Strict lässt den Lauf jetzt mit Nennung des fehlenden Backends scheitern; standard läuft weiter (bubblewrap ist auf den meisten Linux-Distributionen ein eigenes Paket) und `doctor` meldet denselben Zustand ohnehin als Fehler.
- **Ein gemerktes „Ablehnen" legt keine Nur-Lese-Werkzeuge mehr lahm** —— eine abgelehnte Operation der Stufe 2 ließ jedes Werkzeug jenes Projekts „工具执行被拒" antworten, `system_status` und `card_list` eingeschlossen, sodass das Modell jede Beobachtungsmöglichkeit verlor und der Thread nie sagte, warum. Die festgehaltene Entscheidung gilt jetzt für die Operationen, die eine Autorisierung brauchen — genau wofür sie gespeichert wurde.
- **Ein gestreamter Retry streamt** —— der Wächter, der entscheidet, ob eine Antwort JSON oder Prosa ist, wurde einmal pro Aufruf erzeugt statt einmal pro Versuch: eine erste Antwort, die mit `{` begann und mitten im Stream abbrach, ließ den Wächter im Modus „strukturiert" zurück, sodass der Text des Retrys zurückgehalten wurde und die Antwort am Ende in einem Schub erschien. Jetzt entscheidet jeder Versuch für sich; was der Nutzer bereits gesehen hat, zählt weiterhin über den ganzen Aufruf.
- **Uploads zwischen 16 und 25 MiB funktionieren wieder** —— die Body-Grenze der API lag bei 16 MiB, das Limit pro Datei bei 25, also starb ein legitimer Upload in `io.Copy` und wurde als "save failed" gemeldet, was nach einer defekten Platte klingt. Uploads und Diktat bekommen ihre eigene Grenze, und eine Anfrage darüber antwortet mit 413 und dem echten Limit. Derselbe Durchgang schloss drei kleinere Lücken der Konsole: `/healthz` gibt Datenbankfehler nicht mehr an anonyme Aufrufer weiter, der Ereignisstrom ist auf 64 gleichzeitige Verbindungen begrenzt, und ein Request-Body muss innerhalb von 60s eintreffen.
- **Das Arbeitsverzeichnis eines Projekts kann nicht die ganze Maschine sein** —— die Konsole behandelt das `work_dir` jedes Projekts als lesbare Wurzel, also machte `{"work_dir": "/"}` aus einer authentifizierten Anfrage einen Betrachter der ganzen Platte. Der Store verweigert jetzt eine Dateisystemwurzel, das Home-Verzeichnis (oder einen Vorfahren davon) und die eigenen Bäume des Betriebssystems — egal, von welchem Einstiegspunkt aus das Projekt angelegt wird.
- **Ein vor dieser Regel geschriebenes Arbeitsverzeichnis kommt nicht mehr durch** —— die Breitenprüfung lief nur beim Schreiben, also blieb eine von einem älteren Build angelegte Projektzeile nach dem Upgrade eine lesbare Wurzel, und die Konsole lieferte darüber weiter die ganze Platte aus. Die Konsole prüft jetzt jedes Projekt erneut, das sie in ihre Leseliste aufnimmt: Eine Zeile, die die Regel nicht erfüllt, steuert keine Wurzel bei, und die Dateien dieses Projekts bleiben über das Panel unlesbar, bis sein Arbeitsverzeichnis korrigiert ist.
- **Ein abgelehntes Arbeitsverzeichnis nennt den Grund** —— die Projektaktualisierung der Konsole antwortete mit einem nackten `500 update failed`, wenn die Breitenregel das neue Verzeichnis verweigerte, sodass der Betreiber einen defekten Store sah statt der Regel, die zu korrigieren war; das Anlegen antwortete mit 200 für einen vorhandenen Namen und mit 500 für einen neuen. Beide Einstiegspunkte antworten jetzt mit 400 und der Regel, die den Pfad verweigert hat.
- **Ein Datagramm kann nicht mehr unter fremdem Namen reisen** —— die UDP-Ebene versiegelte jeden Frame mit einem einzigen, aus dem Mesh-Secret abgeleiteten Schlüssel, sodass jedes Mitglied einen Frame erzeugen konnte, der behauptete, jedes andere zu sein; getrennt wurden beide nur durch die Quelladresse, die sich zwei Peers hinter einem NAT — oder zwei Hosts in einem LAN — teilen. Datagramme werden jetzt auf das Paar versiegelt, mit einem aus den beiden Knotenidentitäten abgeleiteten X25519-Schlüssel, der Absender-ID im Klartext als Schlüsselauswahl und einem `From` des Umschlags, das dagegen geprüft wird. Hello belegt weiterhin nur die Mitgliedschaft, und ein Peer ohne veröffentlichten Identitätsschlüssel behält den alten Mesh-Schlüsselpfad; ein 0.1.0-Knoten, der einen veröffentlicht, kann die neue Form aber nicht öffnen — diese Ebene verlangt das ganze Mesh auf 0.1.1 (siehe **Inkompatible Änderungen**).
- **Eine gecachte Probe überstimmt den Dienst nicht mehr** —— ein fehlgeschlagenes `run --help` cachte weiterhin eine Stunde lang „dieser Build hat keine dieser Flags" und verweigerte eingeschränkte Aufgaben mit einer Diagnose, die niemand beobachtet hatte; ein Modell, das in einem gecachten Roster fehlte, beendete die Aufgabe, statt den Dienst erneut zu fragen. Jetzt wird nur eine erfolgreiche Probe gecacht, ein Roster-Fehlschlag wird vor dem Glauben erneut geprüft, die Cache-Dateien sind 0600, und eine zurückgestellte Uhr gilt als Ablauf.
- **Eine Diagnoseprobe parkt keinen Agenten mehr** —— `panda doctor` und `agents test` schreiben ihr frisches Urteil in den Routing-Cache zurück, und dieses Zurückschreiben ließ das `unknown`-Flag fallen: ein Endpunkt, der nur in den Timeout lief, wurde als definitiv unerreichbar festgehalten, sodass die nächste Aufgabe diesen Agenten für die TTL des Caches übersprang — das Gegenteil von „was du gedruckt hast, ist was das Routing benutzt".
- **Zwei Speicher-Schreibvorgänge überschreiben sich nicht mehr** —— `memory_add` lud MEMORY.md, änderte die Kopie und schrieb die ganze Datei zurück; zwei überlappende Adds behielten also jeweils nur die eigene Sicht, und ein Schwall von 24 gleichzeitigen Adds hinterließ einen einzigen Eintrag — bei durchweg gemeldetem Erfolg. Lesen und Schreiben sind jetzt ein kritischer Abschnitt, hinter einer Sperrdatei in der Store-Wurzel, die auch CLI und Konsole abdeckt, wenn sie dieselbe Datei aus einem anderen Prozess bearbeiten.
- **Die Konsole tastet nicht mehr bei jedem Öffnen alle Agenten ab** —— `/api/agents` startet jede installierte CLI für ihre Version, und Einstellungen, Workspace, Knotenliste und Team-Auswahl rufen es alle ab, sodass ein Öffnen der Konsole dieselben Sonden mehrfach bezahlte. Versionen werden fünf Minuten lang mit dem aufgelösten Pfad als Schlüssel zwischengespeichert (eine frisch installierte CLI ist ein Fehlgriff, kein alter Wert), Fehlschläge ebenfalls; die explizite Test-Schaltfläche fragt immer die CLI selbst.
- **Eine pathologische Antwort kann die Nachrichtenansicht nicht mehr mitreißen** —— der Markdown-Parser rekursierte pro Verschachtelungsebene, sodass eine Wand aus `>` oder absurde Einrückung den JS-Stack mit einem RangeError erschöpfte statt zu rendern. Die Verschachtelung endet bei zwölf Ebenen, der Inhalt bleibt als Text erhalten.
- **Ein beschäftigter Knoten wird nicht mehr als belegter diagnostiziert** —— `nodeidentity.Acquire` meldete jeden Sperrfehler als „läuft bereits", sodass ein unlesbares Konfigurationsverzeichnis oder ein Volume ohne Sperren dem Engine weismachte, ein Daemon besitze die Zeile, und er zurücktrat. Nur echte Konkurrenz bildet diesen Fehler ab; alles andere wird durchgereicht.
- **Eine Beförderung wird erst nach dem Schreiben protokolliert** —— der Dreaming-Lauf meldete jede Beförderung ins Audit-Log, während die Datei noch ungespeichert war, sodass ein fehlgeschlagener Schreibvorgang einen „ok"-Eintrag für einen nie gelandeten Eintrag hinterließ. Der Lauf hält die Sperre außerdem über Laden, Bewerten und Schreiben, sodass ein während des Laufs vom Agenten hinzugefügter Eintrag nicht mehr überschrieben wird.
- **Ein Projekt umzubenennen verschiebt seinen Speicher in einem gesperrten Schritt** —— die Konsole kopierte die alte Datei und löschte danach das alte Verzeichnis in zwei Schritten; ein dazwischen hinzugefügter Eintrag wurde veraltet kopiert oder vom Löschen erfasst.
- **Eine Aktualisierung ohne Änderung schreibt nichts** —— der Store vergleicht das Ergebnis mit dem Gelesenen und überspringt das Zurückschreiben, sodass ein Konsolidierungslauf ohne Beförderung mtime und Beobachter in Ruhe lässt.
- **Ein angeheftetes Arbeitsverzeichnis unterliegt der Breitenregel des Projekts** — das Arbeitsverzeichnis einer Aufgabe wird zum schreibbaren Wurzelverzeichnis dessen, was sie startet; ein angehefteter Volume-Root oder das Home-Verzeichnis überließ so einer Ausführung die ganze Maschine. Die Projekt-Tabelle lehnte solche Fälle bereits ab; jetzt gilt dieselbe Regel für den Pin der Aufgabe und deckt zugleich das `--workdir` der CLI, das Anlegen von Aufgaben im Panel und das workdir eines Delegate-Markers ab. Ein Marker, der den Baum des Elternteils benennt, verliert seinen Pin weiterhin, doch die von ihm deklarierten Spuren bleiben erhalten.
- **Das Herunterfahren der Queue konkurriert nicht mehr mit ihrem eigenen Dispatch** — die Dispatch-Schleife nahm einen Runner-Platz mit einem nackten `wg.Add(1)`, während das Schließen der Engine bereits in `wg.Wait()` steckte. Go modelliert die erste Erhöhung einer WaitGroup als Lesezugriff auf den Zustand des Wartenden und den ersten Wartenden als Schreibzugriff darauf; zwei ungeordnete Zugriffe meldet der Race-Detector deshalb als Datenrennen: die Queue-Engine der Konsole stolperte darüber beim Abbau, und das Race-Leg des Gates hat es gefangen. Der Platz wird jetzt unter einem Mutex genommen, den auch das Warten hält, und abgelehnt, sobald das Herunterfahren begonnen hat — ein vor dem Warten genommener Platz wird von ihm erwartet, ein danach genommener abgelehnt, und die Aufgabe bleibt in der Queue.

### Verbessert

- **Das Dispatching lernt aus Fehlern, und Sonden wiederholen sich nicht** —— Adapter-Sonden (`opencode models`, `api model.list`, `run --help`) werden prozessübergreifend mit dem Fingerabdruck von CLI und Konfiguration als Schlüssel gecacht, sodass eine Reihe von Aufgaben jede Sonde nur einmal bezahlt; ein abgelehntes Modell erzwingt weiterhin ein frisches Lesen. Das lokale Agent-Ranking stuft einen Agenten herab, dessen Circuit der Knoten offen hält (er bleibt Alternative, wird nie ausgeschlossen), sodass die nächste Aufgabe nicht mehr mit dem Agenten beginnt, den die letzten Fehler ausgeschlossen haben. Der Modell-Circuit-Breaker verlängert wiederholte Fehler von 30 s auf 5 min und probiert zuerst gesunde Fallbacks, mit provider/Endpunkt/Modell als Schlüssel, damit ein Anbieterausfall keinen Alias auf einem anderen Endpunkt abkühlt.
- **Der Baum-Hash pro Runde belegt ~4 MB statt ~165 MB** —— `defense.HashDir` las jede Datei über `io.CopyBuffer` mit einem 1-MB-Puffer, den das `io.WriterTo` von `*os.File` verwirft: Der Kopiervorgang fiel auf eine 32-KB-Allokation pro Datei zurück, rund 165 MB Müll pro Überwachungsrunde bei einem Projekt mit 5000 Dateien. Eine einzige Leseschleife über einen gemeinsamen Puffer bringt das auf ~4 MB und spart etwa ein Zehntel der Laufzeit. Der Digest ist identisch, bereits aufgezeichnete Oszillations-Fingerabdrücke bleiben also vergleichbar.

### Inkompatible Änderungen

- **Der UDP-Datagramm-Fallback verlangt das ganze Mesh auf 0.1.1** — Daten- und Keepalive-Frames werden jetzt auf das Peer-Paar versiegelt, und ein 0.1.0-Build kann nur die Mesh-Schlüsselform öffnen, die dieser Build von jeder Adresse eines Peers mit veröffentlichtem Identitätsschlüssel ablehnt. Zwischen einem aktualisierten und einem älteren Knoten befördert die Datagramm-Ebene in keine Richtung mehr etwas, bis beide aktualisiert sind; die WebSocket-Spur ist nicht betroffen, und Punch-Frames behalten die alte Form, sodass Hole Punching weiter funktioniert. Ein Peer ohne veröffentlichten Identitätsschlüssel — ein Build vor der Doppelschlüssel-Identität oder ein Knoten ohne einen — behält durchgehend den alten Pfad.

## [0.1.0] - 2026-10-23 — "Constellation"

**Die Release-Qualitätslinie beginnt hier** — Codename **Constellation**: die Flotte als ein Himmel. Aufgaben desselben Projekts laufen parallel über deklarierte Pfadbereiche und isolierte Worktrees, während die Delegationsgrenzen bei jedem Hop enger werden; ein netzübergreifendes Mesh trägt Arbeit zwischen Knoten, die sich nicht erreichen können — zweischlüssige Identität, blinde Relays, epidemische Verzeichnis-Synchronisation, Rendezvous-Kanten mit K=2 und die Erreichbarkeitsleiter —, und ein neues Gerät kommt über eine einzige `panda://join`-URI hinein. Eine Konsole befehligt alles: eine Aufgabenseite, die mit ihrem Urteil beginnt, ein To-do-Board, das Arbeit an die Flotte übergibt, eine Liste, mit der ein Thread sein eigenes Team einstellt, und eine Transkription, die den Screenshot als Bild zeichnet — mit der geschlossenen Release-Prüfung dahinter: jeder Korrektheits- und Sicherheitsbefund ist mit einem Regressionstest behoben, und die echte Kette Mac → Relay → Cloud ist verifiziert.

Bekannte Einschränkungen dieser Version: UPnP/NAT-PMP-Portmapping ist nicht implementiert; die Signatur-Konvergenz für Punch- und Verzeichnis-Frames ist noch offen; Mesh-Zähler werden nicht über das IPC des Panels gebrückt; und die Hello-Wiederholung zwischen Knoten bleibt eine offene Protokoll-Challenge. `docs/status.md` führt die Punkte einzeln auf.

### Schwerpunkte

- **Die Flotte reicht über Netze hinweg.** Identität ist zweischlüssig (ein stabiler Signaturschlüssel plus ein rotierender), ein blinder Relay trägt Arbeit zwischen Knoten, die sich nicht erreichen können, Verzeichnisse konvergieren über epidemische Delta-Synchronisation, Rendezvous-Kanten werden mit K=2 gewählt, und die Erreichbarkeitsleiter fällt vom direkten Wählen über Hole-Punching und Relay bis Store-and-Forward zurück — ein neues Gerät kommt über eine einzige `panda://join`-URI hinein.
- **Ein Projekt läuft parallel.** `--paths` begrenzt eine Aufgabe auf die Verzeichnisse, die sie deklariert, `--isolate` gibt ihr einen privaten Worktree, der dreiseitig zurückgeführt wird, und Delegationsgrenzen ziehen sich bei jedem Hop zusammen, statt von einem großzügigen Weiterleiter gewaschen zu werden.
- **Eine Sicherheitslage in Release-Qualität.** Destruktive Befehle kommen nicht mehr als umkehrbar durch, `sandbox.mode: strict` verweigert das Lesen von Knotengeheimnissen, eine unlesbare Vertrauensaussage schlägt geschlossen fehl, ein Relay kann den vom Ursprung genehmigten Umfang nicht mehr umschreiben, und ein bekannter Knoten lässt sich nicht durch Weglassen seines Schlüssels nachahmen.
- **Die Konsole wurde ein Arbeitsort.** Eine Aufgabenseite, die mit ihrem Urteil beginnt, ein To-do-Board, das Arbeit an die Flotte übergibt, eine Liste, mit der ein Thread sein eigenes Team einstellt, und eine Transkription, die den Screenshot als Bild zeichnet.
- **Fehlschlag ist jetzt ein Zustand, kein Abbruch.** Eine verlorene Verbindung wartet auf das Netz und spielt den Aufruf erneut ab, ein Modell, das einen Fehler meldet, wird als fehlgeschlagen verbucht, jedes Urteil auf der Leitung ist durch seinen Dispensation-Versuch eingezäunt, und die Wiederherstellung nach einem Neustart setzt fort, was überlebt hat, statt es neu zu starten.
- **Selbst-Evolution, standardmäßig aus.** `panda self` führt signierte Patch-Sets durch eine Warteschlange, einen Merge-Worktree, eine Genehmigungsaufgabe, `make gate`, einen gestaffelten Austausch und ein `panda.release`-Rückrollziel — [Experimental], opt-in und nie im Weg gewöhnlicher Arbeit.

### Upgrade von 0.0.x

- Keine Breaking Changes: Konfiguration, Capability Cards, gespeicherte Daten und das Protokollformat werden übernommen, Migrationen laufen beim ersten Start.
- Eine bestehende Installation aktualisiert sich an Ort und Stelle: `panda update` hebt einen Knoten auf diesen Schnitt, und eine Neuinstallation ist `install.sh --version 0.1.0`.
- Der Build aus dem Quellcode verlangt jetzt Go 1.26.10 (eine Sicherheitsuntergrenze, keine Vorliebe — siehe den `govulncheck`-Eintrag unten).

### Hinzugefügt

- **Ein Modell pro Agent** —— `injection.model` war eine Entscheidung für den ganzen Knoten, also ließ sich ein Harness, der Anthropic Messages spricht, nur injizieren, indem man das Knotenmodell auf seinen Dialekt umstellt — und damit allen anderen Agenten die Rettungsinjektion nimmt. `injection.agents.<agent|adapter>` pinnt ein Modell nur für diesen Agenten: nicht gesetzte Felder erben das Knotenmodell, die Vererbung endet jedoch vor den Transportknöpfen `params`, `headers` und `thinking` — genau der Weg, auf dem der Body des einen Dialekts in den anderen gerät.

- **Das Eingabefeld nimmt die Stimme** —— Diktat gab es nur für die TUI, deren Sidecars das Mikrofon der Maschine öffnen, auf der der Prozess läuft: der falsche Raum, wenn die Konsole über das LAN geöffnet wird. Jetzt nimmt die Seite 16-kHz-Mono-WAV auf, und `POST /api/voice/transcribe` reicht es an einen OpenAI-kompatiblen `/audio/transcriptions`-Endpunkt weiter. Der Abschnitt `asr` ist optional und erbt das aktive Modell, und eine Ablehnung des Anbieters wird mit dessen eigenem Satz gemeldet.

- **Ein Screenshot in der Transkription ist jetzt ein Bild, kein Pfad** —— eine Tool-Zeile, die ein Bild gelesen oder erzeugt hat (`Read` auf `shot.png`, oder eine Aufnahme mit der Antwort „gespeichert unter …"), zeigte nur den Dateinamen; um zu prüfen, was der Agent gesehen hat, musste man die Datei selbst öffnen. Das Protokoll zeichnet das Bild nun unter dem Aufruf — gerahmte Vorschau, höchstens 220 px hoch — und ein Klick öffnet es im Vollbild, mit dem Pfad in der Fußzeile; Esc, ein Klick daneben oder × schließen es. `GET /api/fs/image` liefert die Bytes aus den Storage-Wurzeln oder dem temporären Verzeichnis des Systems (nur Bilder, 16-MiB-Grenze, `nosniff`), lädt sie erst beim Scrollen in die Zeile, und ein gelöschter Pfad hinterlässt nur eine leise Zeile „Bildvorschau nicht möglich" statt eines kaputten Bildsymbols.

- **To-do-Board: erst notieren, später entscheiden, was Panda übernimmt** —— neue Zeile 待办 in der Leiste: drei Spuren (offen / in Arbeit / erledigt) mit Titel, Beschreibung, Priorität, Fälligkeit, Tags und Projekt; zwischen Spuren ziehen, per Kreis abhaken, Verworfenes klappt in eine Zeile am Fuß. „An Panda geben“ macht aus dem To-do eine eingereihte Aufgabe — die Beschreibung wird zum Auftrag — und verknüpft beide. To-dos liegen bewusst neben der Aufgaben-Warteschlange: die Queue leert sich selbst, ein To-do bewegt sich nur, wenn du es bewegst (Migration v61, `/api/todos`).

- **Ein Netzausfall lässt den Turn nicht mehr scheitern — er wartet auf die Verbindung und macht weiter** — ein Transportfehler verbrauchte bisher das gesamte Retry-Budget innerhalb von Sekunden auf einer toten Route und ließ den Aufruf dann scheitern; für ein Notebook, das gerade in einen Tunnel gefahren ist, ist das die falsche Antwort: Der Ausfall dauert Minuten, die Retry-Leiter Sekunden. Ein fehlgeschlagener Modellaufruf prüft jetzt zuerst den eigenen Endpunkt des Anbieters und zwei öffentliche Anker; gilt die Maschine als offline, wartet er — sichtbar in der Statuszeile der CLI, der TUI und der Konsole — und wiederholt den Aufruf, sobald irgendetwas antwortet, ohne einen Retry-Versuch zu verbrauchen. Endpunkte ohne Internetbedarf (ein lokales Modell auf Loopback oder im LAN) sind ausgenommen, `model.offline_wait: false` stellt das schnelle Scheitern wieder her, und die Wartezeit endet durch deinen Abbruch, nicht durch einen Timer.
- **Eine Nachricht an eine laufende Aufgabe sagt jetzt, ob sie angekommen ist — und die Konsole kann überhaupt eine senden** — `/queue` und `/inject` waren auf jeder Oberfläche implementiert und auf keiner sichtbar: das Board behielt die Notiz, aber nichts meldete, dass es sie gibt, und die Web-Konsole verwarf bei laufendem Turn den gerade angenommenen Text stillschweigend. Beide sind jetzt erstklassige Befehle der TUI — `/queue <Text>` zielt auf die zuletzt im Picker geöffnete Aufgabe, eine explizite ID hat Vorrang — und die Konsole schreibt in den laufenden Turn, statt ihn wegzuwerfen. Jede Benutzernotiz trägt einen Lesebeleg: das Abzeichen `✎n ungelesen` in der Aufgabenauswahl und auf der Board-Karte bleibt, bis die Runde, die sie einbindet, `consumed_at` stempelt, und der Trace hält beide Hälften fest (`user_msg` und `user_msg_consumed`) — „für die nächste Runde eingereiht" ist damit endlich von „hat nie jemand gelesen" unterscheidbar. Ein Inject, dessen Runde zu einem anderen Prozess gehört, reiht weiterhin ein, sagt das aber jetzt, statt einen Abbruch zu behaupten, der nie stattfand; und die TUI bestätigt die Zustellung über den Callback der Rundenschleife selbst, nicht über einen erfolgreichen Kanal-Schreibvorgang.

- **Ein eingereihter Hinweis lässt sich zurückziehen, korrigieren und hochstufen, ohne ihn neu zu tippen** — Enter während einer Runde hat in der TUI jetzt drei Antworten: der erste Druck reiht ein, derselbe Entwurf ein zweites Mal stuft genau diesen Hinweis an Ort und Stelle hoch (keine zweite Zeile, die Runde liest die Worte also einmal), und `ctrl+d` zieht ihn zurück, bevor eine Runde ihn aufnimmt. Ein geänderter Entwurf auf derselben Aufgabe schreibt die eingereihte Zeile um, statt daneben zu posten. Der Streifen offener Hinweise in der Konsole (Warteschlange oder Injektion, Board oder prozesslokal) bekommt Stift und Papierkorb: Bearbeiten trifft die Zeile über `PATCH /api/sessions/{id}/notes/{key}`, eine Injektion bleibt also Injektion und behält ihren Platz, und das Löschen eines bereits gelesenen Hinweises wird mit 409 abgelehnt, statt Board und Prompt auseinanderlaufen zu lassen. Anhänge reisen mit: ein in den Composer eingefügter Screenshot wird zuerst hochgeladen und landet als `@path` im Text, sodass der Agent die Datei öffnet statt einen Dateinamen zu lesen.

- **Ein Thread stellt sein eigenes Team ein** — der Fuß des Composers trägt jetzt eine Liste: jede Agent-CLI, die der Knoten kennt, erscheint als Person mit Gesicht, Namen und der Aufgabe, für die sie gut ist, und nur die gewählten Hände dürfen die Arbeit dieses Gesprächs übernehmen. Leer (der Standard) lässt den Scheduler je Aufgabe wählen; die Wahl liegt auf der Session, sodass ein wieder geöffneter Thread weiterhin weiß, wer daran arbeitet, und die Liste wird in das Spec jeder klassifizierten Aufgabe kopiert — sie gilt damit über Pläne, Sub-Agenten und einen Sprung auf einen anderen Knoten hinweg, statt ein Ratschlag zu sein, den das Modell ignorieren kann. Eine Liste, die nur Agenten nennt, die dieser Knoten nicht führt, fällt auf „keine Einschränkung“ zurück, statt die Aufgabe zu stranden.

### Geändert

- **Der Arbeitsbereich zeigt Geräte, keine Karte** —— Panels aus Agenten-Marken ersetzen den Topologie-Ring: das Panel ist die Maschine, die Kachel der Agent und ob er gerade arbeitet. Und eine Runde endet nicht mehr mit dem ersten Bericht eines Stapels — `roundStillOpen()` liest das Taskboard, sodass „die Arbeit dieser Runde ist abgeschlossen" auf den letzten wartet.

- **„Aufgabe ansehen" öffnet die Aufgabe neben dem Transkript, statt es zu verlassen** —— der Link unter einer delegierten Aufgabe führte nach 队列·任务·项目 und kostete den Leser die Unterhaltung selbst: Scrollposition, Entwurf, Stelle. Jetzt öffnet er die Orchestrierungskarte mit dieser Aufgabe bereits ausgewählt — die Aufgabenliste des Threads daneben —, und die volle Seite bleibt einen Klick in der Fußzeile der Karte entfernt; ⌘/Strg-Klick auf den Link geht direkt dorthin.

- **Eine beendete Aufgabe meldet, wer sie ausgeführt hat und wie sie endete — nicht ihr ganzes Transkript** — der Session-Finalizer klebte die vollständige Antwort des Adapters unter ein `[done]`-Tag in den Thread: zweitausend Wörter mit Änderungsliste, Verifikationsschritten und den Codeblöcken darin. Der Turn besteht jetzt aus der Orchestrierungszeile — Zustand, der ausführende Mitarbeiter (`@claude_code`) und die ihm gegebene Aufgabe — gefolgt vom Schlussabsatz genau dieses Mitarbeiters, an einer Satzgrenze gekürzt, wobei ein abschließender Codeblock, eine Tabelle oder ein „soll ich weitermachen?“ übersprungen wird, damit die Belege die Schlussfolgerung nicht verdrängen. Das Detail bleibt auf der Aufgaben-Seite, und die Historie des Modells spielt nicht länger seine eigene frühere Prosa ab. Plan-Stages tragen nun die Conversation-Id, sodass ein mehrstufiger Lauf die Antwort jedes Mitarbeiters in den Thread zurückmeldet, statt hinter einer einzeiligen Quittung zu verstummen.

- **Dieser Bericht wird als Kopfzeile gezeichnet, nicht als Wire-Tag gedruckt** — die Orchestrierungszeile kam als reiner Text an (`[done] @claude_code · 修复登录重定向`), sodass in einem chinesischen Thread zuerst ein englisches Statuswort in Klammern stand: das Protokoll leckte in die Oberfläche. Der Tag bleibt im gespeicherten Turn (der Ungelesen-Punkt der Historie liest ihn) und wird jetzt als Kopfzeile gezeichnet — der Status als Wort in seiner eigenen Farbe, der Mitarbeiter als Mono-Chip, der Auftragstitel in der Hauptfarbe, darunter der Schlussabsatz als gewöhnliches Markdown.

- **Die Task-Detailseite ist eine Spalte, und ihre Fakten lassen keine Lücke mehr** — die Seite teilte sich in eine 636px breite Lesespalte neben einer 272px breiten Fakten-Leiste, doch die Fakten sind sieben kurze Werte: Die Leiste war nach 240px zu Ende, während das Ereignisprotokoll noch tausend Pixel weiterlief — die rechte Hälfte der Seite blieb über den gesamten Scroll leer. Die Fakten stehen jetzt als Band aus Label über Wert oben (vier bis fünf pro Zeile, die UUIDs mit eigener Zelle zum Umbrechen), und alles darunter — Ergebnis, Brief, Board, Delegationskette, Sub-Agenten, Protokoll — teilt ein Maß, was auch der Tool-Ausgabe die Breite gibt, aus der sie vorher herausgebrochen ist. Die Marker der Zeitachse hängen im linken Rand, sodass die Uhrzeit jedes Ereignisses auf derselben Linie beginnt wie die Abschnittstitel darüber.

- **Die Aufgabendetailseite beginnt mit dem Urteil und klappt zu, was sich nicht zusammenfassen lässt** — die Seite öffnete mit einem Faktenband: fünf Spalten grauer IDs, ein Trace-Streifen, dann ein Ergebnisabschnitt, dessen einzige brauchbare Zeile ein 300 Zeichen langer Fehlertext war, darunter das vollständige Protokoll mit achtzehn Ereignissen (55 % der Seite). Jetzt steht oben ein Urteilsblock: die Statusplakette, ein Satz dazu, was passiert ist (der gemeldete Fehler, das eigene Urteil oder die zuletzt geschriebene Zeile) und was die Antwort gekostet hat (Dauer, Runden, Token, Geld) — die Begründung auf drei Zeilen gekürzt, der Rest einen Klick entfernt. Darunter falten sich die Referenzdaten in eine Kopfzeile (`#id · Projekt · Knoten · erstellt`), der Auftrag auf seinen ersten Satz plus Anzahl der Vorgaben, und das Protokoll öffnet auf seinen letzten fünf Ereignissen. Der Ergebnisabschnitt wiederholt nicht mehr Status, Begründung, Token und Kosten, die das Urteil schon nennt; er entfällt, wenn er nur einen Fehler trug, und die letzte Ergebniszeile des Protokolls druckt dieselbe Ausgabe nicht ein zweites Mal. Temporäre Sitzungsdateien des Agenten (`.claude/…`) zählen nicht mehr als geänderte Dateien.

### Behoben

- **Ein `--json`-Fehler ist auch JSON** — `--json` versprach eine maschinenlesbare Antwort und brach das Versprechen im Fehlerpfad; der Fehler geht jetzt als `{"error":{"code":…,"message":…}}` nach stderr.
- **Ein Queue-Schreibvorgang öffnet keinen Netzwerk-Socket mehr** — `task add`/`task send`/`task continue` starteten einen vollständigen Core und konkurrierten um den LAN-Discovery-Port; der lokale Schreibvorgang nimmt jetzt den leichten Pfad.
- **Die Toolchain-Untergrenze ist Go 1.26.10, und das Gate fährt `govulncheck`** — 1.26.9 trug GO-2026-6809 (Prüfung intermediärer CAs in `crypto/x509`).
- **Ein destruktiver Befehl passiert nicht mehr als reversibel** — der Klassifizierer urteilte nach dem Verb und genehmigte gefährliche Formen von `cp`/`mv`/`chmod`/`chown`/`ln`/`tee`/`install`/`kill` automatisch; nur Formen, die Systempfade, Setuid-Bits oder init treffen, steigen auf Tier 2.
- **Ein Daemon, der seinen Port nicht binden kann, beendet sich statt endlos neu zu versuchen** — bei ungültiger `listen_addr` meldete er „gestartet", und systemd/launchd hielten ihn für gesund.
- **Eine vertippte `--config` ist ein Fehler, keine Warnung** — schreibende Befehle legen nicht mehr still eine nicht existierende Konfiguration an; sie enden mit 2.
- **„Der Daemon läuft nicht" wird nicht mehr geraten** — wenn `ps` nicht lesbar ist, sagt die Prüfung „nicht verifizierbar", statt einen gesunden Daemon für tot zu erklären.
- **Der Entpacker staged über einen Zufallsnamen statt `path + ".partial"`** — ein fester Name war ein Ziel für einen vorab platzierten Symlink.

- **Mehrhop-Aufgaben holen ihre Eingaben wieder über den Relay** — Artifact-Fetch/Chunk-Frames laufen über die Blind-Transit-Ebene (versiegelter Body max. 2 MiB, ein 1-MiB-Chunk pro Frame), sodass ein Executor zwei Hops entfernt seinen Projektbaum erhält statt mit „peer not connected" zu scheitern. Auf einer Mac → Relay → Cloud-Kette über WAN verifiziert.
- **Ein `status:"failed"` des Modells wird nicht mehr als erledigt verbucht** — ein sauberer Adapter-Exit verdeckt die Selbstauskunft des Modells nicht mehr; der Grund erreicht Retry-Schleife, Delegator und Zeitachse.
- **Lehnt ein Peer ab, läuft die Aufgabe auf einem fähigen Ursprung lokal weiter** — die eingereihte Zeile wird übernommen und ausgeführt statt einen falschen Fehler zu melden; ein synchrones Submit wartet nicht mehr auf eine Zeile, die niemand ausführt.
- **Ein bekannter Knoten kann nicht mehr durch Weglassen seines Ed25519-Blocks imitiert werden** — ist für eine Node-ID ein Schlüssel verzeichnet, muss das Hello ihn vorweisen; ein Schlüsselwechsel ist eine Betreiberaktion.
- **Delegierte Projektpakete werden erst nach der Trust-Admission und mit Empfängergrenzen entpackt** — ein `open`- oder abgelehnter Ursprung kann nicht in den Projektspeicher schreiben; eine Kompressionsbombe ist durch Entpackgröße und freien Speicher begrenzt.
- **Ein Datagramm-`hello_reject` kann die UDP-Ebene nicht mehr beenden** — verbindungsgebundene Hello-Frames werden vor dem Dispatch verworfen, und der Handler toleriert eine nil-Verbindung.
- **`sandbox.mode: strict` verweigert das Lesen von Knotengeheimnissen** — Config/Karte, SQLite (private Knotenschlüssel) samt WAL/SHM und der OAuth-Token-Store sind dateiweise lesegeschützt; Elternverzeichnisse bleiben lesbar, damit Arbeitstrees funktionieren.
- **Der eigenständige `panda-webui`-Sidecar bedient Thread- und Skill-APIs** — `make run-local` führt beim Öffnen eines Threads oder der Skill-Seite nicht mehr ins 404.
- **`panda model add custom <url>` panikt nicht mehr** — eine leere Positionsliste ist ein Nutzungsfehler, kein Index außerhalb des Bereichs.
- **Uninstall-Backups sind privat und brechen bei Fehlern das Löschen ab** — das Archiv wird mit 0600 geschrieben (es enthält das Mesh-Secret, Provider-Schlüssel und private Knotenschlüssel); eine unlesbare Datei oder eine volle Platte stoppt die Deinstallation, bevor irgendetwas gelöscht wird, statt ein Teilarchiv zu hinterlassen und die Originale zu entfernen.
- **Der Laufzeitzustand einer Sitzung wird nie in den Benutzerbranch gemerged** — der ganze `.openpanda/`-Baum (Worktrees, Composer-Uploads, Task-Temporärdateien) ist vom `git add -A` des Session-Merges ausgenommen.
- **Fehlgeschlagene `--json`-Pfade beenden mit ungleich null** — `agents test`, `config model test` und `session rm` geben bei Fehlern kein 0 mehr zurück; `session rm` gibt nur JSON aus (Fehler eingeschlossen).

- **Das Verzeichnis-Kontingent zählt jetzt den Signierenden** — ein Mitglied konnte Zeilen für beliebige neue Kennungen signieren; da eine nicht-stabile Kennung nie verankert wird, wurden diese Zeilen niemandem zugerechnet: sein Anteil blieb bei null, während die Tabelle bis zur Grenze von 1024 Zeilen wuchs und einem ehrlichen neuen Knoten kein Platz blieb, seine eigene Zeile zu veröffentlichen. Ein einzelnes Mitglied konnte das Verzeichnis der ganzen Flotte zum Schweigen bringen. Die Signatur deckt den eigenen Schlüssel der Zeile ab — wer signiert hat, ist damit ein Beweis und keine Behauptung, und das Kontingent zählt so.

- **Ein Dial-Timeout schließt die von ihm eröffnete Verbindung nicht mehr** — die Erreichbarkeitsleiter gab jeder Kandidatenadresse eine Frist und übergab dasselbe Kontext an die Leseschleife der Verbindung; die Stornierung schloss deshalb den Socket, bevor die hello-Antwort gelesen war. Jede Markierung über eine angekündigte Adresse und über den Rendezvous starb beim Eintreffen und wurde still zu Relais oder Lochversuch. Das Dial-Budget und die Lebensdauer der Verbindung sind jetzt zwei verschiedene Uhren.

- **Eine unlesbare Vertrauenszusage schließt** — beide Verzeichnisabfragen verschluckten ihren SQL-Fehler, sodass eine kurzzeitig ausgelastete Datenbank ein `guarded` (oder `open`) Gegenüber als voll vertrautes `mesh` las: das Sendekontingent, die Klemme für Artefakteingaben, die Relaisannahme und die Ausnahme für Bildschirminhalte griffen alle. Ein Gegenüber, dessen Stufe nicht lesbar ist, gilt als `open`.

- **Eine NAT-übergreifende Paarung bringt den Knoten nicht mehr zu Fall** — eine über ein Relais eingetroffene Paarung hat keine Verbindung, und die Ablaufbereinigung schloss sie bedingungslos. Die Nil-Dereferenz fing der Panik-Wächter des Monitors ab, dessen Abbruch den ganzen Daemon beendete. Die Bereinigung nutzt jetzt den nil-sicheren close und räumt die abgelaufene Sitzung auf.

- **Eine weitergeleitete Lochstoß-Anfrage erreicht den Anfragenden** — die Identität des Anfragenden reiste im Envelope, und ein Relais prägt das Envelope als eigenes neu; der gewählte Anbieter stieß daher auf das Relais (ohnehin direkt erreichbar) statt auf den Anfragenden. Die Identität reist jetzt in der Nutzlast, und der Regressionstest fährt den echten weitergeleiteten Pfad.

- **Ein unversiegeltes Transit-Frame wird abgewiesen** — die Ausnahme, die den Pairing-Handshake unversiegelt durch ein Relay lässt, war überhaupt nicht getestet: die Guard zu entfernen ließ die Suite grün. Ein Mitglied konnte den Inhalt unversiegelt einschließen, und jedes Relay, das ihn trug, las den Klartext.

- **Ein Relay kann den vom Ursprung genehmigten Umfang nicht mehr umschreiben** — der Consent-Digest war eine handgepflegte Feldliste, und die deklarierten Schreibspuren sowie das Worktree-Isolationsflag kamen erst danach hinzu: ein authentifiziertes Relay konnte beides umschreiben, und die Ed25519-Zustimmung des Ursprungs verifizierte weiterhin. Beide sind jetzt gebunden; Chain und Budgets nicht, weil Relays sie legitim umschreiben.

- **Ein Kind, das seine Spawn-Grenze verliert, scheitert, statt mit schwächerer Politik zu laufen** — beim Spawn wurden Tiefe, Grenze, Scope, Isolation, Arbeitsverzeichnis und Budgets nur als Warnungen persistiert. Die Zeile ist das, was jeder weitere Hop und jeder Neustart liest: eine verlorene Isolation ließ ein Kind, dem eine private Kopie versprochen war, auf dem gemeinsamen Checkout laufen, und ein verlorenes Budget las sich als unbegrenzt. Jeder Fehler bricht das Kind ab und lässt den Spawn scheitern.


- **Delegierte Aufgaben werden bei abgelaufenem Executor-Lease neu geroutet statt in einer Sackgasse zu enden** — eine verschickte Aufgabe, deren Executor-Lease ablief, schlug früher einfach fehl; jetzt kehrt die Zeile mit einem neuen Attempt in die Warteschlange zurück, der verdrängte Executor wird aus den Kandidaten entfernt, und gibt es keine Alternativroute, parkt die Wiederzustellung in `task_outbox`, bis genau dieser Knoten wieder da ist — statt ein falsches Endurteil zu erzeugen. Absolute Deadlines schlagen weiterhin das Retry-Budget: Eine Zeile jenseits von `deadline_unix` wird unabhängig von Restversuchen als abgelaufen abgerechnet, und eine gepinnte Aufgabe wird nie still auf einen Ersatzknoten umgeleitet (bf34652).
- **Jedes Wire-Urteil ist durch den Dispensations-Attempt gezäunt** — `task_accept`/`task_decline`/`task_cancel`/`task_resume`/`task_result` tragen `attempt_id` jetzt durchgehend: Ein Frame, dessen Attempt strikt älter ist als die aktuelle Dispensation der Zeile, ist das verspätete Echo eines vom Delegierenden selbst ersetzten Versuchs und wird verworfen (früher konnte ein Accept den neuen Attempt an sich reißen, ein Decline ihn zurück in die Warteschlange werfen, ein Dispensations-Cancel ihn töten). Menschliche Abbrüche bleiben baumweit (leeres `attempt_id` tötet, was immer die Zeile hält), während Ablauf-/Supersede-Befehle ihren Attempt benennen; eine geparkte `cancel_outbox`-Zeile behält ihren Geltungsbereich über Neustarts hinweg (Migration v55).
- **Ein erneut zugestellter Delegate darf nur eine Kopie ersetzen, die sein Absender upstream tatsächlich besaß** — der Ersetzungs-Frame verlangt nun, dass der Absender in der gespeicherten Kette vor diesem Knoten steht; damit ist die Lücke geschlossen, über die jeder Peer eine frische Attempt-ID prägen und fremde Task-Zeilen löschen (oder wiederbeleben) konnte. Die zu ersetzende lebende Kopie wird vorher kaskadiert abgeräumt — Runner gestoppt, Context-Reservierung freigegeben, Stand-Down downstream weitergeleitet — statt unter der neuen Zeile still entsorgt zu werden.
- **Gestrandete und ersetzte Runs können keine Urteile mehr auf rotierte Zeilen schreiben** — die runner-seitigen Complete-/Fail-/Pause-/Review-Schreibzugriffe sind Attempt-CAS-gesichert (`CompleteAttempt`/`FailAttempt`/`Pause*`/`Review*`), die Retry-Schleife tritt zurück, sobald der Attempt der Zeile an ihr vorbei ist, und die Stranded-Run-Bereinigung rührt nur Running-Zeilen an, die genau dieser Run beansprucht hat.
- **Verwahr-Abläufe und Sweep-Urteile binden die Dispensation, die sie verurteilt haben** — das Expiry-Settlement des Lease-Monitors überspringt jetzt eine Zeile, die zwischen Scan und Settlement rotiert ist (der abgelaufene Lease verurteilt nur den gescannten Attempt; eine absolute Deadline wird auf der frischen Zeile neu geprüft und bindet weiterhin), geparkte `task_outbox`-/`resume_outbox`-TTL- und Bundle-Verify-Abläufe lassen nur den Attempt ablaufen, auf den die Verwahrung genommen wurde (`MarkExpiredAttempt`), Ablehnung/Hash-Mismatch/Speicherfehler eines veralteten Kontext-Fetches können die ersetzende Dispensation nicht mehr töten, und der Orphan-Sweep samt der `failLocal`-Pfade bei Dispatch-Fehlern tragen den Attempt, den sie beobachtet haben, statt zu töten, was immer die Zeile später hält.
- **Store-and-Forward-Verwahrung liefert nach einem Linkflattern in der richtigen Reihenfolge** — geparkte Cancels werden vor geparkten Delegates geflusht (das Stand-Down trifft immer vor der Wiederzustellung ein, die es ablösen sollte), ein geparkter menschlicher Tree-Cancel wird nie durch das Parken einer neueren Zustellung gelöscht, `task_outbox`-Zeilen erwecken keine terminierten/fehlgeschlagenen Arbeiten wieder, und ein neu gestarteter Daemon holt seine geparkte Verwahrung unter seiner stabilen Identität ab statt unter der verstorbenen Instanz-ID.
- **Delegierte Runs rechnen über den gemeinsamen Retry-Loop ab und liefern schlankere Output-Packs** — die drei executor-seitigen Ausführungspfade leiten ihr Ergebnis jetzt einheitlich durch `settleDelegated`, sodass Checkpoint-Wiederaufnahme, budgetierte Retries und das Decline nach upstream für delegierte wie lokale Arbeit gleich ausfallen; per Context bzw. Artifact wiederaufgenommene Runs declinen mit dem geparkten Attempt statt mit dem, den die Zeile später trägt; und Output-Packs überspringen regenerierbare Verzeichnisse (ein gemessenes 389-MB-Ergebnispaket schrumpfte auf 84,6 MB) (f53ddcf).
- **Die Restart-Recovery setzt das Überlebte fort und benennt den Blockierer** — unterbrochene Runs werden fortgesetzt statt von vorn gestartet, Agent-Wechsel-Fortschritt wird früh sichtbar, Projekt-Key-Matching ignoriert Groß-/Kleinschreibung, die Restart-Recovery zieht keine von Peers ausgeführten Zeilen mehr an sich, fremd gepinnte Warteschlangen-Tasks werden korrekt entpinnt, Exec-Lock-Wartezeiten melden, wer die Spur hält, und fehlerhaftes Adapter-JSON ist abgefangen (e0c7bec, 5044f4a).

- **Auch der Windows-Installer lehnt einen Downgrade ab** — `install.sh`, `panda install` und `panda update apply` lehnen ein Binary ab, dessen Migrationsobergrenze unter dem `user_version` des Datenverzeichnisses liegt; `install.ps1` kopierte das Archiv bedingungslos über das Präfix, sodass sich eine ältere Version über eine neuere Datenbank installieren ließ — zurück blieb ein Daemon, der beim Start stirbt und die Daten verschüttet. Jetzt wird das entpackte Archiv mit `panda version --json` geprüft, bevor das Präfix angefasst wird; `-Force` / `OPENPANDA_FORCE=1` deckt einen bewussten Downgrade ab.

- **Der Shell-Installer prüft die Release-Signatur, nicht nur die Prüfsumme** — `checksums.txt` kommt vom selben Ursprung wie das Archiv, SHA-256 konnte also nicht erkennen, wenn beides zusammen ersetzt wurde. `install.sh` prüft nun `checksums.txt.sig` mit demselben fest eingebauten Ed25519-Schlüssel, den der Selbst-Updater erzwingt: bei Abweichung bricht die Installation ab, und nur wo openssl kein Ed25519 kann (LibreSSL an Bord von macOS), bleibt es bei einer ausdrücklichen Warnung. `OPENPANDA_REQUIRE_SIG=1` macht «nicht prüfbar» zum Fehler.

- **`install.ps1` löst Versionen aus dem Repository auf, aus dem es lädt** — der API-Endpunkt war auf das Upstream-Repository festgelegt, während `OPENPANDA_REPO_URL` nur die Download-Basis verschob, sodass ein Fork oder Mirror ein Tag auflöste, das er nicht ausliefert.

## [0.0.12-preview] - 2026-10-19

Die v0.0.12-Vorschau — Codename **Constellation**: die Flotte als ein Himmel gezeichnet. Dieser Schnitt lässt Tasks desselben Projekts in Formation fliegen — delegierte Kinder und handverschickte Arbeit laufen parallel über deklarierte Pfad-Scopes und isolierte Worktrees, unter Delegationsgrenzen, die sich Hop für Hop verschärfen statt verwaschen zu werden — während die Konsole sich zu dem einen Ort konsolidiert, von dem aus diese Konstellation kommandiert wird: Warteschlange, Plan-Board und Projekte verschmelzen zur Control-Seite, die Workspace-Seite zeichnet die gesamte Flotte als Live-Topologiekarte und schießt Turns direkt in das gewählte Gespräch, und eine Profilseite beantwortet, wer dieser Knoten ist und wie beschäftigt er war. Mit einem laufenden Task zu reden wird erstklassig — eine Notiz einreihen oder die fliegende Runde steuern — ein parkender Langzeit-Task kann fortgesetzt werden statt nur angenommen oder abgelehnt, Kontextüberlauf erholt sich über adaptive Replay-Budgets, Ausführungs-Leases gelten prozessübergreifend, und der Modellkatalog zieht unter einer Token-Politik pro Modell auf die aktuelle Generation um — mit einer Härtungsrunde, die Node-Geheimnisse aus Artefakten heraushält, Nutzerdaten besitzerexklusiv macht und abgebrochene Agenten davon abhält, ihre Aufgabe zu überleben.

### Hinzugefügt

- **Geschwister-Tasks eines Projekts fliegen parallel — Pfad-Scopes und isolierte Worktrees** — delegierte Kinder eines Projekts serialisierten am monolithischen `project:<name>`-Lock, selbst wenn ihre Arbeit disjunkte Bäume berührte. Zwei Modi eröffnen jetzt echten Parallelismus auf einem Knoten: ein `paths`-Scope sperrt nur die deklarierten projektrelativen Verzeichnisse (`scope:<project>/<path>`), sodass disjunkte Geschwister den Worktree gleichzeitig teilen, während überlappende, Vorfahren-/Nachfahren- und undeklarierte Scopes weiter serialisieren; `isolate` gibt dem Kind eine private Kopie — bei einem Repo-Root ein detached git worktree auf HEAD, überlagert mit dem uncommitteten Delta (dirty, umbenannte, gelöschte, ungetrackte und ignorierte Dateien), sonst eine Kopie mit Skip-Set — die bei Erfolg drei-Wege zurückgemergt wird (Baseline-Manifest vs. aktueller Hauptbaum vs. Workspace), wobei beidseitig divergente Pfade als Konflikte gemeldet werden, die die Bytes des Hauptbaums behalten, und ein konfliktbehafteter Workspace aufbewahrt und an das Board des Elter gemeldet wird. Die Modi sind auf jeder Oberfläche erstklassige Nutzerwahl — `panda task add --paths d1,d2 | --isolate`, dieselben Flags am REPL-`/task add` und ein Parallel-Modus-Selektor im neuen Task-Formular der Konsole — mit Kanban-Badges, einem Lane-Streifen über der Queue, der aufleuchtet, sobald zwei oder mehr Tasks wirklich gleichzeitig laufen, Eltern-Links in der Detailseite und dem REPL-Protokoll, und Lane-Prompts, damit ein gescopter Lauf hört, welche Verzeichnisse er besitzt. Ein scoped/isolate-Anspruch, der nicht bedeuten kann, was er sagt (kein aufgelöstes Projekt, beide Modi zugleich), wird auf jeder Oberfläche abgelehnt, statt still zu einem Ganzbaum-Anspruch zu degradieren. Delegation selbst ist jetzt End-zu-End begrenzt: `delegation.{enabled,max_children,fan_out,max_depth}` in der Config (`panda config delegation`), Tiefe und Obergrenze reiten auf `TaskDelegatePayload`, wobei die engste Grenze jeden Hop überlebt — ein permissiver Forwarder kann sie nicht reinwaschen — und anonyme Tasks sperren `task:<id>` statt eines globalen Agent-Schlüssels, sodass unabhängige Arbeit nicht mehr hinter einem Lock wartet, den sie nie teilte (d476a7d, 6a5ca17, bfc95ac, 93bcdc4, 50c24a3).
- **Mit einem Task im Flug reden: Notiz einreihen oder die laufende Runde steuern** — `panda task send <id> -m …` legt eine dauerhafte Board-Notiz ab, die in der nächsten Supervisionsrunde in die Intent des Agenten gefaltet wird — nichts wird unterbrochen, ein wartender Task liest sie in seiner ersten Runde — und `task send --inject` geht weiter: die Notiz wird als steer-grade markiert, die fliegende Runde bricht ab und ihr Ergebnis wird verworfen (nie ein Fehlschlag), und der Text führt die Intent der nächsten Runde an, vor dem Follow-up des Supervisors — die Queue/Steer-Teilung, die Claude-Code- und Codex-Nutzer kennen. Zustellung ist End-zu-End Board-gestützt und neustartsicher, exactly-once über das Seen-Set der Runden-Schleife mit einem Slot pro Nachricht; ein Steer, der landet, während der Judge berät, gewährt eine weitere Runde statt den Task ungelesen zu schließen (gedeckelt auf vier Kulanz-Runden); ein prozessübergreifendes Senden degradiert ehrlich zur Zustellung an der nächsten Grenze, und ein Task auf einem anderen Knoten lehnt mit dem Namen des Executors ab — statt eine Notiz anzunehmen, die sein Agent nie sähe (5af3330, 2fb77da).
- **Ein in Review geparkter Task kann fortgesetzt werden, nicht nur angenommen oder abgelehnt** — ein mit `needs_followup` geparkter Task (das Budget der supervisierten Runden ging mitten in der Arbeit aus) hatte zwei Antworten; `panda task continue [-m NOTE]`, `/task continue` und `POST /api/tasks/{id}/continue` fügen die dritte hinzu: die Notiz des Operators landet als steer-grade Board-Nachricht, die Zeile kippt unter einem exactly-once-CAS von review nach queued, und der Daemon führt sie mit frischem Runden-Budget erneut aus, unter Wiederverwendung der persistierten Agent-Session und des Arbeitsverzeichnisses — genau das macht das Verb von einem CLI oder einer Konsole aus benutzbar, während der Daemon den Lauf besitzt. Die Detailseite zeigt Continue nur dann vor approve/reject, wenn das geparkte Ergebnis wirklich danach fragte (7ee6fd0).
- **Kontextüberlauf erholt sich im Flug** — das Replay-Fenster skaliert jetzt auf den vom bedienenden Modell beworbenen Kontext (3/16 davon in Zeichen, geklemmt auf 8K–160K — ein 128K-Modell landet exakt auf dem alten festen 24K), verdrahtet durch REPL, `ask --continue`, Session-Threads, RPC und die Konsole. Ein Agent-Lauf, der sein Fenster überläuft, wird einmal in derselben Runde wiederholt: Laufnotizen falten sich in ein vom Supervisor geschriebenes Digest (ohne es eine hart begrenzte Tail), der Resume-Handle und der gepoolte Session-Prozess fallen mit ihm, und der Prompt wird mit einem Viertel-Budget neu gebaut, mit auf Indexzeilen degradierten Skills; ein zweiter Überlauf parkt wie bisher zur Review, und die Tokens des gescheiterten Versuchs werden weiter berechnet (f4a64c6).
- **Ausführungs-Leases gelten prozessübergreifend** — eingehende Delegates, Inline-Submits und ein zweiter Core auf einer Datenbank umgingen die prozessinterne Run-Registry, sodass zwei Executoren überlappende Lanes gleichzeitig beanspruchen konnten; jeder Lauf fließt jetzt durch eine geteilte `exec_locks`-Tabelle, die unter `BEGIN IMMEDIATE` beansprucht wird (das eigene Worktree-Schlüsselset der Registry plus der aufgelöste Aktuator). Ein GC-Trigger gibt die Zeilen eines Tasks bei jedem Übergang aus den Live-Zuständen frei, und ein pro-Lauf-Nonce prädiziert jede Freigabe — ein spätes Unlock kann nur die eigenen Zeilen des Laufs fallen lassen, niemals die frischen Zeilen einer Re-Ausführung unter derselben Task-ID (c05b99e).
- **Modellfehler kommen klassifiziert, gezählt und mit einem Ausweg an** — ein 429/5xx oder ein totes Netz erreichte den Nutzer früher als rohes Provider-JSON nach bis zu ~2,5 Minuten stillen exponentiellen Backoffs, weil die Retry-Schleifen nicht sagen konnten, dass ein Retry unterwegs ist. Ein Retry-Hook meldet jetzt attempt/max, Delay und Status aus beiden Schleifen, die TUI-Statuszeile zählt den Retry herunter, und ein abgeregelter Fehlschlag rendert die klassifizierte Art samt dem begrenzten Provider-Detail und einer Hinweisliste hinter einer Falte (ctrl+e im TUI) — `ClassifyError` trägt strukturierte kind/status/detail-Felder, sodass kein Frontend Englisch kratzt, und ein nacktes „api status 429“ kann nicht mehr als Endfehler entkommen (dccf3a8).

- **Gleich teure Routen sind deterministisch und der Orbit-Trace stimmt mit der Entscheidung überein** —— drei Dijkstra-Läufe wählten den günstigsten Node in Go-Map-Reihenfolge, sodass eine gleich teure Route von Lauf zu Lauf zwischen Relays schwankte —— undurchsichtig für Traces, instabil für die Outbox-Verwahrung; Gleichstände lösen sich jetzt auf die kleinste Node-ID auf. Bei der Aufgabenprüfung steht der Grund für eine blockierte Genehmigung direkt neben der deaktivierten Aktion.

- **Die Lesespalte wächst auf 900px, und der Thread bekommt eine Karte** —— Transkript und Composer lagen in einem zentrierten 800px-Block, der die Antwort in einem breiten Panel zwischen zwei gleich großen Rändern schweben ließ. Beide sind jetzt 900px breit und bleiben zentriert: Antwort und Frage bilden weiter einen Block, die Frage an seinem rechten Rand, und die zusätzliche Breite nimmt an jeder Seite 50px weg. Eine Fragenleiste am rechten Rand des Panels setzt einen Strich pro Frage im Thread — der gefüllte Strich ist die Stelle, an der Sie gerade lesen, ein Klick springt zu dieser Frage zurück, und der Tooltip zeigt die Frage selbst.

### Behoben

- **Die Karten 节点 und 编排 schließt nur noch ihr eigener Button** —— beide hängen am Kopf, sind aber keine Menüs: man öffnet eine, um eine Maschine zu pinnen oder eine Aufgabe zu beobachten, und liest dann die Antwort dahinter weiter. Ein Klick außerhalb schloss sie, und die Regel dagegen musste die Flächen einzeln aufzählen, die nicht als „außen" galten — zuerst der Composer, dann Transkript, Prompt-Leiste, Sprung-nach-unten-Button, Diff-Schublade und Seitenleiste — und trotzdem verschwand die Karte mitten im Lesen, sobald man eine Zeile markierte oder einem Link folgte. Jetzt ist der Button im Kopf der einzige Klick, der eine Karte schließt; per Tastatur ist es Escape (ein Aufgaben-Detail schließt zuvor über sein eigenes ×). Eine über einem Thread geöffnete Karte übersteht alles, was man in diesem Thread tut.

- **Der Wechsel zwischen den Kopf-Karten verschiebt den Text nicht mehr** —— die Knoten-Karte reservierte 320px rechts der Lesespalte, die Orchestrierungs-Karte 380px, sodass jeder Wechsel Transkript, Composer und Sprungpfeil um 60px hin und zurück schob. Jetzt teilen sich beide eine 380px breite Spur, und die Knoten-Karte ist so breit, dass sie sie füllt (322px, weiterhin unter ihrem eigenen Button). Ein Wechsel ist damit ein Tausch an Ort und Stelle: gleiche Spaltenposition, gleicher 52px-Abstand zur Karte. Der Klick schließt die offene Karte auch nicht mehr zuerst — dieses Schließen-und-Öffnen setzte die Spur für einen Frame auf null, was die Spalte erzittern ließ.

- **`/api/self` startet nicht mehr bei jeder Anfrage einen externen Prozess** — CPU-Modell und Arbeitsspeicher wurden pro Aufruf ermittelt (unter Windows über die Shell, gemessen ~3 s), und der Identitäts-Chip der Seitenleiste liest diesen Endpunkt bei jedem Mount, sodass die Konsole für ihre eigene Identität Sekunden brauchte; die neue Profilseite blieb aus demselben Grund im Ladezustand. Die Ermittlung wird nun prozessweit gemerkt und nur für ein Feld wiederholt, das noch nicht geantwortet hat — ein einzelner Fehlschlag wird nicht zur Antwort für den Rest der Sitzung.

- **Das Herunterfahren des Daemons ist durchgehend befristet** —— abgekoppelte Artefakt-Übernahmen überleben ihren Ergebnis-Umschlag bewusst, und das Herunterfahren wartete ohne Frist auf sie: Eine hängende Übertragung konnte einen Stopp bis zum 30-minütigen Übertragungsbudget dehnen — weit über die Stopp-Zeitüberschreitung des Supervisors hinaus, dessen SIGKILL mitten im Entpacken genau das Ergebnis ist, das das Ablassen verhindern soll. Das Ablassen hält jetzt die Shutdown-Frist des Aufrufers ein und protokolliert, was beim Ablauf noch unterwegs war; Push-Eingabe-Pulls treten derselben verfolgten Gruppe bei, damit das Ablassen auch sie sieht.

### Behoben

- **Die Zusammenfassung einer erledigten Aufgabe wird nicht mehr mittendrin abgeschnitten** — die Konsole faltet das Ergebnis einer Aufgabe als einen Assistenten-Turn in den Thread, und dieser Turn war auf 800 **Bytes** begrenzt, verglichen mit `len()` statt mit einer Zeichenzahl: ein chinesisches Ergebnis endete nach rund 347 Zeichen auf einem `…`, das sich nicht aufklappen ließ, sodass eine fertige Aufgabe wie ein mitten im Satz abgebrochenes Modell aussah. Der Turn trägt jetzt die vollständige Antwort (und bei einer fehlgeschlagenen Aufgabe den vollständigen Grund). Der Deckel war unnötig: das Transkript liegt lokal und wird nur angehängt, und das Replay-Fenster begrenzt separat das History-Budget.

- **Web-Konsole: Die Modellauswahl beim Hinzufügen eines Modells öffnet sich wieder** —— das Feld nutzte `<input list="…">`, und der Browser filtert Datalist-Vorschläge nach dem bereits eingegebenen Wert: Der Katalog-Standard (z. B. `glm-4-plus`) war vorbelegt, sodass das Aufklappen nur diese eine ID zeigte — das Dropdown wirkte tot. Jetzt trägt das Feld seine eigene Auswahl: Ein Caret im Feld öffnet alle vom Anbieter zurückgegebenen IDs, die Auswahl wird direkt ins Feld geschrieben, und der Modellname erscheint nicht mehr in einem zweiten Steuerelement.

- **Die Antwortdauer überlebt ein Neuladen und läuft während des Turns mit** —— die Dauerzeile über einer Antwort wurde im Browser gemessen und am Transkript-Index abgelegt, verschwand also beim Neuladen des Threads oder beim Wechsel weg und zurück. Das Panel stempelt jetzt `duration_ms` auf jeden Assistenten-Turn (auch Fehler-Turns, und Task-Turns aus dem Start/Ende des Tasks selbst) und die Konsole liest es zurück, sodass ein wieder geöffneter Thread weiter sagt, was jede Antwort gekostet hat. Während ein Turn läuft, trägt dieselbe Zeile einen Live-Zähler, der jede Sekunde weiterläuft — die fertige Zahl landet in der Zeile, die sie schon besetzt hat.

- **Der Laufzeit-Scratch eines Workspace liegt in einem versteckten `.openpanda`** —— ein Work-Root, der nicht das Datenverzeichnis des Nodes ist, ist ein sichtbarer Workspace (ein übernommenes Startverzeichnis oder ein expliziter `storage.work_path`), und der Daemon legte seinen Scratch `tasks/`, `plans/` und `projects/` bisher genau dorthin. Alle drei stammen jetzt aus `<work_path>/.openpanda`, und ein Git-Workspace bekommt zusätzlich `.openpanda/` in `.git/info/exclude` —— der Status des Checkouts bleibt sauber, ohne die `.gitignore` des Nutzers anzufassen. Das Datenverzeichnis des Nodes behält sein Layout auf oberster Ebene, und Verzeichnisse älterer Builds bleiben stehen (sie könnten die einzige Kopie eines Deliverables sein) (10b6208).

- **CLI-State-Verzeichnisse sind plattformnativ** —— macOS legt sie in den Application-Support-Ordner, statt eine zweite `~/.local`-Wurzel durchs Home zu streuen, und Windows in `openpanda-data`, statt mit dem Installationspräfix `%LOCALAPPDATA%\OpenPanda` zu kollidieren, wo eine Deinstallation die CLI-Historie mitgenommen hätte. Eine einmalige Migration faltet die alte Unix-Wurzel an den neuen Ort, sodass eine aktualisierte Maschine ihre Historie behält (6d80afb).

- **Nachgestellte Flags verschlucken nicht mehr die Werte ihrer Nachbarn** —— der Schritt, der argv umsortiert (Flags vor die Positionsargumente hebt), zog eine handgepflegte Tabelle werttragender Flags heran; ein dort fehlender Flag wurde nackt nach vorn gehoben, sein Wert blieb unter den Positionsargumenten zurück —— die dokumentierte Zeile `panda pair --secret s --peer a` setzte das Secret auf `--peer` und endete in der Usage, `plan run p.yaml --priority high` las `high` als Plandatei, und `task artifact <id> --file f` übergab die Task-ID an `--file`. Jeder Befehl leitet seine werttragenden Flags jetzt aus seinem eigenen FlagSet ab, sodass die Tabelle nicht mehr von den Definitionen abdriften kann.

- **Unter Windows gepackte Artefakte entfernen keine Exec-Bits eines Checkouts mehr** —— ein Packer, der POSIX-Exec-Bits nicht ausdrücken kann, liefert jede Datei mit 0666, und das Auspacken eines solchen Baums über ein bestehendes Projekt ersetzte das 0755 jedes Skripts durch 0644: Ein echter Lauf ließ `git status` Dutzende 100755→100644-Wechsel melden. Eine Datei, deren Archiv-Mode keine Exec-Bits trägt, behält beim Landen die des Ziels — neue Dateien erhalten weiterhin den Archiv-Mode wörtlich, und ein Symlink am Pfad wird bewusst nicht herangezogen — neu übernommene Bäume bleiben ausführbar.

- **Benutzernotizen an eine Aufgabe tragen einen echten Zeitstempel** —— `PostUserMessage` ließ `sent_at` auf null, sodass jede mit `task send` oder per Inject gesendete Notiz auf `panda task board` als „vor ~57 Jahren“ erschien und aus der zeitlichen Sortierung fiel. Die Notiz stempelt jetzt die Sendezeit wie jeder andere Board-Beitrag.

- **Sitzungsprotokolle, Speicherdateien und installierte Skills sind jetzt nur noch für den Eigentümer lesbar** —— Sitzungsprotokolle, der Speicher (`MEMORY.md`, Tagesprotokolle, `DREAMS.md`), die vom Skill-Hub installierten Kopien und der Zustand ringsum wurden mit 0644/0755 im Datenverzeichnis des Nutzers angelegt und waren für jedes andere lokale Konto lesbar — obwohl ein Protokoll wörtlicher Nutzertext ist und regelmäßig eingefügte Geheimnisse enthält. Neue Dateien landen jetzt mit 0600, Verzeichnisse mit 0700, und ein bereits vorhandenes Sitzungsverzeichnis oder Tages-/Traumprotokoll wird beim nächsten Zugriff nachgezogen — dieselbe Haltung, die der Konfigurationsspeicher schon hatte.
- **Die Artefakt-Extraktion lässt sich nicht mehr aus ihrem Ziel herausführen** —— das Entpacken folgte symbolischen Links, die schon vor dem Öffnen des Archivs am Ziel lagen, sodass ein Archiv (oder ein bereits vorhandener Link im Projekt) die Schreibzugriffe eines Members an jeden Ort umleiten konnte, den der Daemon erreicht; jede Vorfahr-Ebene im Pfad eines Members muss jetzt innerhalb der Zielwurzel aufgelöst werden, während im Archiv mitgelieferte Links weiterhin nach innen zeigen dürfen. Die Eintragszahl ist gegen Inode-Fluten begrenzt, und Berechtigungskorrekturen überspringen Symlink-Ziele, statt durch sie hindurchzuschreiben.
- **Befehle lehnen überzählige Argumente ab, statt sie zu ignorieren und trotzdem zu laufen** —— ein übrig gebliebenes Wort nach einem Befehl ohne Positionsargumente (ein vertipptes Unterkommando, ein hinter dem falschen Befehl eingefügter Pfad) verschwand früher in `fs.Args()`, und der Befehl lief, als wäre es nie da gewesen. Befehle ohne Positionsargumente geben jetzt die beanstandeten Argumente samt Nutzungszeile aus und beenden sich mit Exit-Code 2, sodass ein vertippter Aufruf korrigiert wird, bevor seine Nebenwirkungen greifen.
- **Der Ordner-Picker der Konsole hängt nicht mehr und löst `~/` auf** —— ein offen gelassener nativer Dialog blockierte die Handler-Goroutine des Pickers, und jeder weitere Klick stapelte ein weiteres osascript/zenity/PowerShell dahinter; der Aufruf trägt jetzt ein Zeitlimit von 5 Minuten, mit dem auch der Helfer beendet wird. Die Verzeichnisauflistung löst Pfade zudem so auf wie das Datei-Browsen, sodass `~/projects` im Picker das Home-Präfix expandiert, statt als wörtlicher Pfad zu scheitern.
- **Ein sondierender Relay verurteilt den Agenten dahinter nicht mehr** — eine Probe-Deadline wurde wie eine Ablehnung behandelt, sodass ein Endpoint, der hinter seinem eigenen Upstream-Kontenpool wartet — Claude Code hinter cc-switch, einmal 200 in 3–6 s, im nächsten Moment 18–40 s — für die Failure-TTL aus der Rotation fiel, während die allernächste Anfrage gelang. `ProbeVerdict` trägt jetzt einen `Unknown`-Grad, der nur für eine Deadline gesetzt wird; ein Rate-Limit wird nicht mehr als Credential-Ablehnung gelesen, und ein langsames Relay bekommt Raum zu antworten, bevor das Urteil fällt (f1e903f, 5c16c85, b1e5a07).
- **Eine fehlgeschlagene Runde bringt ihren Grund nach Hause** — drei Stellen warfen weg, warum ein Task starb: der claude_code-Adapter ritt zehn exponentielle Backoffs bei anhaltendem 429/529 aus und emittierte dabei nichts, was der Silence-Watchdog lesen konnte — ein Rate-Limit wurde als Hänger getötet und die Arbeit ging ohnehin verloren; die Verdict-Zeile ließ die Ursache gleich mit fallen. Rate-Limits geben die Runde jetzt beim ersten Verdict auf statt den Backoff auszureiten, und der Grund der fehlgeschlagenen Runde erreicht Task-Record, Trace und Panel statt eines nackten „failed“ (efaba97).
- **Wartende Arbeit hört auf, still zu totem Brief zu werden** — eine besitzende Engine (`panda web`, ein QueueTasks-REPL) heartbeatete ihre Node-Zeile nie und ging ~90 s nach Init stale — tot für Peers und tot für eine Consumer-Liveness-Sonde, die selbst nur prozesslokal war — sodass Enqueues und Board-Notizen wortlos verschwanden. Zeilenbesitzer heartbeaten jetzt, Consumer-Liveness befragt den Store, Sends gegen einen toten Store heben die Warnung, engine-lose Zustellpfade können keine Notiz mehr für einen Task annehmen, den ein Remote-Knoten besitzt, und Board-Nachrichten werden Hop für Hop unter Origin-Bindung weitergereicht, damit eine Notiz ihren Besitzer über die Teilmesh erreicht (ae08a10, 48326e2, 2fb77da).

## [0.0.11] - 2026-10-15 — "Rendezvous"

Das stabile v0.0.11 — Codename **Rendezvous**, das orbitale Treffen. Dieser Schnitt faltet die Vorschau-Linie — per-Session-AEAD im signierten Hello, Bluetooth-artiges Pairing, signierte Discovery-Beacons und stabile `k:<pub>`-Identitäten, harte Knoten-Pins über Multi-Hop-Routen, die Partial-Mesh-Datenebene, das Task-Nachrichtenbrett und das Git-Rollback für Agentenarbeit — zusammen mit den Neuerungen dieses Zyklus: Desktop-Knoten bekommen Computer-Use-Augen und -Hände (Bildschirmaufnahme und synthetisierte Eingaben als erstklassige Aktuatoren, unter POSIX wie auf einem Standard-Windows), Task-Ausgaben werden als gepackte Artifacts aus CLI und Konsole abrufbar, und Bildschirminhalte reisen durchgehend unter ihrer eigenen mesh-only-Vertrauensregel — über Delegation, Pushes, Pulls und eine Bildschirmstufen-Ausgabe, die als Eingabe der nächsten Stufe konsumiert wird.

### Hinzugefügt

- **Computer-use-Augen und -Hände** — zwei neue Referenz-Aktuatoren machen einen Desktop-Knoten für GUI-Arbeit nutzbar: `drivers/panda-screen` erfasst den Bildschirm (macOS `screencapture`, Linux grim/scrot/ImageMagick, Windows PowerShell) und wird als `hardware:screen_capture` beworben; `drivers/panda-input` synthetisiert Eingaben (cliclick+osascript / xdotool / ydotool / PowerShell — move, click, dblclick, type, key, scroll, pos) und wird als `hardware:gui_input` beworben, in Tier 2, weil Klicks und Tasten unumkehrbar sind. `DetectActuators` sondiert den mitgelieferten `drivers/`-Baum automatisch (`OPENPANDA_DRIVERS_DIR` ersetzt ihn exklusiv, danach PATH, dann das mitgelieferte Layout); `panda install` und Release-Pakete liefern die Treiber mit, und Aktuatoren mit `Interface:"desktop"` werden nur beworben, wenn plausibel eine GUI-Session existiert — Konsolen-Besitzer-Check unter macOS, `DISPLAY`/`WAYLAND_DISPLAY` unter Linux, Nicht-Services-Session unter Windows, `OPENPANDA_GUI_SESSION` zum Übersteuern — ein headless Daemon behauptet nie einen Bildschirm, den er nicht sehen kann. Der Routing-Prompt lehrt die Kette Erfassen → Verstehen → Bedienen.
- **Task-Ausgabeartefakte sind abrufbar** — das private Arbeitsverzeichnis einer Bare-Task wird jetzt gepackt und als Ausgabe-Artefakt registriert (der Screenshot eines Aktuators oder die Reportdatei eines Agenten stranden nicht mehr unter `work_path`; leere Verzeichnisse erzeugen nichts, gepinnte/Projekt-Verzeichnisse werden nie en bloc gepackt). Abrufflächen: `panda task artifact <id> [--list|--file <pfad>|--out <verz>]`, drei authentifizierte Panel-Endpunkte (`GET /api/tasks/{id}/artifact`, `/artifact/files`, `/artifact/file?path=`) und eine Konsolen-ArtifactSection, die das Manifest listet, Bilder und Text inline anzeigt und Einzeldateien oder das ganze Bündel herunterlädt. `artifact.Store` gewinnt `Entries`/`OpenEntry` — Manifest-Auflistung ohne Entpacken und Streaming einzelner Dateien mit Pfad-Traversal-Prüfung.
- **[Experimental] Screenshot-Tasks sind mesh-exklusiv** — Bildschirminhalte bekommen ein eigenes Vertrauensbit statt der üblichen Teilnehmerprüfung: `requires`/`action_spec`-Treffer auf `hardware:screen_capture` (einschließlich weiter Tokens wie `hardware:*`, die darauf auflösen könnten) markieren die Task; guarded Peers werden beim Senden gefiltert, Nicht-mesh-Ursprünge an der Admission abgelehnt (`trust_policy_refused`), und die Artefakt-Ausgabeseite gibt screen-gebundene Ausgaben nur an mesh-Peers heraus — weder Teilnahme noch signierte Grants können das aufweiten. Da eine vom Operator definierte `screen_sensing`-Aktuator-ID nur auf der Karte des Produzenten selbst klassifizierbar ist, stempelt der Executor beim Claimen eine persistierte `screen_output`-Marke (Migration v45), die auf `task_result` mitreitet, sodass jeder Delegator-Hop seine eigene Zeile nachstempelt; zwischengespeicherte Autorisierungsverdikte merken sich das Screen-Bit und prüfen den Peer-Tier bei jedem Treffer erneut — eine Vertrauensherabstufung unterbricht einen laufenden Transfer sofort. Die Ausgabe einer Bildschirmstufe, die der nächsten Stufe als Eingabe übergeben wird, behält dieselbe Bindung: der Orchestrator stempelt eine Herkunftsmarkierung auf den Eingabe-Ref, und ein Verbraucher von Bildschirm-Bytes ist selbst display-gebunden — sein Arbeitsbaum und damit sein produziertes Artifact können die Pixel enthalten — sodass die Markierung von Stufe zu Stufe weiterreicht. `network.trust.send.guarded.screen: true` ist der explizite Schalter für den Selbstbetreiber-Fall.
- **Windows-Computer-use-Einstiegspunkte** — `drivers/panda-screen.ps1`, `drivers/panda-input.ps1` und `drivers/panda-notify.ps1` bringen die Augen-/Hände-/Notify-Treiber auf einem normalen Windows-Knoten zum Laufen — gleiche CLI und Exit-Codes wie ihre POSIX-Geschwister, kein git-bash nötig. Die Erkennung löst sie zu `pwsh -File <Skript>` auf (pwsh zuerst, das mitgelieferte PowerShell 5.1 als Fallback), und -File übergibt jedes Argument als literalen String an das Skript, sodass Text aus einer action_spec Text bleibt; .cmd/.bat-Wrapper werden bewusst nicht automatisch aufgelöst, weil cmd.exe seine Kommandozeile nach eigenen Regeln parst und ein Argument mit `&`, `%` oder einem Anführungszeichen in einen zweiten Befehl zerfallen kann (golang/go#27199).

### Behoben

- **Signierter Update-Kanal schließt die letzten Lücken** — der offizielle Ed25519-Release-Schlüssel ist als Standard-`ReleasePubKey` einkompiliert, sodass jede Build `checksums.txt.sig` sofort verifiziert statt auf schlüssellosen Dev-Builds fail-closed zu verweigern; `OPENPANDA_UPDATE_UNSIGNED` ist das explizite Schlupfloch für selbst gehostete unsignierte Kanäle; `install-local` hält `~/.local/bin/panda` als Symlink in den Release-Präfix-Baum, damit `panda update` das Image austauscht, das der überwachte Daemon tatsächlich ausführt.
- **`panda-input` und BSD sed** — die Großschreibung des Tastennamens nutzte eine GNU-only-`sed`-Escape; unter macOS wurde `key up` zu `uup` verstümmelt. Jetzt explizite Fallunterscheidung.
- **Ein Windows-Knoten konnte keinen mitgelieferten Treiber bewerben** — die Sonde suchte nur die extensionslosen POSIX-Skripte: os.Stat meldet unter Windows nie ein Execute-Bit und LookPath kann eine Datei ohne Erweiterung nicht treffen, sodass ein Windows-Desktop-Knoten überhaupt keinen `hardware:*`-Aktuator deklarierte und das Computer-use-Paar faktisch nur unter macOS/Linux existierte. Die Auflösung ist jetzt plattformspezifisch (`.ps1`/`.exe` unter Windows, das nackte Skript unter unix) und die Karte trägt die Invocation statt eines nackten Pfads, sodass PruneUnavailableActuators genau das behält, was dieser Host ausführen kann.
- **Außerhalb des PATH installierte Agent-CLIs werden auch unter Windows gefunden** — die Fallback-Verzeichnisse von `InstalledBinary` waren Homebrew/usr-local-Pfade und die Ausführbarkeitsprüfung verlangte ein unix-Execute-Bit (unter Windows nie gesetzt), womit der ganze Fallback dort toter Code war; Verzeichnisse und Prüfung sind jetzt plattformspezifisch (`%APPDATA%\npm`, winget Links, scoop shims, cargo).
- **`panda-input key tab` / `key F5`** — die dokumentierten benannten Tasten wurden kleingeschrieben, bevor die Backend-Tabellen sie case-sensitiv abglichen: Tab und die F-Tasten starben unter macOS als "unknown key" und tippten über den Windows-Zweig literale Buchstaben. Die kanonischen Namen sind jetzt für beide Backends ausgeschrieben.
- **`panda metrics --runtime` meldet die Daemon-Last unter Windows** — die Zeile war dort nur Liveness (kein `ps`); RSS kommt jetzt aus GetProcessMemoryInfo, CPU/Uptime aus GetProcessTimes, wobei die CPU als verbrauchte Zeit ausgegeben wird ("cpu=4.2s") statt als Momentanprozentsatz, den eine einzelne Stichprobe nicht liefern kann.
- **Nacktes `panda --help` listet die neuen Task-Verben** — die oberste Usage nannte `task artifact` und `task board` nie (die `task`-Sub-Usage, die Shell-Completion und die READMEs schon), sodass der Artifact-Abruf allein über `--help` nicht auffindbar war.

## [0.0.11-preview] - 2026-10-14

Die v0.0.11-Vorschau — Codename **Rendezvous**, das Treffen auf der Umlaufbahn. Dieser Schnitt fasst die ganze Linie zu einem einzigen Vorab-Release zusammen: Peer-Verbindungen handeln pro Verbindung AEAD-Verschlüsselung im signierten Hello aus; Geräte treten dem Knotennetz bei wie beim Bluetooth-Koppeln — Gerät wählen, Code vergleichen, auf beiden Seiten bestätigen — statt Geheimnisse von Hand zu kopieren. Arbeit wird zwei Hops weit auf Knoten gepinnt, aufgelöst über die per Gossip verteilte Topologie, während Contexts und Artefakte Hop für Hop weitergereicht werden; Geschwister-Stufen desselben Plans tauschen jetzt kurze Notizen auf einem begrenzten Nachrichtenbrett aus, statt auf das Endergebnis zu warten. Agentenarbeit auf echten Checkouts ist rückgängig machbar — `panda task revert` stellt die Git-Baseline vor der Aufgabe wieder her. Vertrauensstufen verengen, was ein nicht vertrauenswürdiger Peer tragen darf, und der Lebenszyklus einer Aufgabe meldet in jeder Phase ehrlich, wo sie steht. Diese Vorschau wurde Ende-zu-Ende auf einer echten Drei-Geräte-Flotte (macOS ↔ Windows ↔ Linux SBC) durchgespielt, einschließlich Node-Kills mitten im Lauf, Reconnects und Replay. (Die Alpha/Beta-Linie lief als *Periapsis* — zurückgezogen, weil dieser Name bereits v0.0.9 gehört.)

### Hinzugefügt

- **[Experimental] LAN-Kopplung im Bluetooth-Stil** — `panda pair` entdeckt Geräte im LAN, beide Seiten zeigen denselben kurzen Code, beide bestätigen, und die Geräte treten dem Knotennetz bei; kein Kopieren von Geheimnissen, kein Eintippen von Adressen. Unsignierte Beacons werden bei der Aufnahme abgelehnt, und per Umgebungsvariable übergebene Geheimnisse bleiben von der Platte.
- **[Experimental] Verschlüsselte Peer-Sitzungen** — jede Verbindung handelt einen AEAD-Schlüssel pro Sitzung (HKDF über das gemeinsame Geheimnis und beide Nonces) im signierten Hello aus. Alt-Peers fallen nur unter einer ausdrücklichen Richtlinie (`network.allow_cleartext_for`) auf Klartext zurück; Klartext-Dials über verschlüsselten Unterlagen werden abgelehnt.
- **LAN-Erkennung ohne Konfiguration** — Ed25519-signierte Discovery-Beacons (Replay-geschützt, Punch-Frames nur einmal verwendbar), stabile Knotenidentität unter `k:<pubkey>` und Auto-Dial für einen verifizierten Schlüssel über IP- und Instanz-Drift hinweg. `panda nodes` kennzeichnet signierte Beacons und warnt bei unsignierten.
- **Harte Knoten-Pins, Ende zu Ende und über mehrere Hops** — Plan-Stufen und Aufgaben tragen ihren Knoten-Pin durch Planung, Routing und Ausführung: Die Arbeit läuft auf dem benannten Knoten oder die Aufgabe scheitert mit ehrlicher Begründung — niemals still umgeleitet. `--preferred` und `node:`-Pins der Planungsphase werden über die per Gossip verteilte Topologie aufgelöst: Ein Knoten zwei Hops entfernt (nur in der Anzeige eines Online-Peers vorhanden) wird über den günstigsten angekündigten Weg geroutet, das Wire führt die Identität des endgültigen Ziels mit, und jeder Hop löst es gegen sein eigenes Verzeichnis neu auf. Ein Knoten, der bereits in der Delegationskette steht, lehnt die Schleife weiterhin ab. Ergebnisse erfassen den Ausführer und dessen Arbeitsverzeichnis, sodass „wo lief das" aus Queue, Karte und Ergebnis beantwortbar ist.
- **Datenebene für teilweise vernetzte Meshes** — Pointer-Context-Snapshots und Stage-Artefakte werden entlang der Delegationskette weitergereicht: Ein Executor, der nur den Knoten erreicht, der ihm die Aufgabe gegeben hat, holt sich Snapshot und Eingaben über diesen Hop; jeder Relay prüft vor dem Weiterleiten den Inhalts-Hash und die Absenderidentität (Artifact-Chunks gehen nur an ihre Abrufer, pro Offset dedupliziert), und veraltete Relay-Einträge werden aufgeräumt. Zwei-Hop-Pipelines und Pins sterben nicht mehr an „context source unreachable" bzw. „artifact not held" einen Hop vor den Bytes.
- **[Experimental] Nachrichtenbrett zwischen Aufgaben** — Geschwister-Stufen desselben Plans und ein Elternteil mit seinen delegierten Kindern tauschen mitten im Lauf kurze Notizen aus, statt auf das Endergebnis zu warten: Der Agent postet über das strukturierte `messages`-Ergebnis-Array oder die `PANDA_MSG`-Zeilenmarke; der Scope-Eigentümer löst Adressen (`stage:<id>`, `parent`, `children`, Mitglieds-Task-IDs und eindeutige Präfixe) gegen ein Register auf, das nur er hält, und verteilt an die Knoten der Mitglieder; empfangene Posts falten sich unter `[sibling board]` in die nächste Supervisionsrunde des Empfängers. Slots gibt es einen pro (Absender, Empfänger), sodass eine geschwätzige Aufgabe die anderen nicht verdrängen kann; ein Budget pro Episode dosiert das Posten (`messages.budget`, Standard 8); `panda task board <id>` inspiziert das Brett einer Aufgabe. Zustellung ist best-effort — das Slot-Modell macht eine verlorene Notiz durch den nächsten Post korrigierbar — und Posts, die Mitglieder außerhalb des Registers benennen (Absender oder Empfänger), werden als Scope-Drift abgelehnt.
- **[Experimental] Git-Rollback der Agentenarbeit** — Läufe auf echten Git-Checkouts bekommen einen Rückgängig-Punkt: Der gesamte Baum vor der Aufgabe (tracked und untracked) wird über einen Scratch-Index nach `refs/heads/panda-base-<id>` gesnapshottet, ohne Index oder Branch des Nutzers zu berühren; `panda task revert <id>` stellt ihn wieder her und fegt nach der Baseline erzeugte Dateien weg, verschachtelte Bäume eingeschlossen. Session-Merges landen immer mit `--no-ff` und notieren die Refs vor und nach dem Merge unter `refs/openpanda/`, sodass `panda session revert` sauber zurücksetzt oder — stehen darüber Commits — auf `git revert -m 1` ausweicht, und auf einem schmutzigen Checkout verweigert, statt die Arbeit des Nutzers zu verstricken. `session diff --stat` (und die Vorab-Prüfung von `session merge`) zeigen eine numstat-Zusammenfassung plus Markierungen für binäre/sensible Pfade (`.env`, Schlüsselmaterial), und die Web-Konsole zeigt dieselben Diff-Statistiken und ein Revert-Verb. `task delete` räumt die panda-eigenen Refs dieser Aufgabe ab.
- **Interaktive Aufgaben-Queue und Follow-up-Turns** — `/tasks` öffnet eine auswählbare Liste in Scheduler-Reihenfolge (Drag-Reihenfolge → Priorität → FIFO), die sich bei Abschluss-Watch-Events an Ort und Stelle neu zeichnet, ohne den Cursor zu verlieren; Enter auf einer beendeten Aufgabe, `/task followup <id>` oder `panda task followup <id>` füttern ihr gespeichertes Ergebnis als echten Streaming-Ask-Turn zurück ans Modell — der Prompt trägt Identität/Status der Aufgabe und ein runen-begrenztes Ergebnis-Digest. Abschluss-Benachrichtigungen zeigen auf das Follow-up-Verb und schließen die Schleife einreichen → Queue → weiterfragen.
- **Bedienbare Memory-Konsole** — Einträge in USER.md, MEMORY.md, topics und projects filtern/bearbeiten/löschen/schnell anlegen über eine einzige geteilte Listen-Komponente; Tagebuchdateien lassen sich einzeln löschen oder auf Knopfdruck mit 30d/90d-Aufbewahrungsfenster prunen (Archivdateien sind nicht mehr ausgenommen); der Memory-Graph zeichnet evidenzgewichtete Kanten (Promotions-Marker und Erwähnungszählungen) mit Rad-Zoom, Drag-Pan, Pfeilen und Gewichts-Badges; und der Retriever rankt mit BM25-lite (IDF + Längennormierung) statt nacktem Token-Overlap.
- **[Experimental] Binäre Datenframes und begrenzte Queue-Lesungen** — der Bus handelt binäre Frames für den Artefakt-Transfer aus; Aufbewahrung abgeschlossener Aufgaben und begrenzte Lesevorgänge halten lange Historien günstig.
- **`timeouts.native_s`** — Wanduhr-Budget für einen einzelnen nativen Fähigkeits-Befehl; ersetzt den eingebauten Fünf-Minuten-Standard nur auf Executoren, die ihn beibehalten hatten. Ein explizit gesetztes Timeout pro Befehl wird vom globalen Regler nie aufgeweicht.
- **Sichtbarkeit von Transit-Knoten in den Verwaltungswerkzeugen** — `card_list`/`card_show` melden Geräte, die nur über ein Relay erreichbar sind („reachable via <peer>, two hops out"), damit das orchestrierende Modell nicht länger einen lebenden Zwei-Hop-Knoten als „nicht im Gerätenetz" einstuft und Arbeit ablehnt, die das Mesh routen könnte.
- **Live-Ausführungserzählung in der Konsole** — der SSE-Trace-Stream trägt nun das Agent-Aktivitätsset (Tool-Aufrufe, Denken, Fortschrittsnotizen, Nutzung, Fallback, Judge, Supervision, Ergebnis) mit gekappten Oversize-Payloads, und jede gelistete Aufgabe trägt einen `last_event`-Stempel, damit eine laufende Aufgabe beim ersten Rendern echte Arbeit erzählt statt eines nackten „running". Die Kanban-Live-Zeile, die Orbit-Pille und die Detail-Timeline lesen alle daraus.
- **Auftrags-Karte** — die Detailansicht rendert die Task-Spec (Ziel, Constraints, Umfang, Erfolgsdefinition) als lesbaren Brief statt sie in `spec_json` zu verstecken.
- **Konsolen- und Sitzungs-UX** — Web-Kopplungsablauf und Knoten-Probe bei der Aufnahme, Härtung der Flottenseite, Pin-/Batch-Operationen in der Thread-Leiste mit Live-Sync, angepinnte Threads mit Massenlöschung und ein Sitzungs-Fingerprint im Änderungsfeed.

### Hinzugefügt — Vorschau der Trust Zones (weiterhin experimentell)

- **[Experimental] Trust Zones** — Einträge in `network.peers` können einen `trust:`-Tier tragen (`mesh` als Default = Verhalten vor dem Feature, `guarded`, `open`), pro Eintrag in der Config setzbar oder live über `panda nodes trust <id> <level>` (oder die stabile `k:<pubkey>`-Identität, die einem Knoten über Instance-ID-Wechsel hinweg folgt); `nodes add`/`nodes admit` akzeptieren `--trust`, `panda pair --trust` fixiert den Tier beim Beitritt (sowohl moderne als auch Altlast-`--secret --peer`-Pfade), das REPL spiegelt alle Verben, und die Knotenkarte der Web-Konsole trägt einen Tier-Auswähler (`POST /api/nodes/{id}/trust`, `k:`-Identitäten eingeschlossen), der zugleich die passenden `network.peers`-Einträge neu schreibt, sodass ein Config-Reload den alten Pin nicht wiederauferstehen lässt. `guarded` begrenzt, was die Delegation in seine Richtung tragen darf (Context gedeckelt auf Pull-Pointer, Projekt-Packs / Artifact-Eingaben / Zustimmungsgewährungen entfernt; Aufgaben, die ihren Pack oder ihre Eingaben verlieren würden, werden umgeroutet) und nimmt Arbeit an, die sie selbst ursprüngt, gemäß `network.trust.accept.guarded` (`auto` | `review` | `refuse`, optional mit einem werkzeuglosen `policy_llm`-Klassifikator, der die deterministischen Gates niemals lockern kann). Eine zur Prüfung geparkte Aufgabe hält den Lease des Delegierenden mit Fortschritts-Heartbeats (gedeckelt auf 24 h), damit langsame menschliche Entscheidungen nicht in ein doppeltes Umrouting ablaufen, und der Park wird nach einem Daemon-Neustart neu scharf gestellt. `open`-Peers liegen im Verzeichnis; auf jedem Knoten, der sie pinnt, können sie weder Push-Arbeit empfangen noch selbst welche auslösen — Vertrauen ist eine lokale, subjektive Aussage (ein Knoten, der sie nicht gepinnt hat, behandelt sie als Mesh, deshalb wird der Offer/Bid-Markt, für den sie existieren, nicht gebaut). Ein Peer-Schlüsselwechsel stuft einen Mesh-Pin zusammen mit dem bestehenden Verifikations-Reset zurück auf `guarded`.
- **[Experimental] Signierte Annahme von Aufgaben** — Executoren signieren `task_accept` mit ihrem Ed25519-Knotenschlüssel über (Aufgabe, Versuch, Signatursteller, Zeitstempel); Delegierende und Relays prüfen den eigenständigen Nachweis und verwerfen fehlerhafte, veraltete (>5 min Abweichung) oder schlüsselabweichende Frames. Unsignierte Frames von Peers vor dem Feature werden weiterhin akzeptiert.
- **[Experimental] Lokale Reputation im Routing** — `routing.reputation: true` rechnet die geglättete Erfolgsrate jedes Executors aus den `delegation_metrics` dieses Knotens in den DCPS-Score ein (Gewicht 0.1, Laplace-geglättet; Peers ohne Beobachtungen erhalten keinen Bonus). Standardmäßig aus.

### Behoben

- **Ein während eines Leitungsausfalls entstandenes Urteil konvergiert jetzt** — Endresultate, Abbrüche und Genehmigungen parken in dauerhaften Outboxes und werden beim nächsten Hello erneut zugestellt; ein Sweep beim Wiederverbinden stellt aktuelle Endurteile erneut zu, auch ohne Outbox-Zeile (ein in einen halbtoten Socket geschriebener Frame verschwand still und ließ den Delegierenden in `dispatched` zurück, bis ein Lease über ein Timeout log). Ein verspätetes `done` gleicht auch einen lease-abgelaufenen Fehler aus — belebt aber niemals eine menschlich abgelehnte Aufgabe wieder.
- **Der echte Daemon gewinnt seine Kante immer** — Hellos tragen ein Autoritätsbit, das nur der lockhaltende Daemon setzt, sodass er die Peer-Kante von einem streunenden Prozess gleicher Identität zurückholt; ein Daemon, dessen Listen-Port ein Streuner hält, wiederholt den Bind, statt zu sterben, und der Streuner tritt seine Mesh-Pflichten ab, sobald der Daemon den Knoten-Lock übernimmt.
- **Genehmigungen stranden nicht und lügen nicht** — eine akzeptierte Entscheidung wird auf die beim Peer geparkte Schwesterkopie gespiegelt; eine doppelte Genehmigung tötet nicht mehr die Kopie des Delegierenden; einwilligungsgeparkte Kopien konvergieren auf das Urteil des Ausführers; und eine geparkte Genehmigung wird als ehrliche Zustellungsquittung dargestellt, nicht als vom Modell erfundene „wartet noch auf Genehmigung".
- **Pläne werden bis zum Urteil verfolgt** — ein gestarteter Plan wird überwacht, bis jede Stufe sich setzt oder ein menschliches Gate erreicht wird; das Genehmigen einer geparkten Stufe tritt wieder in die Plan-Überwachung ein und zeigt das nächste Gate, statt den Turn beim Beleg einer Aufgabe zu beenden. Die Tier-2-Zustimmung einer Plan-Stufe wird jetzt ebenfalls über das Verdict-Gate des Aufrufers aufgelöst — `StartPlan` übersprang es vollständig, sodass Stufen mit `authorized=false` hinausgingen und eingeschränkte Executoren sie selbst unter `approval.mode: never` ablehnten.
- **Hängende Agenten sterben sichtbar** — der Stille-Watchdog tötet jetzt standardmäßig einen Agenten ohne Ausgabe für 240 Sekunden (`timeouts.silence_s`; `-1` deaktiviert das Töten), und ein periodischer Heartbeat meldet „agent still running", damit ein stiller Lauf nie für tot gehalten wird. Das Einstiegsmodell wiederholt außerdem einmal bei leerer Antwort, statt den ganzen Turn scheitern zu lassen.
- **Windows-Ausgabe kommt unversehrt zurück** — entferntes stdout wird von der Konsolencodepage des Ausführers (GB18030/ShiftJIS/EUCKR/Big5) transkodiert, sodass CJK-Ausgabe nicht mehr als Ersatzzeichen ankommt; die geplante Daemon-Aufgabe läuft über ein Wrapper-Skript, das `daemon.log` weiterrollt; Adapter dekodieren Subprozess-Ausgabe explizit als UTF-8 und pinnen UTF-8-Stdio mit MBCS-Fallback.
- **Delegation blockiert und doppelt nicht mehr** — der Eltern-Kind-Ressourcen-Deadlock ist gebrochen (ein Elternteil, das einen `project:`-Queue-Key hielt, während es auf ein Kind hinter demselben Key faltete, blockierte dauerhaft — live über 7 Minuten ohne Fortschritt beobachtet; solche Kinder werden jetzt als ausstehend annotiert statt erwartet), Kinder, die ein Agent während des Laufs erzeugt (`task add --parent-id $PANDA_TASK_ID`), werden jetzt in jeder Runde erneut aus den Task-Zeilen gefaltet, eine eingeschränkte Sitzung kann trotzdem fragen, der Plan-Sweep des Ausführers tötet keine delegierten Stufen mehr, und ein Zombie-Hello kann eine verdrängte Verbindung nicht wiederbeleben.
- **Kernel-Härtung** — Eigentum am geteilten Ledger und Artefaktgrenzen werden durchgesetzt, Consent-Grants signieren die endgültige Nutzlast, und Peer-Adressen werden vor dem Dial-Tie-Break gebunden, damit eine Aufgabe nie über eine unbestätigte Leitung geroutet wird.
- **Ablehnungen und Neustarts werden ehrlich gemeldet** — eine vom gepinnten oder vom fähigen Knoten abgelehnte Aufgabe meldete nur ein nacktes „no capability matches"; Ablehnungen zur Queue-Zeit scheitern jetzt mit der angereicherten Ablehnungsspur („declined by X (capacity full)"), und Zeilen mit Remote-Ursprung geben das echte Verdikt über die Kette weiter. Ein Executor-Neustart, der eine laufende Aufgabe als `failed` zurückholt, trägt die Ursache im `failed`-Feld des Recover-Events, und der Delegierende empfängt `interrupted` statt „task is failed". `task show` zeigt bei nie gelaufenen Fehlschlägen `✗ failed` statt `✗ exit 0`.
- **Stiller Bruch der Artifact-Kette** — dem Scheduler-Kern der Ask-Engine war kein Artifact-Pool angehängt, weshalb das Packen der Stufenausgabe leer zurückkam: Stufen meldeten done ohne `output_artifact`, und Nachfolgestufen liefen gegen leere Verzeichnisse. Der Pool wird bei der Engine-Initialisierung angehängt, und ein Packen ohne Pool schlägt jetzt laut an der Stufe fehl, die ihn besitzt, statt zwei Hops später.
- **Fest verdrahtetes Fünf-Minuten-Timeout für native Befehle** — langlebige native Befehle wurden nach 300 s abgeschossen, ohne Möglichkeit der Verlängerung. Konfigurierbar über `timeouts.native_s` (siehe Hinzugefügt).
- **Spekulative Artifact-Sonden als Fehler protokolliert** — die über das Ende des Fetch-Fensters hinausgehenden Lesezugriffe wurden auf dem bereitstellenden Knoten verweigert und mit WARN protokolliert; sie antworten nun mit dem leeren `EOF`-Marker, den der Client-Vertrag erwartet, sodass kleine Artifact-Abrufe still bleiben.
- **Umgebungs-Pack aus dem Home-Verzeichnis** — ein unter `$HOME` verankertes Projekt durchlief vor dem Erreichen des Größenlimits bei jeder Aufgabe den gesamten Home-Baum (`.Trash` ohne Berechtigung, Scan über Minuten). Solche Packs werden vorab abgelehnt, und Source-Packs beschneiden jetzt in beliebiger Tiefe credential-ähnliche Verzeichnisse (`.ssh`, `.aws`, `.gnupg`, `.kube`, …) und Dateien (`.env*`, `.netrc`, `id_*`-Schlüssel) — Home-ähnliche Verzeichnisse (`.config`, `.local`, `AppData`, `Library`) nur, wenn die Pack-Wurzel tatsächlich `$HOME` ist — während unlesbare Einträge im `pack_skipped` des Manifests landen, statt das gesamte Pack zu versenken.
- **Ehrlicher Agenten-Arbeitsbereich** — das Host-State-Masking verschluckte jede Agenten-Änderung (das Default-Layout legt `openpanda.db` in die Work-Root; `filepath.Dir(DBPath)` als host-owned zu markieren ließ den ganzen Snapshot unverändert aussehen, und korrekte Arbeit parkte fünf Review-Runden); `config.HostStatePaths()` zählt jetzt die Host-State-Dateien exakt auf. Anonyme Aufgaben liefen außerdem im Arbeitsverzeichnis des Knotens — die Ausgabe landete neben der lebenden Datenbank, und konkurrierende anonyme Aufgaben teilten sich ein Dateisystem; normale Aufgaben laufen jetzt in einem privaten `tasks/<taskID>`, Projektaufgaben ohne Eingaben im Arbeitsverzeichnis des Projekts, und verwaiste Workdirs werden erst eingesammelt, nachdem ihre Task-Zeile den Store verlassen hat.
- **Credential-Withholding über nicht vertrauenswürdige Kettenglieder** — eine über ein guarded/open-Glied zugelassene Aufgabe startete die Subprozesse des Agenten mit den Modellschlüsseln dieses Knotens und weitergeleiteten Adapter-Credentials im Environment — ein `printenv` entfernt vom Leck. `network.trust.accept.guarded.model_creds` (`withhold` als Default im Sub-Mesh, `provide` für mesh) unterdrückt Model-Env-Injektion, Credential-Forwarding und Auth-Failure-Retry-Injektion am einzigen Env-Assembly-Punkt, und das Urteil faltet sich aus der gespeicherten Kette, sodass Delegate, Resume, Push-Resume und Queue-Adoption alle übereinstimmen.
- **Unsignierte Updates werden abgelehnt** — ein Build ohne Release-Key akzeptierte checksum-only Updates, doch Hash und Archiv reisen über denselben Kanal, sodass nichts auf dem Draht sie verankert. `downloadRelease` schlägt jetzt geschlossen fehl, außer der Operator setzt `OPENPANDA_UPDATE_UNSIGNED` ausdrücklich.
- **Der Daemon überlebt Goroutine-Panics** — alle nackten Goroutines laufen jetzt über `guard.Go`/`guard.Call`: Ein Panic in einer Conn-Loop, einem Watchdog oder einer Spawn-Aufgabe riss bisher den ganzen Daemon mit einem unformatierten Stack nieder. Beim Durchfegen gefundene Fixes: Der cliui-Spinner band seine stop/done-Kanäle lazy (ein Pairing-Race über Start/Stop-Aufrufe hinweg), askengine las seine Listen-Adresse dort, wo ein Config-Reload sie hätte tauschen können, der ask-Worker von TUI/REPL liefert jetzt ein Fehler-Ergebnis statt die Pumpe aufzuhängen, und ein bus-writeLoop-Panic schließt die Verbindung.
- **Brett-Fälschung wird abgelehnt** — der Member→Owner-Post authentifizierte den sendenden Knoten, nicht aber die behauptete Task-ID; der Owner prüft jetzt vor dem Schreiben des Slots auch, ob der benannte Absender im Scope-Register steht, sodass ein erreichbarer Knoten nicht mehr unter der Identität einer fremden Aufgabe posten kann.
- **TUI-Composer-Stapelung** — `mainChatView` malte den Frame genau auf Terminalhöhe, sodass die letzte Zeile auf der untersten Bildschirmzeile landete; auf Terminals, die dort beim Schreiben scrollen, wanderte jeder Neuaufbau um eine Zeile nach oben — der alte Frame-Rest des Composers wurde nie gelöscht und stapelte sich den Bildschirm hinunter (#44). Der Frame wird jetzt eine Zeile kürzer gemalt, und die Hitboxen von Approval-Karte und Laufzeit-Fußzeile folgen der Zeile, die der Frame tatsächlich gemalt hat, statt ein bodenverankertes Layout anzunehmen.
- **Migrationen unter Connection-Pooling** — Migrations-Transaktionen pinnen jetzt eine dedizierte `*sql.Conn`; beim verbreiterten Pool konnte ein nacktes `BEGIN IMMEDIATE` DDL und COMMIT über Verbindungen verstreuen (SQLITE_BUSY / „no transaction").
- **Stille Content-Verlustpfade** — eine Antwort mit leerer Antwort aber nicht-leerer Notiz verwirft die Notiz nicht mehr; der Streaming-Delta-Guard spiegelt nun exakt die Erste-`{`-Entscheidung von `ParseOutput` (Lead-in-Limit, Illustrative-Marker, Fence-Behandlung); mittendrin unterdrückter Antworttext wird beim Flush restauriert, und Fallback-Notizen werden auch dann gedruckt, wenn der Stream nichts lieferte.
- **Web-Formatter-Feldmismatch** — `agent_usage` las `tokens`/`cost`, während der Draht `input/output/cache_*_tokens` trägt; Token-Tags summieren jetzt die echten Felder.
- **TUI-Frame-Korruption** — betitelte Box-Kanten spleißten Border-Runen in ANSI-Escape-Sequenzen; Titel werden jetzt über einer escape-bewussten Kante gerendert.
- **Stille Agenten-Substitution** — eine `agent:X`-Anforderung, die auf eine andere Harness zurückfiel, lief ohne jede sichtbare Spur; das Ergebnis nennt jetzt den angeforderten und den tatsächlichen Agenten.
- **Download-Erkennung im Approval-Gate vervollständigt** — der Download auf Platte deckt nun die Schreibweisen ab, die der `-o`-Flag-Scan übersah: Umleitungen (`curl url > file`), Pipe-Senken (`| tee file`, PowerShell `| Out-File`), Prozesssubstitution (`bash <(curl …)`) sowie `iwr`/`Invoke-WebRequest` — alle wie `curl -o` mit Tier 2 bewertet, während `make > build.log`, `2>&1`-Duplikate, `grep curl notes.txt` und die Nicht-Shell-Operatoren `=>`/`->` weiterhin Tier 1 bleiben.
- Ein `task_resume` vom Delegierenden auf dem Draht konnte eine zur Trust-Admission-Prüfung geparkte Aufgabe freigeben — also genau das Gate umgehen, das den Delegierenden prüfen soll. Admission-Parks tragen jetzt ihre eigene Disposition `admission_review`: Lokales `panda approve` nimmt sie wie jeden beliebigen Park vor der Ausführung wieder auf, Resume-Aufrufe auf dem Draht gegen sie werden jedoch mit der gehaltenen Verdict abgelehnt.
- Bei Reconnect wiederholt gepuschte Prüf-Verdicts tragen jetzt die typisierte Approval-Disposition. Ein `resume_execution`-Park, der den Delegierenden erreichte, degradierte bisher zur konservativen `accept_work`-Voreinstellung, nach der das echte Ergebnis des Executors die gespiegelte Prüfung nie mehr schließen konnte — die Kopie blieb stranded.
- Eine `task_accept`-Signaturprüfung, die den Signatursteller an den unmittelbaren Draht-Absender pinnte, verwarf gültige Annahmen, die über eine Multi-Hop-Kette weitergereicht wurden; der Nachweis wird jetzt gegen das geprüft, was er tatsächlich bindet (Aufgabe, Versuch, Signaturschlüssel, Zeitstempel).
- Der optionale Trust-`policy_llm`-Klassifikator-Aufruf ist begrenzt (15 s) und fällt geschlossen auf `review` zurück — ein festhängender Endpunkt kann die eingehende Nachrichtenschleife eines Peers nicht mehr einfrieren.
- Admission-Vertrauen faltet jetzt den am wenigsten vertrauenswürdigen Tier über die gesamte Delegationskette, sodass ein `open`-Peer keine Arbeit mehr über ein Mesh-Relay laundering kann, indem er in `chain[0]` einen Mesh-Ursprung benennt.
- `context_fetch` erzwingt nun auch auf der Abrufseite ein `summary`-Sende-Cap — ein Peer, der als unfähig deklariert ist, Snapshots zu halten, kann sie nicht mehr on demand abrufen. (`pointer` bleibt bewusst Pull-on-Demand: Es ist ein auditierter Transport-Tier, keine Geheimhaltungsgrenze.)
- `artifact_fetch` erzwingt das `inputs`-Cap auf der Abrufseite richtungsbewusst: Ein Anfragender, der in der Aufgabenkette unterhalb dieses Knotens liegt, wird unter `inputs: false` abgelehnt, selbst wenn er den Hash out-of-band erfahren hat, während ein vorgelagerter Delegierender, der die Ausgaben seiner eigenen Aufgabe abruft, nicht betroffen ist — dieser Lesezugriff ist eine Ausgabe, keine Eingabe.
- Eine `authorized=true`-Zustimmungsgewährung eines Nicht-Mesh-Ursprungs konnte auf dem Executor die uneingeschränkte lokale Werkzeugfläche erlangen — das „Ja" des Ursprungsnutzers stand ein für den Eigentümer dieses Knotens. `network.trust.accept.<tier>.foreign_consent` (`strip` als Default, `honor` für Knoten desselben Eigentümers auf nicht vertrauenswürdigen Segmenten) entscheidet, ob eine fremde Gewährung die Admission überlebt; aberkannte Aufgaben laufen eingeschränkt und parken ihre irreversiblen Schritte in der lokalen Prüfwarteschlange.
- `trust.NeedsOf` zählt `ContextType: "file"` nun als „braucht Eingaben", passend zu den Ableitungen auf Store- und Submit-Seite — eine Datei-Aufgabe kann nicht mehr ein Gate passieren und an einem anderen stolpern.
- Die Vertrauensauflösung faltet auch den konfigurierten Adress-Hinweis, wenn eine Zeilen-Pin existiert (am wenigsten vertrauenswürdig gewinnt in beide Richtungen), und die Reputation aggregiert über den belegten Ed25519-Schlüssel des Peers statt über dessen Instance-ID — ein neu gestarteter Knoten startet seine Bilanz nicht mehr auf null.
- **Signierter Update-Kanal durchgängig verdrahtet** — der fail-closed Updater oben wurde ohne Schlüssel-Infrastruktur ausgeliefert: Release-CI erhielt nie ein Signing-Secret, kein `checksums.txt.sig` wurde erzeugt und die Publish-Liste ließ es ohnehin aus — dieser Build lehnte daher jedes angebotene Release ab. `make package` läuft jetzt unter `OPENPANDA_REQUIRE_RELEASE_KEY` (fehlender `OPENPANDA_RELEASE_KEY` bricht ab statt zu warnen) und das Signatur-Asset wird veröffentlicht; `panda update` wählt außerdem für Lite-Builds die `lite-`-Assets per Build-Flag-Probe und lehnt Plattformen ohne Release-Artefakt vorab ab.

### Verbessert

- `timeouts.silence_s`-Semantik: ungesetzt oder `0` bedeutet jetzt den Standard-Kill nach 240 Sekunden (vorher: deaktiviert); `-1` deaktiviert das Töten und behält den Heartbeat.
- **SQLite-Schreibkonkurrenz** — dateibasierte Stores fahren einen 4-Verbindungs-WAL-Pool mit `_txlock=immediate` (In-Memory-Stores behalten eine Verbindung); Artefakt-Transfer-Wire-Handler cachen positive Peer-Autorisierungen eine Minute statt pro Chunk neu abzufragen, und die Push-Wasserlinie persistiert einmal pro Sekunde pro Transfer statt pro Frame.
- **Dedup-Kosten** — der Eingangsframe-Dedup-Key ist ein Struct (keine String-Allokation pro Frame) unter eigenem Mutex, abseits des Peer-Registry-Locks.
- **SSE-Trace-Stream startet am aktuellen Wasserstand** — ein Connect spielt nicht mehr die komplette Event-Historie ab; Hydration kommt von `last_event` und dem Task-Payload.
- **Konsolen-Designpass** — Kanban-Karten heben beim Hover mit Eintrittsanimation ab, Views faden ein, stille Buchhaltungszeilen rendern als dünne Linien, Changed-File-Chips filtern VCS-/Dependency-Rauschen und klappen ab zwölf ein, und Composer, Scroll-Button und Nachrichtenbubbles sind neu ausbalanciert.
- **Event-Zeilen-Faltung** — eine Folge von „no output"-Stille-Heartbeats kollabiert zu einer gezählten Zeile, und Tool-Aufrufe bekommen lesbare Argumentzusammenfassungen (ein opakes `{argc:3}` wird als „3 Argumente" gezeigt).
- **Datenschutz-Baseline für Source-Packs** — siehe „Umgebungs-Pack aus dem Home-Verzeichnis": Der Datenschutzfilter gilt nur für Source-Packs; Executor-Ausgabe-Packs liefern den Baum weiterhin unverändert zurück (ein von einem Lauf erzeugtes `dist/` oder `.env` ist das Ergebnis, kein Leck).
- **Workdir-Snapshots begrenzt und gehärtet** — der Pre-Task-Snapshot batcht seine Existenz-Prüfungen und markiert gestaged Gepruntes im Takt, meldet partielle Abdeckung (`files_truncated`) und überspringt das Drift-Intercept auf einem gekürzten Diff; das Markdown-Rendering der TUI wird über Frames hinweg gecacht.

## [0.0.10-preview] - 2026-10-06

Das v0.0.10-Preview — Codename **Apoapsis**, der fernste Bahnpunkt: die Linie, die vom Kern hinaus in das LAN um den Knoten und an die Hardware am Rand reicht. Knoten entdecken sich im LAN gegenseitig mit fingerprint-bestätigter Aufnahme und können die Schlüssel des anderen von Hand pinnen; delegierte Datei-Tasks tragen ihren Worktree zum Executor und bringen das Ergebnis zurück; ein blockierter Agent kann dem Nutzer eine Frage stellen statt zu raten; und Tasks können physische Aktoren — Servo, Mikrofon, Kamera, Notify, serielle MCU — auf dem Knoten ansteuern, der die Hardware besitzt. Darunter hat sich der Vertrauensboden gehärtet: `task_events`- und `audit_log`-Zeilen tragen Ed25519-Signaturen und werden gegen den Schlüssel dieses Knotens verifiziert, entfernte Agentenläufe ohne Consent Grant werden auf read-only Werkzeuge geklemmt, Klartext-`ws://`-Dials außerhalb verschlüsselter Underlays werden verweigert, und der Updater kann eine Out-of-Band-Release-Signatur verlangen. Auch die Steady-State-Kosten sanken: Idle-WAL-Schreibungen sind change-gated, Queue und Reminder-Scanner gehen bei Leere in den Leerlauf, Capability-Matching allokiert nichts, und die Artifact-Ebene poolt ihre Chunk-Buffer. Über die Aufmacher hinaus: das Entry-Modell kann jetzt das Live-Web suchen und lesen (web_search/web_fetch), `sandbox.mode` legt jeden gespawnten Subprozess in ein OS-Deny-Default-Profil, das Adapter-Wire wächst zu v2 mit Sessions und typisierten Transkripten, das Scheduling liest gemessene Kapazität (mit `nodes drain`-Wartung und `--nodes`-Fan-out), und die Web-Konsole bekommt ein Light-First-Redesign.

- **Konfigurierbares Modell-Retry-Budget** — `model.max_retries` ersetzt das hartkodierte Transport-Retry-Budget (fehlend/0 behält den Default 5, negativ schaltet Retries ganz ab); der Backoff pro Schritt ist auf 30 s gedeckelt, sodass ein tiefes Budget wartet statt busy-loopt, und der Knopf taucht im Web-Settings-Modelformular, den Panel-Modell-Endpunkten, `/model add --retry` und `config.example.local.yaml` auf.
- **[Experimental] Live-Kapazitätsmetriken, Drain-Modus und Named-Node-Fan-out** — Heartbeats tragen jetzt gemessene mem-free/disk-free/GPU-util-Samples (`-1` = ungemessen, gegen korrupte Werte geklemmt) und annoncieren Queue-Tiefe neben der In-Flight-Zahl; das Scoring diskontiert Effizienz nach gemessenem Speicher-Headroom und das Routing droppt Knoten mit fast vollem Arbeits-Disk hart — nur Messdaten, ungemessene Peers werden nie ausgeschlossen. `panda task add --nodes` fächert einen Task auf benannte Knoten (je eine gepinnte Kopie) und aggregiert das Ergebnis pro Knoten, und `panda nodes drain [--off]` schreibt ein Shared-Settings-Flag, das der laufende Daemon aufnimmt: Heartbeats sagen "draining", eingehende Delegates werden abgelehnt, In-Flight-Arbeit läuft zu Ende.
- **Stable-Identity-Outbox-Custody** — Outbox-Custody schlüsselte auf die Instanz-ID, sodass ein neu gestarteter Peer, der unter neuer ID re-hellote, seine geparkten Results, Cancels, Bundles und Artifact-Pushes bis zum TTL verwaiste; Custody schlüsselt jetzt auf die authentifizierte Ed25519-Identität (`k:<pub>`, durch den signierten Hello gebunden) mit `task_id` als Operations-ID, alle vier Outbox-Tabellen persistieren unter dem Stable-Key, Flush beansprucht die Vereinigung aus Stable-Key und jeder je gesehenen Instanz-ID, und Bundle-`DestEID` trägt den Stable-Key, der über das Directory zur aktuellen Instanz aufgelöst wird.
- **Repository-Plumbing ist auf dem Worktree-Rückweg geschützt** — ein hash-korrektes, traversal-freies Archiv konnte trotzdem ein Top-Level-`.git` tragen, dessen Hooks und Config (die Credentials einbetten können) direkt auf dem Checkout des Nutzers landeten; `ExtractExcept` fügt ein First-Element-Skip-Set hinzu, sodass Adoption peer-gelieferte `.git`- oder `.panda-shadow`-Inhalte nie materialisiert (verschachtelte Treffer bleiben — das eigene `.git` eines vendored Checkouts ist legitimes Output), und übersprungene Einträge werden im Manifest gezählt und geloggt.
- **[Experimental] OS-Level-Subprocess-Sandbox (`sandbox.mode`)** — `security.Sandbox` bekommt echte Einschließung jenseits der Env-Filterung: `sandbox.mode: standard|strict` hüllt jeden gespawnten Subprozess — native Kommandos wie Agenten-Adapter — in den Deny-Default-Mechanismus der Plattform (sandbox-exec/seatbelt auf macOS, bubblewrap auf Linux, ehrliches No-op mit Startwarnung sonst). `standard` lässt Workdir und gewhitelistete Runtime-Verzeichnisse beschreibbar, alles andere EPERM, während `deny_write_paths` (db-Verzeichnis, memory, config, card, Artifact-Pool, `.panda-shadow`) selbst unter einem gewhitelisteten Elternteil geschützt bleiben; `strict` fügt Lese-Verweigerung der OS-Credential-Orte hinzu. `panda doctor` berichtet, ob ein Backend den Knoten wirklich einschließt.
- **Datei-förmige beschreibbare Mounts und ein geteiltes Protected-Path-Set** — nackte Credential-Dateien im `$HOME`-Wurzel (z. B. `.claude.json`) deklarieren jetzt über `WritableFiles` und werden unter Linux als Datei gebunden / unter macOS in das Writable-Set gefaltet, statt eines per Basename geratenen Inode-Typs, der das Falsche mountete und eine Schrottdatei auf dem Host hinterließ; die fest verdrahtete Deny-Liste des Daemons ist jetzt `commander.ProtectedPaths`, mit der Embedded-Engine geteilt, sodass ask/repl/web/voice-Sessions denselben Vertrag bekommen, `Options.ConfigPath` lässt die eigene Config-Datei der Engine ins Write-Deny-Set, und der Desktop-Keyring kommt in `SystemSecretPaths`.
- **Web-Konsolen-Refresh** — das Warm-Paper-Light-Theme ist jetzt die alleinige Quelle der Wahrheit in der Token-Ebene (dunkel bleibt über `[data-theme='dark']` und den `prefers-color-scheme`-Fallback verfügbar); fleet, memory und skills steigen zu gruppierten Top-Level-Routen auf, alte `#/settings?tab=*`-Links leiten um, der Chat-Composer und das Neue-Task-Formular exponieren Node-Auswahl, und eine Memory-Graph-Ansicht kommt hinzu. Der Onboarding-Terms-Schritt wächst auf zehn Abschnitte — Self-Hosted/No-SLA-Klarstellung, Third-Party-Modell- und Peer-Node-Bedingungen, AI-Output- und Professional-Advice-Disclaimer, Execution-Safety, Warranty und Liability — in allen fünf Sprachen.

### Verbessert

- **Akzeptanzkriterien erreichen den Executor** — `success_definition` und `constraints` des Specs werden in den Run-Intent gefaltet (`taskSpecEnvelope`), sodass das Agenten-Prompt aussagt, was "fertig" heißt, und der Supervise-Judge gegen dieselben Kriterien verifiziert statt nur Prosa zu benoten.
- **Per-Task-Ausführungskontrollen überleben Delegation** — `tools_policy` und `max_turns` zogen auf `entry.TaskSpecDetail` (das Struct, das in `spec_json` persistiert und über die Leitung geht); der Executor wendet sie via `commander.WithToolsPolicy`/`WithMaxTurns` an, und Adapter parsen `max_turns` aus dem Request-Envelope.
- **Roher Nutzer-Prompt über die Destillation hinweg bewahrt** — die ursprüngliche Anfrage wird beim Submit an den gespeicherten Intent angehängt und reist mit der Delegation, sodass Peers und Retries die Worte des Nutzers neben dem destillierten Intent des Entry-Modells sehen.
- **Idle-Schreibverkehr ist change-gated** — der Heartbeat schreibt die Self-Zeile nur neu, wenn sich die annoncierte Kapazität tatsächlich änderte (mit 30-s-Freshness-Floor, sicher unter dem 45-s-Liveness-Check und dem 90-s-Stale-Sweep), der 5-s-Neighbor-Refresh und die Residenz-Publish pro Beat sind jetzt Read-Compare-Write (`ledger.UpdateAdjacencyIfChanged`), und der Node-Fingerprint des Panels quantisiert `last_seen` auf die Minute, sodass ein Heartbeat kein "nodes changed"-Event mehr an jede verbundene Konsole schiebt. Die WAL-Schreibrate eines idle Knotens sinkt um grob eine Größenordnung.
- **Queue-Poll entspannt, wenn die Queue leer bleibt** — nach ~30 s ohne bereite Zeile stuft der Fallback-Poll des Schedulers von 400 ms auf 2 s (`queueIdleAfter`/`queueIdlePoll`); eine lebendige Queue und prozess-internes `Wake()` behalten die schnelle Kadenz, sodass nur wake-lose prozessübergreifende Abholung den langsameren Tail zahlt.
- **Reminder-Scanner idled auf leerem Board** — ohne anstehende Zeile entspannt sich das Scan-Intervall auf 60 s statt 15 s (Zeilen, die ein anderer Prozess hinzufügt, tauchen innerhalb dieser Schranke auf), während `Store.Add`/`AddEvery`/`Delete` jeden Scanner im selben Prozess wecken, sodass ein prozess-interner Reminder noch innerhalb einer Sekunde nach Fälligkeit feuert.
- **Offline-Peer-Reconnect-Logging wird gedrosselt** — ein toter Peer emittierte früher bei jedem Redial (~30 s Steady-State) einen `peer dial failed`/`punch offer failed`-WARN in LaunchAgents unrotierte `/tmp`-Logs; der erste Fehlschlag und jeder ~20. werden mit `consecutive`-Zähler geloggt, und eine Recovery-Zeile meldet, wie lange der Ausfall lief. Die `MaintainPeers`-Redial-Schleife der Panel-/Web-Engine folgt derselben Policy.
- **Change-gated Writes sind Single-Statement** — `HeartbeatIfChanged`/`UpdateAdjacencyIfChanged` lassen jetzt SQLites `WHERE … IS NOT …`-Gate entscheiden, ob sich die Zeile bewegt, sodass ein ruhiger Beat oder Neighbor-Tick ein no-op-UPDATE-Roundtrip ist statt SELECT plus bedingtem Write — und der Vergleich ist atomar mit dem Write.
- **Message-Dedup-Sweeps sind amortisiert** — `claimMsgID` ging bei jedem eingehenden Frame durch die gesamte `msgSeen`-Map (O(Kapazität) pro Nachricht auf einem heißen Mesh); Expiry läuft jetzt höchstens alle 30 s, was die Dedup nur konservativer, niemals schwächer macht.
- **Poll-Projektionen schleppen keine Payloads mehr** — der `ListReady`-Poll der Queue selektiert jetzt die sechs Spalten, die der Scheduler liest (`ListReadySummaries`), statt das spec/intent/result-JSON jedes queued Tasks, und die per-Sekunde-SSE-Fingerprints des Panels hashen dedizierte Stamp-Zeilen (`TaskStamps`, `ledger.NodeStamps`) statt voller Task- und Node-Zeilen.
- **Agenten-Prompts beginnen mit einem prüfbaren Ausführungsvertrag** — der Schluss-Rider ist jetzt verifizierbare Bullets in allen fünf Sprachen (lies die eigenen Quellen und Docs des Projekts vor dem Editieren, beweise die Success-Definition mit der eigenen Build-/Test-Konvention des Projekts bevor du Fertig meldest, fasse nur Dateien innerhalb des deklarierten Scope an, berichte die gelaufenen Kommandos und ihre Ergebnisse, nenne jedes Kriterium, das du nicht verifizieren konntest), ein `[execution context]`-Frame nennt Task, Projekt und Workspace-als-cwd vorn, und `spec.scope` wird neben den Erfolgskriterien in den Run-Intent gefaltet.
- **Steady-State-CPU und Allokationen sinken** — Capability-Matching tokenisiert on-the-fly ohne Allokationen (2709 ns/40 Allocs → 1619 ns/0 Allocs pro Kandidat), die Artifact-Datenebene borgt 1-MiB-Chunk-Buffer aus einem `sync.Pool` und schreibt kein `sent_through` mehr pro Chunk (das Ack des Empfängers entscheidet die Retransmission), der Session-Finalizer des Panels probt `task_events` einmal statt die Timeline jedes Tasks neu zu lesen, und `RouteAtP` überspringt die Seen-Map auf dem üblichen leeren-Chain-Pfad. `make bench` pinnt die Zahlen (Routing Match/Decision, Control- + 1-MiB-Frame-Codec bei ~86/184 MB/s, Dispatch-Dedup).

### Behoben

- **Peer-Adressen validieren die echte Wire-Grammatik an jedem Write-Pfad** — `nodes add`, REPL `/nodes add`, `pair --peer`, das `POST /api/nodes/add` des Panels und der Config-Load teilten sich nur einen nackten `net.SplitHostPort`-Check, sodass `punch:<id>`-Einträge auf einer Formalie durchrutschten, nicht-numerische Ports (`peer:smtp`) gespeichert wurden und erst zur Dial-Zeit still scheiterten, und die Fehlermeldung des Panels noch host:port verlangte. `config.ValidatePeerAddr` besitzt jetzt die Grammatik (punch:<node-id>, ws(s)://-URL, host:port mit numerischem 1–65535-Port) und jeder Entry-Point ruft sie.
- **Panel-Add-Node zeigt das Cleartext-Gate** — `POST /api/nodes/add` schluckte den Dial-Fehler früher in eine generische "not reachable"-Zeile; die Antwort trägt jetzt `cleartext_hint`, sodass die Konsole wie der CLI auf `network.allow_cleartext` (oder wss:// / punch:) zeigen kann.
- **MCP-stdio-Server sterben nicht mehr mit dem Request-Kontext** — Spawn und Handshake erbten früher den 30-s-Request-ctx des Aufrufers, sodass Settings-Änderungen den Server-Prozess töteten; das Kind überlebt jetzt den Request (`TestServerSurvivesSpawnContextCancel`).
- **Ask-Engine läuft auf modellosen Knoten** — `askengine.New` scheitert nicht mehr ohne konfiguriertes Modell; Ask-Pfade melden `ErrNoModel` lazy, sodass Edge-Knoten delegierte Arbeit ohne API-Key ausführen können.
- **Work-dir-Ableitung handhabt relative Wurzeln** — `stageWorkDir`/`attachedWorkDir`/`projectWorkDir` normalisieren die Wurzel mit `filepath.Abs` vor dem Traversal-Beweis; `NewCore`s `"."`-Default scheitert nicht mehr am Escape-Check (Regression, die delegierte Tasks auf gepushte Inputs parken ließ).
- **Test-Fixture-Pfade lösen neben ihren YAMLs auf** — die Storage-Pfade der `testdata/*.yaml` sind wie dokumentiert am Verzeichnis der Config-Datei verankert, und ein verirrter `testdata/testdata/`-Baum wird ignoriert/entfernt.
- **WebSocket-Ping-Periode ist geklemmt** auf einen legalen Bruchteil des Pong-Waits und verhindert Starvation bei falsch konfigurierten Keepalives.
- **Nur-Hardware-Knoten können ausführen** — `NewCore`/`ReloadCard` bauten den Commander-Router nur, wenn die Karte native-, agent- oder manual-Fähigkeiten hatte, sodass ein Knoten, dessen gesamter Capability-Satz Aktoren war (der Jarvis-Edge-Case), jeden zu ihm gerouteten Task als "no capability matches" ablehnte; Aktoren zählen jetzt zur Router-Erzeugung.
- **`{action}`-Platzhalter schlägt geschlossen fehl** — ein Treiber-Template, das `{action}` nannte, substituierte früher einen leeren String, wenn der Task kein action_spec trug (oder ein action-loses), und reichte dem Treiber ein leeres Verb; jetzt lehnt er ab wie ein fehlender `{param:<name>}` — die Unstimmigkeit wird gemeldet, nicht ausgeführt.
- **`action_spec` kann nicht auf einem Nicht-Aktor-Plan gestrandet werden** — ein Task, der ein auf `hardware:x` zielendes Spec trug, dessen `requires` aber zu einer normalen Ability auflöste, ließ das Spec fallen und lief den Intent als Shell-Kommando; das Run-Gate lehnt den Dispatch jetzt ab, und die Submission-Grenzen stellen das `target_actuator` des Specs an die Spitze von `requires`, damit `MatchActuator`s First-Match-Ordnung den beabsichtigten Aktor auflöst (`ledger.RequiresForActionSpec`, angewendet in `toTaskInput`, `task add` und `/task add`).
- **REPL `/task add --action-spec` akzeptiert echtes JSON** — `splitArgs` gruppierte nur doppelte Quotes, sodass die eigenen Quotes eines JSON-Payloads den Tokenizer mitten im Token kippten und gestripped wurden; einfache Quotes gruppieren jetzt ebenfalls, und `--agents` kombiniert mit `--action-spec` wird verweigert statt das Spec still zu verwerfen.
- **Discovery-Bind validiert seinen Port** — ein nicht-numerischer `network.discovery_addr`-Port passierte die `SplitHostPort`-Formprüfung und band dann einen ephemeren Socket, der Port 0 annoncierte; `net.ResolveUDPAddr` prüft ihn jetzt beim Start, und der `:7837`-Default lebt in einem `DiscoveryAddrOrDefault()`-Helper, den Daemon und eingebettete Engine teilen.
- **Event-Chain-Verifikation ist am Schlüssel dieses Knotens verankert** — `VerifyTaskEventChain`/`VerifyChain` verifizierten jede Zeile gegen den `sig_pub`, den sie trug, sodass ein Schreiber, der die Kette umschrieb, sie unter seinem eigenen Keypair neu signieren konnte und trotzdem passierte; Signaturen müssen jetzt vom Schlüssel dieses Knotens stammen, und sobald eine signierte Zeile existiert, muss jede spätere Zeile signiert sein — Signaturen vom Tail abzustreifen wird also erkannt. Relayed Consent Grants, deren Origin-Key unbekannt ist, werden weiter adoptiert (Verweigern würde jeden relayed Tier-2-Task lahmlegen), loggen jetzt aber laut.
- **Dedup-Eviction folgt der Expiry-Ordnung** — der `msgSeen`-Überlauf ließ ein beliebiges Viertel der Tabelle in Map-Ordnung fallen, was eine frische ID evicten und ihr Replay wieder zulassen konnte, während alte IDs überlebten; Oldest-First-Eviction heißt: ein Replay schlüpft erst durch, nachdem sein eigenes Dedup-Fenster ohnehin geschlossen hätte.
- **Permission-Tier-Klassifikator-Bypässe über Shells, Remotes und Stores geschlossen** — `TierFromCommand` sah nur den Binärnamen, sodass eine destruktive Payload in einer benignen mitreiten konnte; die eingebettete Kommandozeile wird jetzt extrahiert und klassifiziert — `find -exec`/`-execdir`/`-ok`/`-okdir`-Payloads, `ssh`-Remote-Kommandos und `-o ProxyCommand`, `parallel`s opaque Kommando-String, `tmux send-keys`/`screen -X stuff`-Keystroke-Injection in lebende Terminals — und die Verb-/Objekt-Lücken schließen ebenfalls: `systemctl`s Power-State-Familie (reboot/suspend/hibernate/isolate/firmware-setup), `pmset` sleepnow und geplante Power-Downs, `launchctl bootout`/`reboot` und Container-Zerstörung.
- **Self-Update installiert tatsächlich** — drei echte Defekte hinter dem Bericht: ein ephemerer Panel-Token wurde beim Exec-Restart neu generiert und ließ jede offene Konsole am Token-Gate stranden (der Token reitet jetzt via `OPENPANDA_PANEL_TOKEN` durch den Restart und bleibt per Env-Allow-List aus Task-Subprozessen draußen); ein service-verwalteter `panda daemon` behielt sein altes Image, nachdem sich die Binärdatei auf Disk änderte (`applyRelease` bittet jetzt den Service-Manager um Restart); und macOS-Archive werden mit `COPYFILE_DISABLE=1` plus xattr-Strip neu gepackt. `panda update --force` bei degradiertem Check druckt kein Phantom-`downloading v<current>` mehr — `--force` verzichtet auf den Newer-Than-Test, nicht auf die bekannte Release — der Updater bekommt einen begrenzten `http.Client` (30 s Metadaten, 30 min Assets), und das Panel erklärt den Post-Apply-Zustand.
- **Tote TUI-Kommandos und Shared-State-Races** — `/model`, `/sessions`, `/projects` mit Argumenten wurden von der Slash-Panel-Interzeption verschluckt (nackt öffnet weiter das Panel, Args erreichen jetzt exec); `/tasks watch` konsumierte sein `watch`-Token ohne es zurückzugeben, sodass das Live-Board nie startete, und seine 2-s-Repaints fluteten beim Exit das Transcript (nur der letzte Frame wird jetzt committet); `watchQueueTo` verdrahtete `i18n.Detect()` und ignorierte `/lang`. Multi-Chunk-Exec-Output panickte die ganze TUI — eine Value-Receiver-Kopie eines nicht-null `strings.Builder` detonierte beim zweiten Chunk und tötete jedes slash/shell-Kommando mit Streaming-Output (`/agents`, …) — das redundante Modell-Mirror-Feld ist gelöscht, die Ansicht rendert den mutex-akkumulierten Buffer.
- **Mesh-Transport-Stalls und Blackholes** — Antworten schauten nur auf `connFor`, sodass ein nur über eine gepunchte Datagram-Route erreichbarer Peer nie decline/result/ack-Antworten erhielt; `sendTo` ist jetzt der geteilte Pfad (conn zuerst, gebundener UDP-Endpoint danach, Outbox bei Fehlschlag). UDP-Routen tragen `udpHeard` und verfallen nach Stille — ein toter Endpoint "funktionierte" weiter, weil UDP-Writes beim Schreiben Erfolg melden: Sends wurden bestätigt, Outbox-Zeilen gelöscht und der Peer punchte nie neu; Keepalives refreshen nur bei exaktem Endpoint-Match. Die Inbound-Deadline refresht pro dispatched Frame, sobald die Conn gebunden ist (ein abgelehnter Hello verdient nicht mehr das 60-s-Fenster, ein langsamer Handler kann keinen gesunden Link aushungern), Heartbeat/Card-Broadcasts fächern concurrent aus statt dass ein verklemmter Peer alle anderen um je `writeWait` verzögert, der WS-Upgrader bekommt einen `HandshakeTimeout`, und UDP-Keepalives tauchen erst nach erfolgreichem AEAD-Open upstream auf.
- **Adapter-Wire-Decoding und Registry-Scoping** — `AgentResult.ExitCode` trug kein json-Tag, sodass das `exit_code` des Wires nie unmarshalierte und Adapter-Timeouts (124), fehlende Binaries (127) und malformed Requests (2) alle als exit 0 auftauchten — Retry-Klassifikation und Failure-Reporting korrumpiert; jedes `AgentResult`-Feld trägt jetzt explizit seinen Wire-Namen. Registry-Auflösung, die nur auf das Adapter-Skript schlüsselte, verwechselte jeden `generic.py`-Karten-Eintrag — ein Custom-CLI erbte zcodes Binaries, Credentials und Endpoint; `agents.Lookup(name, adapter)` verlangt jetzt beides.
- **Input-Boundary-Caps und Flags** — mutierende Panel-`/api/*`-Requests hatten kein Body-Limit (ein 16-MiB-`MaxBytesReader` wrappt jetzt POST/PUT/PATCH/DELETE); nicht-streamende Provider-Antworten lasen unbegrenzt (64-MiB-Cap); pfad-förmige Adapter-Namen (`../x.py`) werden schon beim Card-Write statt erst beim Spawn abgelehnt; `session_mode` meldet `session_dead` auf dem Ergebnis-Umschlag, sodass der One-Shot-Fallback nicht mehr gegen den async-`cmd.Wait`-Marker rast; und das Panel sendet ein striktes Same-Origin-CSP (`script-src 'self'`, keine Objects/Frames) für Nicht-Loopback-Exposition.
- **Aktor-Exklusion, Delegate-Parsing, Lease-Waits und State-Hashing** — zwei Treiber auf einem GPIO-Pin sind ein Fehler, kein Parallelismus: Queue-Resource-Keys mergen jetzt jede `hardware:*`-Requirement plus den Ziel-Aktor des `action_spec`, und `run()` nimmt am Execution-Point ein Per-Aktor-Mutex, sodass delegierte Accepts und Inline-Submits gleichermaßen serialisieren. `PANDA_DELEGATE`-Parsing toleriert pretty-printed Payloads und Markdown-Fences, sammelt jeden Request im Turn und dispatchet Kinder parallel mit Budget; Remote-Waits pollen den persistierten Lease, sodass die Beats eines erneuernden Executors ihn über die alte feste Deadline hinaus am Leben halten; und ein Worktree über dem Hash-Walk-Cap fingerprinted über gits eigenen Index (`HEAD` + Porcelain + gecappte Diff-Streams) statt den Oszillations-Check zu überspringen.

### Breaking Changes

- **Klartext-`ws://`-Dials werden verweigert, solange das Underlay nicht verschlüsselt** (5d06d37) — der Hello-Handshake beweist Mesh-Mitgliedschaft, authentifiziert aber danach nichts, sodass ein Netzwerk-MITM auf einer Klartext-Strecke die Task-Ebene lesen und einen gefälschten `task_delegate` injizieren konnte. `cleartextOK` gated jetzt ausgehende Dials: `ws://` zu einem nackten `host:port` passiert nur für Loopback und Tailscale (CGNAT 100.64.0.0/10, die fd7a:115e:a214::/48-ULA, `*.ts.net` MagicDNS), die auf einem verschlüsselten-oder-lokalen Underlay reiten; `wss://`- und `punch:`-Peers gehen durch. **Ein als schlichter LAN-`192.168.x.x:7836` konfigurierter Peer schlägt nach dem Upgrade beim Dial fehl** — auf `wss://` umstellen, über Tailscale tunneln, oder `network.allow_cleartext: true` auf dem wählenden Knoten setzen, um das frühere Verhalten auf einem vertrauenswürdigen LAN wiederherzustellen.

## [0.0.9] - 2026-09-25 — "Periapsis"

Das stabile v0.0.9-Release — Codename **Periapsis**. Für eine Einzelmaschinen-Installation ist es ein Komfort-Release: Genehmigungen lassen sich merken statt erneut zu beantworten, die CLI erklärt sich besser (ein Status, der sagt ob *dieser* Knoten läuft, eine leere Queue, die den nächsten Schritt vorschlägt, ein Erstlauf-Hinweis, Release-Notes, die der Updater ausgibt), die Web-Konsole attribuiert jede Antwort dem Agenten und Modell, der sie produziert hat, und pinnt Node-Liveness und Version in die Seitenleiste — und die TUI überlebt alltägliche Befehlssequenzen, die sie früher korruptierten. Für Flotten vervollständigt es die Linie, die die Beta eröffnete: eine authentifizierte Datagramm-Ebene mit NAT-Traversal, verschlüsselte DTN-Payloads, geplante Kontaktfenster, kryptografische Knotenidentität mit signiertem Consent, direkte Stage-übergreifende Artifact-Übergabe und ein Lite-Build für beschränkte Geräte.

### Hinzugefügt

- **Gemerkte Genehmigungen auf allen Flächen** — ein Tier-2-Prompt muss nicht mehr jedes Mal neu beantwortet werden: eine Entscheidung kann für die Session oder das Projekt gemerkt werden (einmalige Antwort bleibt Standard). Die Engine merkt sich Session-Entscheidungen, die Projektzeile trägt eine eigene Policy (Mode-Override + Standard-Scope + gemerkte Entscheidung, Migration V26), und ein gemerktes *Deny* kürzt mit einer Ablehnung ab statt erneut zu fragen. Der Scope wird dort gewählt, wo gefragt wird: die once|session|project-Zeile der Approval-Karte (Tasten 1/2/3, klickbare Zellen), `/approval` und `panda project approval` für die wirksame Policy, `panda ask`/`session ask` und ein Scope-Picker in den Queue- und Session-Ansichten der Web-Konsole — die auch geparkte Tier-2-Tasks zeigen.
- **Task-Aktivitäts-Heatmap** — ein Jahr täglicher Task-Zählungen als Raster im Willkommensbanner, per `/heatmap` im REPL und als `panda heatmap [--weeks N]` für Skripte; NO_COLOR/Dumb-Terminals bekommen eine Glyphen-Rampe, Nicht-Unicode-Konsolen ASCII-Zellen.
- **`panda agents test <name>`** — Diagnose eines installierten Agent-CLI in einem Durchgang: Credential-Herkunft, aufgelöstes Modell, Endpoint-Erreichbarkeit mit Statusdetail und Latenz; Flags `--json` und `--config`, nicht-null Exitcode, wenn der Agent unbrauchbar ist.
- **Execution-Attribution** — eine unauffällige Zeile `Agent (Modell) · Knoten` läuft durch die ask-Ausgabe (menschlich, JSON und Stream), REPL-Task-Blöcke, TUI-Turns und den Panel-Approve-Pfad (aus dem persistierten ResultJSON restauriert), sodass jede Antwort den Ausführenden benennt, der sie erzeugt hat. Die Web-Konsole trägt dieselbe Attribution in Session- und Detail-Ansichten, und die System-Versionskarte zeigt `v0.0.9 Periapsis` in vollem Gewicht.
- **Web-Sidebar-Node-Chip** — der Fuß der Konsolen-Sidebar zeigt jetzt den Namen dieser Maschine, einen Up/Down-Punkt und die laufende Version, einen Klick von der System-Ansicht entfernt; `GET /api/self` meldet außerdem den Release-Codenamen.
- **Dezentralisierte DAG-Runtime** — End-to-End-Ed25519-Knotenidentität: beim ersten Start wird ein persistenter Schlüssel geprägt, signierte Hellos (`PubKey`/`EdSig`, mit HMAC-Fallback, damit Meshs gemischter Versionen weiterlaufen; ein Peer-Key wird nur aufgezeichnet, wenn seine Signatur verifiziert — Migration V28), und signierter Tier-2-Consent: der Ursprungsknoten signiert `Authorized` mit AuthSig/AuthPub/AuthTs, der Ausführende verifiziert gegen den aufgezeichneten Key und verwirft gefälschte Grants (`consent:forged` im Audit-Log); das Grant persistiert in der Task-Zeile (Migration V29) und wird wörtlich auf Queue-Forwards und Decline-Reroutes neu ausgestellt. Stage-Outputs werden direkt übergeben: ein Artifact-Fetch trägt ein orchestrator-signiertes Grant, gebunden an plan/consumer/producer/hash, sodass der Produzent einen Consumer bedient, für den er keine Task-Zeile hat; Nachfolger adoptieren den Output sofort, während eine Hub-Replik im Hintergrund geholt wird, und der Input-Fetch fällt auf den Orchestrator zurück, wenn der Produzent nicht erreichbar ist. Dynamische Sub-DAGs: `panda task add --parent-id/--preferred`, die MCP-Tools `panda_subtask_spawn`/`panda_subtask_await` und `PANDA_TASK_ID`, das in Agent-Umgebungen injiziert wird.
- **DTN-Kontaktplan** — `network.contacts` deklariert geplante Übertragungsfenster pro Peer (ein [start, end)-Fenster plus optionale `period` und `rate_bps`), über Heartbeats und Capability-Summaries gegossiped und in `employee_cache.contacts_json` gespeichert (Migration V27). `scheduler.ContactNextHop` läuft einen Earliest-Arrival-Dijkstra über die Vereinigung von Live-Kanten und beworbenen Fenstern, sodass ein offline Knoten mit publiziertem Plan ein legitimer Custody-Zwischenhop ist — der Fall, den Live-Topologie-Routing nicht ausdrücken kann; Fenster, die den Transfer nicht fassen können, und Pfade, die nach der Bundle-Lebensdauer ankommen, werden beschnitten. Ohne jeden Plan fällt die Suche unverändert auf die Live-Topologie zurück, und ein beworbenes leerer Plan löscht den gecachten (ein fehlendes Feld eines älteren Knotens lässt ihn weiterhin unberührt).
- **UDP-Datagramm-Ebene (farsky-Track)** — `internal/bus/udp.go` ergänzt einen zweiten Transport: AES-256-GCM-versiegelte Envelopes und HMAC-signierte Punch-Frames auf einem geteilten UDP-Socket, Schlüssel aus dem Mesh-Secret unter Domain-Trennung abgeleitet, Limit 1400 Byte pro Datagramm. `network.udp_listen` nutzt standardmäßig den Port von `listen_addr` auf der Wildcard-Schnittstelle (jedes Datagramm ist authentifiziert, der Any-Interface-Bind legt also nichts offen, was das LAN nicht ohnehin sehen könnte); `"off"` deaktiviert die Ebene. `sendTo` bevorzugt weiterhin die WebSocket-Verbindung und fällt auf eine bestätigte UDP-Route zurück, wenn keine existiert.
- **NAT-Hole-Punching über das Mesh koordiniert** — `network.peers` akzeptiert `punch:<node-id>`-Einträge für nicht anwählbare Peers. Ein `punch_offer`/`punch_ready`-Paar läuft über die Live-Verbindung oder wird entlang des Link-State-Graphen weitergereicht (TTL-begrenzt, pro Hop neu umhüllt, Ursprung im `Src` des Payloads erhalten); danach sprühen beide Seiten signierte Punch-Frames auf die ausgetauschten Kandidaten, bis ein Ack das Pinhole bestätigt. Der gebundene Endpunkt wird eine UDP-Route, per 25-s-Keepalive gehalten und bei Verlust neu gepuncht.
- **Reflexive Adressermittlung ohne externe Abhängigkeit** — derselbe UDP-Socket beantwortet RFC-5389-Binding-Requests: jedes Mesh-Mitglied mit öffentlicher Adresse ist der STUN-Server der Flotte (`internal/bus/stun.go`, null Abhängigkeiten); `network.stun_servers` ergänzt externe Server nur für Deployments, die eigene betreiben oder ihnen vertrauen. Hello-Antworten tragen außerdem `you` — die vom Listener beobachtete IP — sodass ein NAT-gebundener Knoten seine öffentliche Adresse gratis erfährt.
- **Verschlüsselte DTN-Bundle-Payloads (v2)** — `bus.Bundle.Seal` verschlüsselt den Payload mit AES-256-GCM unter einem aus dem Mesh-Secret abgeleiteten Bundle-Domain-Key und bindet den signierten Header als Associated Data; `Open` entsiegelt v2 und verifiziert v1-Klartext-Bundles, Meshs mit gemischten Versionen funktionieren weiter. Relay-Custody speichert nur das versiegelte Blob — Zwischenhops leiten Ciphertext weiter, den sie nicht lesen können.
- **Lite-Build für beschränkte Geräte** — `go build -tags lite` / `make build-lite-linux-{amd64,arm64,armv7}` lässt die eingebettete Web-Konsole (der Panel-Endpoint serviert stattdessen einen kleinen Hinweis) und die Bubble-Tea-TUI weg, behält aber Daemon, Mesh, DTN, Queue, ask und den klassischen Zeilen-REPL — ein schlankeres Binary ohne die Frontend-Abhängigkeitskette für Raspberry Pi und reine CLI-Geräte. `install.sh --lite` wählt das `panda-<ver>-lite-<os>-<arch>`-Archiv und akzeptiert 32-Bit-ARM; die Deploy-Skripte verwenden es standardmäßig auf SBC-Klasse-Zielen.
- **Release-Codename** — `internal/version.Codename` benennt diese Linie „Periapsis"; `panda version`, `panda --version`, `/api/version` und die Systemansicht zeigen ihn an.
- **Queue-Verwaltungswerkzeuge für die Ask-Engine** — `taskq_approve` (Tier-2, damit das Modell kein Tor erweitert, durch das es gleich gehen will), `taskq_reject`, `taskq_clear` (Bereiche history/review/all) und Batch-`task_ids` für `taskq_cancel`; `taskq_list`/`taskq_show` annotieren die Approval-Disposition jeder Task, und `taskq_priority`/`taskq_move` verweigern das stille Umsortieren nicht gequeuter Tasks.
- **Multi-Harness-Tasks aus `task add`** — `panda task add --agents claude_code,codex` fächert eine Task auf mehrere Agenten-Harnesses auf: `parallel` (Vorgabe) setzt alle Stages gleichzeitig frei, `--mode serial` kettet jede Stage an das Ergebnis der vorherigen. Jede Stage fixiert ihr Harness per `agent:<name>`-Requirement und wird an den Knoten geroutet, der es wirklich hat — die vorhandene Plan/DAG-Maschinerie, ganz ohne YAML.
- **LAN-Freigabe der Web-Konsole** — `panda web --lan` bindet an alle Interfaces und zeigt pro erkannter LAN-Adresse eine teilbare Zeile `http://<lan-ip>:<port>?token=…`, damit ein zweites Gerät im Netz die Konsole direkt öffnet. Ein nicht-loopback `network.panel_addr` ohne konfiguriertes Token bekommt jetzt ein ephemeres — `/api/*` bleibt nie ungeschützt — statt den Start zu verweigern; dieselbe Regel bei `panda web`, REPL `/web` und dem Standalone-Sidecar.

### Verbessert

- **Hello bewirbt die Datagramm-Ebene** — `HelloPayload` trägt `udp_port`, die Antwort trägt `you` (die vom Peer beobachtete Quell-IP): der Listener lernt den Punch-Hinweis jedes verbundenen Peers, und jeder Knoten erfährt seine öffentliche Adresse ohne Konfiguration.
- **Bundle-Wire-Format v3: relative Lebensdauer** — das absolute `DeadlineUnix` des Wire-Bundles wird zu einem BPv7-artigen Paar (Erstellt, Lebensdauer): jeder Custody-Halter verankert die Frist neu an seiner eigenen Uhr statt der des Ursprungs zu vertrauen — was geparkte Bundles zwischen Knoten mit nicht synchronisierten Uhren korrekt macht. v1/v2-Bundles verifizieren weiter: der decodierte Raw-Slot wird für Signatur/AAD aufbewahrt, und ihre absolute Deadline wird nur für die Custody-Logik zu einer Lebensdauer normalisiert.
- **`panda init` sät das Mesh-Secret und kennt den Modellkatalog** — die generierte Config kam früher mit leerem `shared_secret` heraus (der WS-Listener lehnte dann jeden eingehenden Peer ab, bis jemand `pair`/`nodes add` lief); init prägt es jetzt von Anfang an. Das interaktive Modell-Menü enumeriert die Provider-Registry — denselben Katalog, den `panda model add` und die Web-Einstellungsseite anbieten — statt einer eingefrorenen Fünferliste ausgemusterter Defaults, respektiert NoAuth-Provider (Ollama überspringt die Key-Frage) und schreibt Provider/Context-Window/Max-Tokens neben den Endpoint. Unter `--defaults` werden die dokumentierten `OPENPANDA_MODEL_*`-Umgebungsvariablen in die Datei adoptiert.
- **`panda doctor` prüft die Netzwerk-Ebenen** — ein leeres `shared_secret` schlägt den Check jetzt fehl (es deaktivierte eingehendes Peering still, während der Daemon gesund aussah), und die Datagramm-Ebene meldet ihr Bind oder das absichtliche `udp_listen=off`.
- **Agenten werden vor dem Dispatch geprüft** — ein minimaler authentifizierter POST auf den aufgelösten Endpoint entscheidet, ob ein Agent-CLI dispatchbar ist: eine definitive Credential-Art von 401/402/403/429 lehnt ab, 5xx/Transport-Fehler markieren unerreichbar, ein anonymes 4xx zählt als lebendig. `AgentDispatchable` gated Matching, Execution und Capability-Werbung, sodass ein konfigurierter-aber-kaputter Agent keinen Plan mehr gewinnt und dann bei der Ausführung fällt.
- **Updates und Installationen lehnen ein Binary ab, das älter ist als das Datenverzeichnis** — `storage.LatestVersion` exponiert die Migrations-Decke des Binary und `panda version --json` meldet sie (plus das live `db_schema` des Datenverzeichnisses, wenn erreichbar); der Updater prüft das gestagte Binary vor dem Tausch, `panda install` lehnt eine Kopie mit älterem Schema ab, und `install.sh` prüft das heruntergeladene Archiv ebenso — ein Downgrade, das beim Start mit „schema version newer than binary" sterben würde, wird vorher abgelehnt (`--force`/`OPENPANDA_FORCE=1` für bewusste Downgrades).
- **Alltags-CLI-Politur** — `panda status` nennt das Node-Verzeichnis richtig (es hieß fälschlich „keine Tasks im Store") und sagt, ob dieser Knoten läuft oder je registriert wurde; die leere `panda queue`-Tafel schlägt den nächsten Schritt vor; die Kein-Modell-Nachricht zeigt auf `panda model add` oder die Web-Einstellungen statt auf ein yaml-Feld; der klassische REPL druckt einen Erstlauf-Hinweis, wenn keine Config-Datei existiert; `panda update apply`/`upgrade` geben die Release-Notes der gerade installierten Version aus; die Abschlusszeile von `init` nennt `doctor`/`web`/`panda` als nächste Schritte.
- **Einheitliche Versionsidentität** — `v0.0.9 Periapsis` wird identisch von `--version`/`version`, dem REPL-Willkommensbanner, dem TUI-Splash und der Lite-Startzeile ausgegeben — ohne Anführungszeichen, mit gleichem Gewicht — und der Web-Sidebar-Node-Chip trägt es ebenfalls.
- **Prozessübergreifende Queue-Abholung ~5× schneller** — Tasks, die ein anderer Prozess einreihte (`panda task add`, `panda plan run`, MCP-Submits), konnten bisher nur per 2s-Fallback-Polling des Queue-Schedulers entdeckt werden (der Wake-Kanal reicht nicht über Prozesse hinweg); das Polling ist jetzt 400ms, eingereichte Tasks starten spürbar früher, und das prozessinterne Aufwecken bleibt sofort.

### Behoben

- **Alle Tool-Calls einer Modellantwort laufen jetzt in derselben Runde** — die Engine führte pro Turn nur den ersten `tool_use` aus und notierte den Rest; ein Modell mit mehreren Queue-Operationen verbrannte so das ganze Tool-Budget mit Wiederholungen (der gemeldete „räum die Task-Queue auf"-Fehler). Native Antworten führen jetzt alle Calls aus und spielen sie als ein Assistant-`tool_use[]`- plus ein User-`tool_result[]`-Turn nach Anthropic-Protokoll zurück; DSML-Invokes laufen der Reihe nach und werden als Prosa zurückgespielt.
- **Der DSML-Parser akzeptiert die Formate, die DeepSeek tatsächlich ausgibt** — `<｜DSML｜>`-Varianten mit einfachem und doppeltem Pipe, locker gequotete Invoke-Namen und JSON-Argumentkörper lassen kein Protokoll-Markup mehr in die Antwort leaken.
- **Approval-Zustände legen ihre echte Semantik offen** — `approval_disposition` (accept_work / resume_execution / needs_changed_input) erscheint in `taskq_list`/`taskq_show`, im Task-API-Payload und in Queue-/Detail-Ansichten, die Approve deaktivieren, wo die Eingabe geändert werden muss; Tasks mit bereits produziertem Ergebnis sind nicht mehr von solchen ununterscheidbar, die auf Autorisierung warten.
- **`Approve` auf einer resume_execution-Task wird adoptierbar neu eingereiht** — der Resume-Zweig markiert die Zeile `scheduled=1`, sodass `ListReady` sie claimen kann; ein direktes Approve erzeugt keine `queued`-Waisenzeile mehr, die kein Scheduler je abholt.
- **Erschöpfte Tool-Schleife degradiert zu einem Digest** — ein verbranntes Tool-Budget liefert eine Zusammenfassung der ausgeführten Calls statt eines nackten „max tool rounds"-Fehlers.
- **TUI-Command-Execution korruptiert oder crasht das Frontend nicht mehr** — Alltagssequenzen (`/clear`, ein paar Turns, ein falsch getippter Befehl) konnten das echte Terminal an Bubble Tea vorbei beschreiben oder ungepaarte History hinterlassen. `/clear` malt jetzt über `tea.ClearScreen` neu; die Exec-Pumpe füttert Befehle mit einem leeren Stdin und fängt Handler-Panics als Error-Block auf; die aufgefangene Ausgabe wird beim Commit und beim Live-Render ANSI-gestripped; State-mutierende Befehle (`/new`, `/resume`, `/project`, `/authorize`, Listen-Änderungen) laufen über gemeinsame Helpers auf der Update-Goroutine statt State doppelt zu schreiben; ein gescheiterter Turn persistiert als gepaarter User+Error-Turn, sodass das nächste ask nicht mit 400 zurückkommt; `/history` fällt auf die persistierte Konversation zurück und `/new` leert Speicher und Datei.
- **Outboxes leeren über gepunchte Datagramm-Routen** — `sendableTo` behandelte einen nur per UDP-Pinhole erreichbaren Peer als nicht-leerbar, sodass geparkte Bundles für Punch-only-Peers ewig auf eine WebSocket-Verbindung warteten, die nicht existiert; sie drainen jetzt über die UDP-Route.
- **DTN-Relay-Buchführung überlebt Neustarts** — das Hop-Budget pro Bundle liegt jetzt in `dtn_relay_log` (Migration V25) statt im Speicher, und das Upsert von `parkBundle` aktualisiert `via` — die No-Echo-Regel eines erneut zugestellten Bundles folgt damit seinem jüngsten Eingangspfad.
- **Skill-URL-Imports können das interne Netz nicht mehr sondieren** — `ImportURL` (der Pfad hinter `panda skill install <url>`, `panda_skill_install`, `skill_install` und `/api/skills/import`) verlangt jetzt https für jeden Nicht-Loopback-Host und validiert jede aufgelöste IP zum Connect-Zeitpunkt: Loopback, RFC1918/ULA, Link-Local (Cloud-Metadata-Endpoints), Multicast und unspezifizierte Adressen werden nie angewählt, und Redirects müssen dieselbe Klassifikation erfüllen — eine von einem Agenten oder einem Index gelieferte URL kann den Knoten nicht mehr zum SSRF-Sprungbrett machen (Härtung: `internal/skills/fetchguard.go`).
- **STUN-Binding-Responses per Quell-IP rate-limitiert** — 10 Antworten/Quelle/Sekunde mit einer begrenzten Tracking-Map bindet den ~2×-Reflexionsfaktor des UDP-Sockets ein, ohne echte Clients zu treffen (RFC-5389-Retransmits laufen in Sekundenordnung).

### Breaking Changes

- **`?token=`-Query-Param-Auth auf `/api/*` entfernt** — die Panel-API akzeptiert nur noch `Authorization: Bearer <token>`, weil ein Credential in einer URL in Browser-History und Proxy-Access-Logs landet. Die mitgelieferte Konsole sendet den Header überall inklusive des SSE-Streams (fetch-basiert, nicht EventSource), und die `/?token=`-Auto-Login-URL, die `panda web` öffnet, ist nicht betroffen — das ist die statische Seite, nicht die API. Externe Skripte und Dritt-Clients sollten auf den Header umstellen.
- **Kein eingebauter Modell-Vendor-Default mehr** — eine Config mit leerem `model:` bedeutete früher „still einen gebündelten Vendor-Endpoint benutzen": er materialisierte sich in generierte Configs, erschien im Banner als wäre er die Wahl des Nutzers und leitete die Prompts eines unkonfigurierten Knotens an diesen Vendor. `entry.NewClient` gibt jetzt `ErrNoModel` zurück, und `panda ask`/`voice`/REPL/TUI verlangen ein konfiguriertes Modell und verweisen auf `panda init`/`panda model add`; `config.example.yaml` bringt die Sektion auskommentiert mit Anleitung, und Credential-Injection (`injection.model`) verlangt einen echten Endpoint. Wer auf den impliziten Default angewiesen war, setzt `model.provider`/`model.base_url` oder führt `panda init` aus.

## [0.0.9-beta] - 2026-09-23

Die Beta v0.0.9 vervollständigt die Hybrid-Transport/DTN-Architektur: Mesh-Routing ist jetzt latenzgewichtet, DTN-Bundles bewegen sich tatsächlich über Live-Links und parken bei Offline-Links, Delegations-Token-Budgets werden mit echter Abrechnung durchgesetzt, präemptierte Arbeit überlebt über Schattenkopien, und Hardware-Aktuatoren bekamen einen Ausführungspfad. Zusätzlich erhalten delegierte Agenten einen verwalteten Weg zurück zu den eigenen Werkzeugen des Knotens, die vollständige Modell-Konfigurationsoberfläche landet, und das Modellverwaltungs-TUI wird um ein Vollbreiten-Register plus einen Einbildschirm-Formulareditor neu gebaut.

### Hinzugefügt

- **Latenzgewichtetes Mesh-Routing** — Nachbarn gossippen Link-RTT-Stichproben in Heartbeats (`HeartbeatPayload.Links`, persistiert als `employee_cache.links_json`), und `graphFirstHop` führt nun Dijkstra über die gemessenen Linkkosten aus statt Hop-Count-BFS; ungemessene Kanten kosten `unknownLinkCost`, sodass ein bewährter Mehrfachsprung-Pfad einen teuren Direktlink schlagen kann (§4.1).
- **DTN-Bundles auf der Leitung** — geparkte delegierte Tasks werden in signierte CBOR-Bundles (HMAC-SHA256, EID, TTL) verpackt, in `task_outbox.payload_blob` gespeichert und Byte für Byte in einer `dtn_bundle`-Hülle verschickt; Empfänger prüfen Integrität und Frist, liefern an die Ziel-EID oder relayen/parken für den nächsten Hop (§8.3, §9.1).
- **Periodische Outbox-Sweeps** — `sweepOutboxes` wiederholt Result-, Cancel- und Task-Outboxes jetzt per Timer statt nur beim Peer-Hello, mit einem Flush-Claim pro Peer, damit gleichzeitige Flushes sich nicht verflechten; abgelaufene Bundles werden sauber verworfen und markieren ihren Task als expired.
- **Mesh-weite Token-Budgets** — Migration V20 fügt `tasks.token_budget` hinzu (0 = unbegrenzt/Legacy, positiv = Restkontingent, -1 = Erschöpfungs-Sentinel); `SpendTokens` dekrementiert atomar, Agenten- und Supervisor/Judge-Verbrauch wird nach jedem Modellaufruf verrechnet, und ein erschöpfter Task konvergiert zu review statt eine tote Quote zu verbrauchen (§6.1).
- **Schatten-Arbeitskopien bei Yields** — ein zum Yielden aufgeforderte Task snapshotet jetzt vor dem Abbruch seinen deklarierten Scope in `.panda-shadow`, und der wiederaufnehmende Task mergt nicht-konfliktierende Dateien zurück (Konflikte behalten die Bytes des Gewinners und werden in einer Systemnotiz gemeldet) — ersetzt das bisherige „bei Abbruch alles verloren" (§5.2).
- **Aktuator-Ausführungspfad** — Capability-Card-Aktuatoren können `command`/`args`/`tier` deklarieren; der Commander routet passende Tasks über den nativen Executor mit `ActionSpec`-Platzhaltersubstitution, und `panda card invoke <actuator-id> [action] [name=value ...]` testet sie lokal mit `--dry-run`/`--authorize` (§7).
- **Agenten-Selbstverwaltungsfläche (`panda mcp`)** — der Knoten bringt jetzt einen eigenen MCP-Stdio-Server mit, der OpenPandas Verwaltungsseite als erstklassige Agenten-Tools exponiert: `panda_status`, `panda_nodes`, `panda_queue`, `panda_task_status`, `panda_task_submit` (ruft `panda task add` auf, max. 8 Einreichungen pro Sitzung), `panda_skill_list`, `panda_skill_install` (Hub-Name oder http(s)-URL), `panda_skill_import` (rohes SKILL.md) und `panda_card`. Unter `routing.tools_policy: extended` materialisiert der Commander einen `openpanda`-Eintrag in der `.mcp.json` des Arbeitsverzeichnisses neben konfiguriertem `mcp.command`-Passthrough, sodass MCP-fähige Agenten-CLIs ihn automatisch entdecken; Shell-fähige Agenten erhalten einen Prompt-Hinweis auf das `panda`-Binary im PATH. `routing.panda_tools: false` deaktiviert die Selbstverwaltungsfläche bei Beibehaltung der erweiterten Toolfläche.
- **Gechunkter, fortsetzbarer Artifact-Push (`artifact_push`)** — fette Bundle-Payloads oberhalb der Inline-Grenze werden jetzt in 1-MiB-Frames gestreamt statt dem Pull-Pfad überlassen: Migration V21 `artifact_push_outbox` persistiert die Sender-Verwahrung über Neustarts, Empfänger stagen Chunks auf der Platte unter `<pool>/.staging/` und melden eine zusammenhängende Wasserlinie, und eine Wiederverbindung setzt beim bestätigten Offset auf statt neu zu starten. Ein DTN-Task, dessen Inputs nicht gelandet sind, parkt in `waiting_context` statt zu scheitern, und ein Relay, das den Task weitergeleitet hat, pusht das Artifact weiter, sobald es landet (verkettete Verwahrung, §8.3).
- **Unbegrenzte Artifact-Transfers** — die 512-MiB-Grenze `artifact.MaxBytes` fällt: Pools sind standardmäßig unbegrenzt und der freie Dateisystem-Platz ist die Grenze, sodass ein deklariertes `total`, das das Volumen nie fassen könnte, vor dem ersten Byte abgelehnt wird (`ErrNoSpace`). `storage.artifact_max_bytes` / `OPENPANDA_ARTIFACT_MAX_BYTES` setzen auf Knoten mit kleiner Platte wieder eine feste Grenze.
- **Multi-Volume-Artifact-Pools** — `storage.artifact_extra_paths` / `OPENPANDA_ARTIFACT_EXTRA_PATHS` fügt dem Pool Volumes hinzu: Schreibzugriffe wählen das Volume mit dem größten nutzbaren Platz (`free − storage.artifact_min_free_bytes`, Standardreserve 256 MiB; explizite 0 deaktiviert die Wassermarke), Lesezugriffe durchsuchen jede Wurzel, und gestagte Chunks liegen auf dem gewählten Volume, damit das Commit-Rename atomar bleibt. Extra-Pfade erhöhen die Kapazität — sie replizieren keine Artifacts, und allein der empfangende Knoten entscheidet, wo eingehende Daten landen.
- **DTN-Multi-Hop-Relay** — `relayBundle` wartet nicht mehr auf einen Direktlink zum Ziel: `scheduler.DTNNextHop` führt einen zielbewussten gewichteten Pfad über die gegosippte Topologie aus (Zwischenhops müssen online sein; das Ziel darf offline sein), leitet das signierte Bundle wörtlich an einen näher gelegenen verbundenen Nächst-Hop weiter, echot es nie zum eingehenden Peer zurück (`task_outbox.via`, Migration V22) und berechnet den Hop bei jedem Outbox-Flush neu. Ein Relay-Log pro Bundle begrenzt die Weiterleitung auf `dtnRelayMaxHops` und verfällt mit der Bundle-Frist.
- **Agenten-Session-Checkpointing** — Migration V23 fügt `tasks.agent_session_id`/`agent_session_node` hinzu: das Konversations-Handle des Adapters wird nach jeder Runde persistiert (`context.WithoutCancel`, sodass ein Yield-Cancel es nicht verlieren kann), dem Delegierenden auf dem Result-Wire gemeldet (`agent_session_id`) und beim Re-Dispatch nur dem ursprünglichen Knoten über `resume_session_id` zurückgereicht. Ein unterbrochener Task setzt die eigene Konversation seines Agenten fort statt kalt zu starten; Adapter ohne Session-Support lassen das Feld leer und behalten den Schattenkopie-Fallback (§5.2).

### Verbessert

- **Heartbeat-Gossip transportiert jetzt Adjazenz + Link-Metriken** — `Core.broadcastHeartbeat` publiziert Live-Nachbarn und gemessene RTTs; `handleHeartbeat` faltet sie ins Verzeichnis, sodass Routing-Entscheidungen die realen Linkkosten abbilden — jeweils aktualisiert, wenn RTT-Stichproben eintreffen.

### Behoben

- **Klassische Windows-Konsolen zeigen jetzt Farbe statt roher Escape-Sequenzen** — die Palette gab SGR-Codes auf jedem Windows-TTY aus, aber der klassische Konsolen-Host (cmd.exe, Windows PowerShell 5.1, per Doppelklick gestartete Binärdateien) interpretiert sie erst, wenn der Prozess die VT-Verarbeitung aktiviert. `internal/cliui` schaltet jetzt beim ersten Gebrauch `ENABLE_VIRTUAL_TERMINAL_PROCESSING` für stdout ein und koppelt sämtliche ANSI-Ausgabe daran — wo VT nicht aktivierbar ist, erscheint sauberer Klartext statt `[31m`-Müll.
- **Das klassische Windows-REPL bekommt einen echten Zeileneditor** — bisher war der Fallback eine reine Scanner-Lesung: keine Cursor-Bewegung, kein Verlauf, keine Tab-Vervollständigung, und Ctrl-C während einer laufenden Anfrage traf den Konsolen-Control-Handler und beendete das gesamte REPL. Ein neuer Editor auf Basis der Konsolen-API bringt Inline-Bearbeitung, persistenten Verlauf (jetzt unter `%LOCALAPPDATA%\openpanda`), Vervollständigung von Slash-Befehlen und Argumentpositionen, Abbruch der laufenden Anfrage per Esc/Ctrl-C (Doppeldruck beendet, wie unter unix) und echte Terminalbreite.
- **`panda uninstall` räumt jetzt Standard-Konfiguration und Fähigkeitskarte ab** — eine Konfiguration am Benutzer-Standardort (z. B. `%APPDATA%\openpanda\config.yaml`) wurde als „custom location — kept“ eingestuft, sodass API-Schlüssel und das gemeinsame Secret auf der Platte blieben; die Fähigkeitskarte tauchte nie im Plan auf. Beide gelten jetzt als zugehörig, wenn sie in den Standard-Konfigurationsverzeichnissen von Benutzer oder System liegen (behebt auch `~/.config/openpanda` unter Linux).
- **Browser-Öffnen unter Windows bricht nicht mehr an URL-Sonderzeichen** — `cmd /c start <url>` interpretiert `&`, `^` und Klammern als Shell-Syntax; `panda web` öffnet die Token-URL jetzt über `rundll32 url.dll,FileProtocolHandler`.
- **Robustere Windows-Installation/-Deinstallation** — der Selbsttest des Installers schlägt jetzt bei einem Exit-Code ungleich null fehl, statt für eine defekte Binärdatei Erfolg zu melden; der PATH-Vergleich expandiert `%VAR%`-Einträge, sodass keine Duplikate entstehen; die `taskkill`-Abbruchpfade blenden kein Konsolenfenster mehr ein; Hardware-Probes bevorzugen `pwsh` mit Fallback auf `powershell`; `SystemConfigDir` fällt auf `C:\ProgramData` zurück, wenn `ProgramData` fehlt; der REPL-Verlauf liegt jetzt in `%LOCALAPPDATA%\openpanda` statt im unix-artigen `~/.local/state`.

## [0.0.7] - 2026-08-31

Das Usability-Release: Die Capability-Karte — die Datei, die dem Scheduler sagt, was dieser Knoten kann — lässt sich nun von jeder Oberfläche (CLI, REPL, TUI und Webkonsole) bearbeiten, ohne den Daemon neu zu starten; ein zweites Gerät hinzuzufügen ist jetzt ein Produktfluss statt eines Konfigurationsdatei-Rätsels; und jedes Aufgabenergebnis erhält eine menschenlesbare Zusammenfassung, sodass der Nutzer sieht, was passiert ist, statt einer Wand aus rohem stdout.

## [0.0.6] - 2026-08-27

Das Release über geräteübergreifendes Rechnen nimmt Form an: Eine Anfrage, die für verschiedene Schritte verschiedene Maschinen braucht, ist jetzt ein Plan erster Klasse, dessen Stufen dort laufen, wo die Hardware ist — und beide Oberflächen, CLI und Web-Konsole, bekamen die Präsentationsschicht, die ihnen fehlte: Live-Feedback während ein ask konvergiert, echtes Markdown im Browser und den Eingabe-Editor, den der Alltag verlangt.

### Hinzugefügt

- **Plan plane — Pipelines, deren Stufen auf verschiedenen Maschinen laufen** — eine Stufe IST eine gewöhnliche Aufgabe (CAS-Zustandsmaschine, Lease, Retry, Supervision, Review-Parken), also erbt eine Pipeline alles, was eine Aufgabe schon hat; das Arbeitsverzeichnis einer beendeten Stufe wird gepackt, in Chunks über den Bus zur Maschine der nächsten Stufe transportiert. Zwei Einstiege: `panda plan example > train.yaml`, `panda plan run train.yaml [--dry-run]`, `panda plan show <id>` — oder ein Satz über `panda ask`, wobei das Modell genau dann einen Plan ausgibt, wenn eine Anfrage die Maschine wechseln muss. Keine Stufe trägt Tier-2-Zustimmung: Eine irreversible Stufe parkt im Review für einen Menschen (c10b8af).
- **Routing nach deklarierter Hardware** — `resource_profile` ist ein Hartfilter (`ledger.Fits`), und der Scorer rangiert nach freier Kapazität + Queue-Tiefe + Tier, abgezinst um Herz-Frische — zwei gleichzeitig gestellte Aufgaben landen auf zwei Maschinen; der Eingabe-Prompt trägt die echte Hardware jedes Knotens, damit das Modell den Routing-Filter sehend füllt statt blind (c10b8af).
- **`panda voice`** — Wake Word → ASR → dieselbe Eingabe-Pipeline → TTS: der Desktop-Tier-Einstieg für ein Gerät ohne Tastatur (c10b8af).
- **`panda card show | rescan | edit | set`** — eine Befehlsfamilie über der Fähigkeitskarte: ausgeben (und aus welcher Datei sie stammt), Hardware und installierte Agent-CLIs neu scannen (`rescan` druckt ein Diff, `--write` wendet es an und behält `.bak`, handgeschriebene Entscheidungen bleiben), im `$EDITOR` öffnen oder Felder headless setzen. `panda detect`, der Karten-Rescan und das Panel teilen sich jetzt eine Erkennungsschicht (`internal/hwinfo`) (fdb56b8).
- **Eine Präsentationsschicht für das CLI** — `internal/cliui`: eine einmal aufgelöste Palette und eine Live-Statuszeile (Spinner, Verb, vergangene Sekunden, Token-Zähler — die letzten beiden wurden längst erfasst, nur nie gezeigt), die auf Pipes zu einer statischen Zeile zurückfällt. Der Zeileneditor lernt Bracketed Paste und mehrzeilige Eingabe (ein eingefügter mehrzeiliger Prompt ist ein einziger ask, die Historie ruft ihn als einen ab), Ctrl-R inkrementelle Historiensuche und Vervollständigung an Argumentposition für die IDs, die niemand neu tippt. Unbekannte Befehle erhalten ein did-you-mean; `/help` druckt inline nach Absicht gruppiert; neue Befehle decken ab, was nach dem ersten ask gebraucht wird (`/cost`, `/model`, `/status`, `/doctor`, `/export`, `/clear`), plus `@file`-Anhang und `!cmd`-Durchreiche, damit der Prompt nie verlassen wird (c538ab6).
- **Die Web-Chat-Oberfläche holt auf** — ein handgeschriebener Markdown-Renderer (null `innerHTML`, also keine Sanitizer-Abhängigkeit; 29 Node-Tests) ersetzt literales `**bold**` und ```-Zäune in Antworten; die Hauptaktion des Composers während des Streamings ist ein Stopp-Button (der SSE-Reader nimmt ein AbortSignal); Autoscroll reißt die Ansicht nicht mehr herunter, sobald der Leser hochscrollt; Cmd+K-Palette über dasselbe Navigationsvokabular wie die Sidebar; mobiler Thread-Drawer statt `display:none` (c538ab6).
- **Eine Statusseite** — `docs/status.md` hält fest, was funktioniert, was nur gebaut und was fehlt, samt Verifizierungsstand der Flaggschiff-Pipeline (76c5b69).
- **Veraltete Knotenzeilen lassen sich entfernen** — `panda nodes remove <id>` und ein Entfernen-Knopf auf Offline-Knotenkarten löschen eine Verzeichniszeile, die kein lebender Peer stützt (eine umbenannte Maschine, eine geänderte Identität, ein abgewickelter Knoten). Die Zeile des lokalen Knotens und Online-Knoten werden abgelehnt — beide registrieren sich selbst erneut, „Entfernen" wäre also ein No-Op im Erfolgskostüm.
- **Release-Notes-Werkzeug** — der Release-Workflow veröffentlicht die CHANGELOG-Sektion der Version plus plattformbezogene Installationsbefehle als Release-Body und lässt den Build scheitern, wenn die Sektion fehlt; die 0.0.5-Release-Seite wurde nach diesem Standard neu geschrieben, mit englischem Body und Sprachumschalter; jeder CHANGELOG beginnt jetzt mit der Ein-Befehl-Installation (4e12779, c25a3cb, 98e10df, 600ffb3).

### Behoben

- **Queue-Aufgaben und Plan-Stufen routen jetzt wirklich** — der Queue-Pfad behielt eine lokale Abkürzung „wenn ich es kann, mache ich es", die der Router selbst längst entfernt hatte — und genau dieser Pfad lief für jeden Panel-Task und jede Plan-Stufe: Der Hardware-Filter lief nie dort, wo die Flaggschiff-Pipeline tatsächlich läuft (eine GPU-Stufe blieb auf dem Pi, solange der Pi die Fähigkeit hatte; ein Stoß Aufgaben blieb geschlossen auf dem annehmenden Knoten). Die Entscheidung gehört jetzt dem Scheduler; eine leere Fähigkeitsliste bedeutet „keine Bedingung", nicht „niemand passt"; Plan-Stufen bekommen je einen Ressourcenschlüssel, sodass unabhängige Stufen fächern statt sich gegenseitig zu blockieren (a5b792e).
- **Das Ergebnis eines beendeten Laufs passt in einen Frame** — die `task_result`-Ausgabe wird auf die Bus-Frame-Größe geklemmt, sodass das Ergebnis eines abgeschlossenen Laufs beim Einreicher ankommt, statt den Frame zu überlaufen und zu verschwinden (c1310da).
- **Memory-Zäune lassen sich von innen nicht schließen** — der `<memory_data>`-Zaum umwickelte den Körper, ohne die Tags des Körpers selbst anzufassen: Ein Eintrag mit dem literalen Schließ-Tag beendete den Zaum vorzeitig und der Rest wurde als Anweisung gelesen — und Memory ist durch die eigenen Werkzeuge des Modells, das Panel und beförderte Traum-Kandidaten schreibbar. Innere Tags werden neutralisiert; der Text bleibt sichtbar zur Prüfung (3f18994).
- **Ein Knoten beschreibt nicht mehr die Hardware einer anderen Maschine** — jede dieser Stellen war ein fest codierter Wert, wo eine Sonde hingehörte: Der Standard-Knotenname war „macbook", also meldete sich jeder Knoten ohne `panda init` unter dem Laptop-Namen des Autors; macOS/Windows hatten keine Machine-ID-Quelle, Umbenennen sah wie ein neuer Knoten aus; die Windows-Sandbox entfernte PATHEXT/SYSTEMROOT/TEMP — genau deshalb konnte ein Windows-Compute-Knoten gar keinen Adapter starten; `python3` ist kein portabler Interpretername (jetzt wird gesondet, Windows probiert `py -3` zuerst); eine Time-out-Aufgabe hing unter Windows für immer, weil das Harness einen Prozessbaum nicht töten konnte (jetzt `taskkill /T`); eine Karte, die eine native Fähigkeit ohne vorhandenes Kommando bewarb, gewann die Route und starb mit 127 (beim Laden entfernt); eine GPU, deren Größe keine Sonde lesen konnte, schrieb 0 und wurde von genau der Arbeit ausgeschlossen, für die sie existiert („unbekannt" ist jetzt ein dritter Zustand); `deploy-pi.sh` defaultete auf die LAN-Adresse eines Entwicklers (jetzt Pflichtfeld) (fdb56b8).
- **i18n-Regressions geschlossen** — fest codiertes Chinesisch im Voice-Pfad, in der Plan-Ausgabe von ask/repl, in Gesprächszusammenfassungen, Deinstallationsfehlern und einem Hinweis in `panda help` wanderte nach `internal/i18n` in alle fünf Sprachen — ja/es/de-Nutzer sahen in diesen Oberflächen Chinesisch (c538ab6).
- **Die REPL öffnet in unter einer Sekunde, nicht nach dem Peer-Dial-Timeout** — der interaktive Start wählte jeden konfigurierten Peer **seriell** vor dem Banner an und wartete dann auf deren Festigung: ein offline Peer verbrannte das volle 10-s-Timeout des Dialers als tote Stille vor dem ersten Prompt. REPL, `panda session` und `panda voice` wählen Peers jetzt im Hintergrund (ein offline Peer ist in einer langlebigen Session Routine, und sein Fehlschlag druckt keine WARN-Zeilen mehr mitten im Tippen), und der einmalige `panda ask` wählt parallel — ein unerreichbarer Peer blockiert keinen erreichbaren mehr.

Fünf Commits, alle auf genau dieser Hardware verifiziert.

### Hinzugefügt

- **`panda task add --requires`** — deklariert die Fähigkeiten, die ein Task braucht (`--requires gpio:read`, kommasepariert); ein Queue-Task ohne lokalen Treffer wird auf ein Gerät geroutet, das sie hat — dieselbe Root-Scheduler-Policy, die `panda ask` immer verwendet hat (c4e1bc7).

### Behoben

- **Queue-Aufgaben routen jetzt geräteübergreifend** — Tasks aus `panda task add` und der Web-Konsole wurden ausschließlich vom Ursprungsknoten geclaims und ausgeführt: Ein Task, dessen Fähigkeit nur ein anderes Gerät hatte, scheiterte direkt (`route: no capability matches` beim Einreichen von `pi.uptime` auf einem Mac). Beim Claim befragt der Scheduler jetzt den Root-Scheduler; ohne lokalen Treffer wird der Claim an einen fähigen Peer umgeleitet (Loop-Schutz über abgelehnte Knoten, Lease zur Erkennung eines toten Executors), und das Ergebnis des Peers vervollständigt die Zeile des Ursprungs. Im Labor in alle drei Richtungen verifiziert: Mac→OrangePi, OrangePi→Mac, Windows→OrangePi (c4e1bc7).
- **Tier-2-Autorisierung reist mit der Delegation** — die `--authorize`-Zustimmung war lokal auf den einreichenden Knoten beschränkt, sodass ein delegierter Agent-Task an der Defense-Schicht des Executors abprallte, obwohl der Nutzer ihn genehmigt hatte. Die Zustimmung propagiert jetzt über den authentifizierten Bus, und der Executor ehrt sie: Eine kreditialenlose Orange Pi, die einen autorisierten Coding-Task beim claude des Macs einreicht, läuft jetzt durch, statt in review zu sterben (c4e1bc7).
- **Ausgesperrte Agent-CLIs ziehen kein Routing mehr an** — die Capability-Karte ist statisch, aber eine installierte CLI kann unbrauchbar sein: Ein `claude.exe` auf der Windows-Maschine ohne Login-State und ohne Model-Key bewarb `agent:*` in der Flotte, das Routing schickte ihm einen Coding-Task, und es hing minutenlang, bevor es mit einem Netzwerkfehler starb. Die lokale Fallback-Kette und das über hello beworbene Capability-Summary prüfen jetzt Viability — CLI im PATH *und* ein erreichbares Modell (eigene Credentials oder Injection); das Summary dieser Windows-Maschine bewirbt jetzt nur noch `win.sysinfo` (2db530f).
- **`panda web` stirbt nicht mehr an einem belegten Port** — ein zweites `/web` (oder ein leftover Prozess) brach mit `bind: address already in use` ab und druckte einen Token zum Abtippen. Die Konsole weicht jetzt auf einen Nachbar-Port aus und sagt das; der Browser öffnet sich bereits authentifiziert (der Token wird nie gedruckt), und ein laufendes `/web` öffnet den Browser neu eingeloggt. `--no-browser` druckt weiterhin eine Token-URL für manuelle Nutzung (c4e1bc7).
- **Peer-hello meldet die echte Version** — alle drei Hello-Pfade bewarben ein hartkodiertes `0.1.0-dev`, sodass `panda nodes` in einer gemischten Flotte falsche Versionen zeigte; sie melden jetzt `version.Version` (alle drei Labor-Geräte zeigen 0.0.5) (2db530f).
- **Die Capability-Karte neben der aufgelösten Config schlägt `./capabilities.yaml`** — ein Daemon-Start aus einem Verzeichnis, das zufällig ein capabilities.yaml enthält (ein Repo-Checkout, die Karte eines anderen Knotens), lud lautlos die falsche Karte; die von init neben die Config-Datei geschriebene Karte gewinnt jetzt, `--card` bleibt die höchste Instanz (2db530f).
- **Windows-Datenverzeichnis kollidiert nicht mehr mit dem Installationspräfix** — das Standard-State-Dir `%LOCALAPPDATA%\openpanda` und das Installationspräfix `%LOCALAPPDATA%\OpenPanda` sind auf case-insensitivem NTFS dasselbe Verzeichnis: SQLite-Store, Memory und Projekte lagen *innerhalb* des Installationspräfixes, und ein Uninstall räumte sie weg. Das Datenverzeichnis ist jetzt `%LOCALAPPDATA%\openpanda-data`; Windows-Knoten von 0.0.4 starten mit einem frischen Store (fc50721).
- **Installer überleben rate-limitete GitHub-API und kaputten WinPS-5.1-HTTP-Stack** — `api.github.com` erlaubt 60 unauthentifizierte Requests pro IP und Stunde; bei Erschöpfung lösen beide Installer die neueste Version jetzt über den 302-Redirect von `/releases/latest`. `install.ps1` erzwingt TLS 1.2 vorab, bevorzugt das mitgelieferte `curl.exe` (Windows 10 1803+) mit `Invoke-WebRequest` als Fallback und ergänzt Timeouts, sodass eine kaputte WinINET-Proxy-Konfiguration schnell fehlschlägt, statt zu hängen. Beides trat bei der echten Drei-Geräte-Installation auf (109b567).
- **Homebrew-Tap-Push authentifiziert** — der Tap-Update-Schritt des Release-Workflows scheiterte mit `could not read Username`, wenn dem Job-Token der Grant fehlte; die Push-URL bettet jetzt das Token ein (6868a63).

- **Open-Source-Dokumentation** — fünf READMEs, CONTRIBUTING mit Merge-Gates (`make gate`) und die öffentliche Roadmap (51031eb).

### Behoben

- **Gegenseitiges Wahl-Verbindungsflattern** — zwei sich gleichzeitig anwählende Knoten erzeugten einen endlosen ~1s-Verbindungs-/Trennungs-Zyklus; der deterministische Tie-Break in `ensurePeer` (der lexikographisch kleinere Knoten-ID gewinnt) lässt genau eine TCP-Verbindung überleben (879b42d).
- **Wire-Protokoll-Autorisierungslücken** — result/decline/accept/context-ack verifizieren den Sender als aktuellen Ausführenden; CAS-Wachen schließen TOCTOU-Rennen; `waiting_context` trägt immer einen Lease; lokale Fehler terminalisieren ohne Zombies (9622538).
- **Befehls-Klassifikations-Bypässe** — `env -S`-Werte rekursiv klassifiziert, `php -r` gescannt, `find -exec` / `tar --checkpoint-action` / `git push/commit` fail-closed zu Tier 2 (f5db449).
- **Prozessgruppen-Verwaltung** — Ganzbaum-Kill beim Abbrechen (Unix `Setpgid`, Windows `taskkill /T`) und ein 630s-Adapter-Hard-Timeout (f5db449).
- **Gedächtnis-Injektionskanäle** — atomare Schreibvorgänge für Hermes/Projects/skills, externe Eingabe als `[ext]` markiert, Gedächtnis in `<memory_data>` mit Daten-sind-keine-Anweisungen-Präambel eingezäunt (a742585).
- **Abbruch-Propagation** — `task_cancel` kaskadiert hoppenweise zu ausführenden Knoten entlang der Delegationskette (574632a).
- **Transaktionale Schreibvorgänge** — Task-Status-UPDATEs und ihre Audit-INSERTs committen in einer Transaktion (c5d34d4).
- **Umfassender Sweep (D1–D32)** — Delegations-Waisen terminalisiert, weitergeleitete Kopien verleast, Hello-HMAC an ein 5-Minuten-Fenster gebunden, NetworkGuard auf konfigurierte Endpunkte genagelt, begrenzte Ausgabe-Erfassung (1694b7d).
- **Weiße Konsole bei frischen Klonen** — ein von git wiederhergestelltes gehashtes `index.html` zeigte auf ignorierte Assets; der committete Platzhalter ist jetzt stabil und `make web` bewacht das Landen des echten Builds (ab87f90).
- **Unbekannte Subcommands starteten einen residenten Daemon** (`panda statsu`) — jetzt Exit 2 mit Verwendung (a742585).
- **Sprach-Wach-Defaults** — echte eingebaute Schlüsselwörter pro Backend (`hey_jarvis` / `porcupine`) (4ea73bf).
- **Vorab-Release-Audit-Fixes** — `panda help` existiert; „PANDA“-Markenreste aus Prompts und Beispielen entfernt; `config.example.yaml` dokumentiert `mcp:` und `model.api_type`; toter Roadmap-Link behoben (2f001c0).

### Verbessert

- **Harte Gedächtnis-Mauer** — persönliches Gedächtnis wird nie in Workspace-(worktree-angepinnte)-Konversationen injiziert; Projekt-Gedächtnis erreicht die Ausführung nur über den ContextPack des ausführenden Knotens (da9c9e1).
- **Agenten-Adapter treten dem Tier-Modell bei** — nicht deklarierte sind standardmäßig Tier 2 und werden vor dem Spawn des Subprozesses abgewiesen (a4d2d9e).
- **OpenAI-Wire-Format neben Anthropic** — das Entry-Modell spricht beide Endpunkt-Typen, mit Streaming auf beiden (c36cad1).
- **Geheimnis-Datei-Härtung** — Konfigs mit `api_key` / `shared_secret` / `panel_token` werden automatisch auf 0600 chmod-iert mit Umgebungsvariablen-Hinweis (6275fd4).
- **Das Panel standardmäßig auf Loopback** (`127.0.0.1:7840`); Nicht-Loopback-Binds warnen vor Klartext-HTTP (a742585).
- **Peer-Wiederverbindung ersetzt obsolete Verbindungen** — eine neue Verbindung derselben Identität wechselt in die Registry; das Entfernen matcht per Verbindungsidentität (7911bbe).
- **Die Interpreter-`-c`-Klassifikation ist whitelist-basiert** — nur nachweislich rein ausgebender Code bleibt Tier 1 (f5db449).
- **Deployment-Basislinie dokumentiert** — Klartext-`ws://` nur über Loopback/Tailscale/vertrauenswürdiges LAN; TLS + `wss://` im offenen Internet (7582754).

### Breaking Changes

- **Projekt in OpenPanda umbenannt** — Modulpfad `github.com/Xustalis/OpenPanda`, Umgebungsvariablen mit Präfix `OPENPANDA_`, Units `openpanda.service` / `com.openpanda.node.plist`, Standard-DB `openpanda.db`; das CLI-Binary behält den Kurznamen `panda` (ac71bb1, 6f2083e).
